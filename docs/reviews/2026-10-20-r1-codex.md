**V — account sync and token ownership**

Reviewed dd734b4 and a12368a (v248–v249), plus aliax-core 9806651. The capability gate in src/main/server/index.ts:540 precedes accounts.pull and handleM3a/accounts.push; both require admin. Ordinary pull and broadcast use exportAccount(access), remove Claude appSession and strip the service refresh field; receiving an access copy strips it again before the encrypted vault write. Handoff exports a full grant, installs it on the named owner, then confirms and strips the sender. takeOver uses releaseTo before replying. Owner guards protect ordinary Claude/Codex refresh calls; the findings below concern transitions those guards do not cover. Activation can also write the stored blob to the local CLI credential store. No explicit token logging appeared in the normal sync/refresh paths inspected. Not verified: real setup-token failure output, real provider rotation, and nested Cursor credential fields captured from an actual IDE. No real credential store was read.

| Severity | File:line | Failure scenario | Fix I would make |
| --- | --- | --- | --- |
| HIGH | `/Users/landon/IdeaProjects/aliax-core/src/refresh.ts:103` | A refresh started before confirmHandoff can finish afterward and write a full refresh token back into the former owner's access-only vault while the new owner holds the same grant. | Serialize refresh and ownership transfer under the same per-profile lock, drain in-flight refreshes before export, and check the ownership generation before saving or returning a result. |
| HIGH | `src/main/server/remote/accountSync.ts:236` | liveLineage always returns false for Codex because its adapter has neither fingerprintOf nor liveFingerprint, so setting a remote home can hand off the CLI's live grant while the local CLI keeps refreshing it. | Add Codex grant fingerprints and refuse a handoff when the live lineage cannot be ruled out; test a Codex CLI live grant. |
| HIGH | `/Users/landon/IdeaProjects/aliax-core/src/sync.ts:221` | An older handoff answers ok and changes the owner without saving its refresh token, after which the sender strips its only refresh token and neither host can renew the account. | Make handoff acceptance atomic with installing its grant, and reject or reconcile stale handoffs before the sender relinquishes ownership. |
| MEDIUM | `/Users/landon/IdeaProjects/aliax-core/src/sync.ts:249` | A takeOver pull strips the owner's refresh token before the response reaches the caller, so a dropped response permanently loses the grant. | Use an acknowledged durable handoff with an idempotent transfer id and recovery instead of relinquishing ownership before delivery. |
| MEDIUM | `src/main/server/remote/peers.ts:231` | Replacing a revoked admin key without changing routes leaves the stopped PeerLink in place, so account sync stays disconnected after successful re-pairing. | Track credential changes and reconnect the peer when the saved key changes. |
