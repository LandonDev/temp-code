# The computer-use protocol

TempCode's own computer use: a Swift service on the Mac, `tc-computer`, reads accessibility trees, acts on elements and captures windows; the TypeScript host keeps one session per thread; four `computer_*` tools on the app MCP server put it in front of every model on every harness. Ten threads build it (AX reader, Input tiers, Capture, Service shell, Computer sessions and tools, Tier scheduling, Computer model instructions, Bridge path, Preview and image results, Task benchmark). This document is their contract, and each changes it with its code. It fixes:

1. the wire between the host and `tc-computer`: newline JSON-RPC 2.0 on stdio, every method, its params, result and errors, and the notifications;
2. the observation: the AX tree as indexed text, the diff after the first read, when a full tree comes back, the size budget;
3. the input tiers `ax`, `process`, `session`, the tier each action reports, the per-app verdict, the clipboard lock;
4. the smart wait;
5. capture: window screenshots to a downscaled file, and a preview stream;
6. the tools the models see, with Anthropic's native computer-use verbs and parameter names, element refs beside coordinates, and how a screenshot reaches each harness;
7. recorded fixtures from real apps, scratch content only.

**In code today** is the contract alone: the zod in `src/shared/computer/` (`protocol.ts` the wire, `observation.ts` the grammar, `tools.ts` the model-facing shapes), the Swift Codable types generated from it, the `native/tc-computer` package with every target declared, the fixtures, and tests in both languages that parse the fixtures; and the Capture module (§6, §7: screenshots, the preview stream and the pixel watch, with its live proof on the Mac). No service, no tools, no UI yet. Where this document and the zod differ, the zod is right and this document is stale.

## 1. Process and framing

- **One service per app instance on the Mac**, spawned as `tc-computer serve` with stdin and stdout as pipes and stderr as a log. All of that instance's threads share it: AX element handles and the diff state live in the service. Each thread is a `session` inside it. A dev or proof instance spawns its own.
- **The two things there is one of per Mac**, the pasteboard and the real pointer and keyboard, are guarded by advisory file locks every service on the Mac shares, so a dev instance's service can never paste or take the session over the installed app's: `flock` on `$TMPDIR/tc-computer/clipboard.lock` (§5.3) and on `$TMPDIR/tc-computer/session.lock` (held for the whole of a `session`-tier step, and while a `session`-tier button is held down, §5.1).
- **Frames**: one JSON-RPC 2.0 object per line, UTF-8, `"jsonrpc":"2.0"` on every frame, no newline inside a frame. A line is at most 16 MiB; screenshots never ride the wire (they go to files), preview frames are capped at 512 KiB. The envelope is the framing's: `RpcRequestSchema`, `RpcErrorResponseSchema`, `requestFrameSchema(method)` and `resultFrameSchema(method)` in `protocol.ts`; `RPCFrame`, `LineReader` and `encodeLine` in `native/tc-computer/Sources/ComputerProtocol/Framing.swift`. The notification unions hold `{ method, params }` alone, since the generator tells a union's branches apart by one literal field.
- **Direction**: the host sends requests and two notifications (`$/cancel`, `capture.stream.ack`); the service answers requests and sends notifications. The service never sends a request.
- **Ids**: the host's integers, increasing. Responses may arrive out of order.
- **Lifecycle**: the host sends `initialize` first; any other method before it answers error `not_initialized`. `shutdown` is answered, then the service exits 0 within 2 s. The service also exits on stdin EOF and when its parent is gone (`getppid() == 1`, polled every 5 s, as the appshot helper does). A crash is respawned by the host with backoff (Computer sessions and tools); the new process has a new `epoch` and knows no sessions, so every element index from before is stale.
- **Cancellation**: `$/cancel { id }` stops request `id` at its next safe point (between batch steps, inside any wait, before an input event is posted). A cancelled `action.run` or `action.batch` answers its normal result: the steps already done keep their results, the step it stopped is `failed` with kind `cancelled`, the rest `not-run`, and no observation is taken (`observationError` kind `cancelled`). Any other cancelled request answers error `cancelled`. Thread Pause and Stop use it.
- **Concurrency**: reads (`state.get`, `capture.*`, `apps.*`) run concurrently. Actions are serialized per app (one at a time per pid, across sessions); an action that waits more than 5 s for an app's slot fails `app_busy`. Any `session`-tier step holds the Mac-wide session lock. Reads of one app wait for its running action.
- **Versioning**: `COMPUTER_PROTOCOL = 1`. Adding a method, an optional field, an error kind or an enum value keeps 1; the generated Swift enums carry an `unknown(String)` case and the host tolerates unknown notification methods. Anything else bumps it; `initialize` with another number answers error `protocol_mismatch` and the host refuses the service.

## 2. Shared types

All in `src/shared/computer/protocol.ts`, exported as zod schemas and inferred types. Every wire shape is one the generator (§12) already emits as written: fixed-length arrays instead of tuples (`z.array(z.number().int()).length(2)` becomes `[Int]`), objects with optional fields and a refinement instead of untagged unions, discriminated unions only on a string literal field, no `z.unknown()`. `tools.ts` is TypeScript only and never generated.

```ts
type Rect = { x: number; y: number; w: number; h: number }      // points; screen space unless named otherwise
type Point = number[]          // length 2, integers: [x, y] in the session's coordinate space (§6)
type Region = number[]         // length 4, integers: [x0, y0, x1, y1], top-left and bottom-right, same space
type Tier = 'ax' | 'process' | 'session'
type Permissions = { accessibility: boolean; screenRecording: boolean }

type AppRef = { app?: string; pid?: number }                     // exactly one; app = bundle id or display name (§2.1)
type WindowRef = { id?: number; title?: string }                 // neither = the app's main window (§2.1)
type Target = {
  session: string; app: AppRef; window?: WindowRef; launch?: boolean
  epoch?: string   // the epoch of the observation the call's element indices came from; required when an action or a read names an element
}

type CoordinateSpace = { width: number; height: number; scale: number }
// width × height: the window's screenshot in pixels; scale: pixels per window point.

type AppInfo = { pid: number; bundleId: string | null; name: string; active: boolean; hidden: boolean; windows?: WindowInfo[] }
type WindowInfo = {
  id: number; title: string; frame: Rect; main: boolean; focused: boolean
  minimized: boolean; onScreen: boolean; space: 'current' | 'other' | 'unknown'
}

type WaitOptions = { minMs: number; quietMs: number; maxMs: number; busyMaxMs: number }
type WaitReport = { waitedMs: number; settled: boolean; busy: boolean; reason: 'quiet' | 'max' | 'busy-max' | 'cancelled' | 'skipped' }

type Shot = {
  path: string; format: 'jpeg' | 'png'; width: number; height: number; bytes: number
  scale: number; window: { id: number; frame: Rect }; region?: Region
  blank: boolean          // every pixel one colour: a window on another Space the compositor has not drawn
  capturedAt: number      // epoch ms
}

type ElementBrief = { index: number; line: string }               // line = the element's observation line after its indent and `[<index>] `: `button "Save"`

type ComputerAction = { action: ComputerActionName } & ActionParams // §5.1: one flat object, generated as one Swift struct
```

Named so the generator emits each once (`COMPUTER_SUBSET` in scripts/gen-swift-computer.ts is the list): `Tier`, `PermissionName`, `Permissions`, `Rect`, `Point`, `Region` (both `[Int]` in Swift), `AppRef`, `WindowRef`, `Target`, `CoordinateSpace`, `WindowSpace`, `AppInfo`, `WindowInfo`, `DisplayInfo`, `WaitOptions`, `WaitReason`, `WaitReport`, `Shot`, `ShotFormat` (`'jpeg' | 'png'`), `ElementBrief`, `ComputerActionName`, `ScrollDirection`, `ComputerAction`, `ObservationMode` (`'auto' | 'full'`, state.get), `ObserveMode` (`'auto' | 'full' | 'none'`, ObserveOptions), `ScreenshotPolicy`, `Budget`, `ObserveOptions`, `ObservationKind`, `ObservationStats`, `Observation`, `InputVia`, `ClipboardOutcome`, `StepEffect`, `StepResult` (branches `OkStep`, `FailedStep`, `NotRunStep`), `ActionResult`, `BatchResult`, `ComputerErrorKind`, `ComputerError`, `InterruptedBy`, `StaleReason`, `Empty`, `SessionRef`, the fixture shapes `RawAXValueType`, `RawAXValue`, `RawAXNode`, `RawAXTree`, and the notification unions `ComputerNotification` (the service's) and `HostNotification` (the host's), each discriminated on `method`.

### 2.1 Resolving a target

- `app` matches, in order: a bundle id exactly; a running app's display name case-insensitively; an installed app's name (only with `launch: true`, which launches it in the background, `activates: false`); a unique case-insensitive prefix of a running app's name. No match answers `app_not_found` with up to five close names in `data.candidates`.
- `window` absent: the app's AXMainWindow, else AXFocusedWindow, else its first standard window. `id` is the CGWindowID from `apps.list`; `title` matches exactly, then as a substring. No match answers `window_not_found` with the app's window titles.
- The **focus window** of an observation is the resolved window plus whatever is attached to it: sheets, open menus (an AXMenu the app shows), popovers and the app's focused dialog. A new standalone window does not replace the target; the observation header names it (§4.1).

## 3. Methods

Every method's params and result are a zod schema in `COMPUTER_METHODS` (`protocol.ts`): `{ [method]: { params, result } }`. Defaults below are the service's when a field is absent; the host always sends `wait` explicitly from `COMPUTER_WAIT` so the numbers have one home.

| Method | Params | Result |
|---|---|---|
| `initialize` | `{ protocol: 1, client: { name, version }, dataDir: string }` | `{ protocol: 1, service: { version, build }, epoch: string, os: { version, arch }, permissions: Permissions, displays: { id, frame: Rect, scale }[] }` |
| `shutdown` | `{}` | `{}` |
| `permissions.get` | `{}` | `Permissions` |
| `permissions.request` | `{ which: 'accessibility' \| 'screenRecording' }` | `Permissions` (as now; the grant arrives later as `permissions/changed`) |
| `apps.list` | `{ windows?: boolean }` (default false) | `{ apps: AppInfo[] }`: regular apps only (activation policy regular), the active one first, then by name |
| `apps.launch` | `{ app: string, open?: string[] }` (urls or absolute paths) | `{ pid: number, launched: boolean }` (false: it was already running); never activates |
| `session.open` | `{ session: string }` | `{}`: idempotent |
| `session.close` | `{ session: string }` | `{}`: frees its element maps, bases and streams |
| `state.get` | `Target & { mode?: 'auto' \| 'full', element?: number, screenshot?: 'auto' \| 'always' \| 'never', maxEdge?: number, geometry?: boolean, menus?: boolean, budget?: { bytes: number }, wait?: WaitOptions }` | `Observation` (§4) |
| `action.run` | `Target & { action: ComputerAction, tiers: Tier[], wait?: WaitOptions, observe?: ObserveOptions }` | `ActionResult` |
| `action.batch` | `Target & { actions: ComputerAction[] (1..32), tiers: Tier[], stepWait?: WaitOptions, wait?: WaitOptions, observe?: ObserveOptions }` | `BatchResult` |
| `capture.screenshot` | `Target & { maxEdge?: number, region?: Region, format?: 'jpeg' \| 'png' }` | `Shot` |
| `capture.stream.start` | `Target & { stream: string, fps?: number (1..15, default 4), maxEdge?: number (default 960) }` | `{ stream, width, height }` |
| `capture.stream.stop` | `{ stream: string }` | `{}` |
| `input.probe` | `Target & { classes?: ActionClass[] }` (default `['scroll', 'key', 'click']`) | `ProbeReport`: which classes the app honours at the `process` tier, each tried only where its state can be put back through AX (§14.6) |
| `input.restoreSession` | `{}` | `SessionRestore`: what the `session` tier changed since the last restore, put back unless the person moved since (§14.5); `session_unavailable` when another holder keeps the session lock for 5 s |

Notifications from the host: `$/cancel { id }`, `capture.stream.ack { stream, seq }`.

`ObserveOptions = { mode?: 'auto' | 'full' | 'none', screenshot?: 'auto' | 'always' | 'never', maxEdge?, geometry?, menus?, budget? }`: the same knobs as `state.get`, for the observation that closes an action; `mode: 'none'` asks for none.

**Where a failure goes.** `action.run` and `action.batch` answer a JSON-RPC error only when nothing could start: `not_initialized`, `protocol_mismatch`, invalid params, `unknown_session`, `permission_missing`, `app_not_found`, `window_not_found`, and `stale_element` with reason `service-restarted` (the `epoch` check runs before any step). Every failure once steps can run is a step's: that step is `failed` with its `ComputerError`, the later ones `not-run`, and the result still carries the observation (or `observationError`, when the window it would read is gone), so the model sees where the batch left the window. `state.get` and `capture.*` answer every failure as a JSON-RPC error.

```ts
type ActionResult = {
  step: StepResult
  observation?: Observation              // absent with observe.mode 'none', or when observationError says why
  observationError?: ComputerError       // the closing observation failed (the action closed the window or quit the app, a cancel); the steps stand
}
type BatchResult = { steps: StepResult[]; observation?: Observation; observationError?: ComputerError; waited: WaitReport }

type StepResult =
  | { index: number; action: ComputerActionName; status: 'ok'; tier: Tier | null; effect: 'changed' | 'none' | 'unknown'
      element?: ElementBrief; input?: { via: 'ax-insert' | 'ax-value' | 'keys' | 'paste'; clipboard?: 'restored' | 'kept-person-copy' }
      cursor?: Point; text?: string; shot?: Shot; waited?: WaitReport
      session?: SessionChange }                       // on every step that ran at the session tier (§14.5)
  | { index: number; action: ComputerActionName; status: 'failed'; error: ComputerError }
  | { index: number; action: ComputerActionName; status: 'not-run' }
```

- `tier` is null for actions that send no input (`screenshot`, `zoom`, `cursor_position`, `wait`).
- `effect` is what the service saw within the wait: `changed` when the focus window's tree, the focused element, a value, a selection or the set of windows moved, or a menu or sheet opened; `none` when nothing observable did; `unknown` when the app exposes too little to judge (a thin tree).
- `text` carries `cursor_position`'s answer, `X=512, Y=384`, in the session's space.
- `shot` carries the image of `screenshot` and `zoom`.
- A batch runs its actions in order, waits `stepWait` after each step that can change the screen (every action but `screenshot`, `zoom`, `cursor_position`, `wait`), and stops at the first failure: later steps are `not-run`. The final `wait` runs once after the last step that ran, then the observation.

## 4. The observation

```ts
type Observation = {
  epoch: string
  session: string
  app: { pid: number; bundleId: string | null; name: string }
  window: { id: number; title: string; frame: Rect }
  kind: 'full' | 'diff' | 'unchanged' | 'subtree'
  seq: number                 // per session × app: the baseline count, +1 per full, diff or unchanged observation returned; a subtree carries the current one
  base?: number               // the seq a diff is against
  text: string                // what the model reads (§4.1)
  space: CoordinateSpace      // what coordinates mean now (§6)
  stats: { elements: number; lines: number; bytes: number; omitted: number; thin: boolean; partial: boolean; readMs: number }
  shot?: Shot
  waited?: WaitReport
}
```

- `omitted`: elements left out by the budget; `partial`: the walk stopped at its node or time cap; `thin`: the tree is too poor to act from (§4.5).

What the walk dropped here: the two scroll bars, two unnamed groups, and the title bar's `text "Untitled"` (it repeats the window's name).

**Header** (line 1): `app "<name>" · window "<title>" · <width>×<height>` (the coordinate space), then, in this order, any of ` · focused [<i>]`, ` · still loading` (a busy indicator showed when the wait ended), ` · changes since your last read` (a diff) or ` · no changes` (unchanged), ` · thin tree, see the screenshot` (§4.5). Line 2, only when the app has other windows: `other windows: ` and their titles, comma-separated, each followed by ` minimized` or ` other Space` when so.

**Element line**: `<indent>[<index>] <role>[ "<name>"][ = "<value>"][ <state>…][ caret <n> | selection <a>..<b>][ actions: <action>, …][ @<x>,<y> <w>×<h>]`

- `indent`: two spaces per depth among the elements kept (§4.3), at most 10 levels.
- `index`: §4.2.
- `role`: one entry of `ROLE_TAGS` (`observation.ts`), the AX role and subrole mapped to a short word: `window`, `sheet`, `dialog`, `button`, `pop up`, `menu button`, `checkbox`, `switch`, `radio`, `tab`, `tabs`, `input`, `search`, `password`, `text area`, `combo box`, `text`, `link`, `image`, `heading`, `toolbar`, `menu bar`, `menu`, `menu item`, `list`, `outline`, `table`, `row`, `cell`, `column`, `scroll area`, `slider`, `stepper`, `progress`, `busy`, `split`, `web area`, `disclosure`, `date`, `color well`, `level`, `group`. A role not in the table prints as its AX name without `AX`, split into lower-case words (`AXRulerMarker` → `ruler marker`).
- `name`: the first non-empty of AXTitle, AXDescription, the AXTitleUIElement's value, AXPlaceholderValue (shown as the name only when there is no value), then the subrole's word from `SUBROLE_NAMES` (`AXCloseButton` close, `AXMinimizeButton` minimize, `AXFullScreenButton` full screen, `AXZoomButton` zoom; the window buttons carry no title or description), as a JSON string, at most 100 Unicode scalars, then `…` inside the quotes (`cutName`).
- `value`: AXValue as a JSON string (numbers as written), at most 160 Unicode scalars, then `…(+<n> chars)` inside the quotes (`cutValue`). Never shown for `password`. Booleans of checkboxes and switches print as states instead.
- `state` words, only when they hold: `focused`, `selected`, `disabled`, `checked`, `unchecked`, `mixed` (checkbox, switch and radio always show one of the three), `expanded`, `collapsed` (rows, disclosures), `required`, `invalid`, `modal`, `read-only` (an input, search, text area, combo box or date whose AXValue is not settable).
- `caret <n>` or `selection <a>..<b>`: on the focused text element, AXSelectedTextRange in UTF-16 units.
- `actions:`: the AX actions the element exposes beyond its role's default, as words from `ACTION_WORDS`: `AXShowMenu` show menu, `AXOpen` open, `AXConfirm` confirm, `AXCancel` cancel, `AXDelete` delete, `AXIncrement` increment, `AXDecrement` decrement, `AXRaise` raise, `AXPick` pick, `AXZoomWindow` zoom window, `AXScrollToVisible` scroll to visible, `AXScroll<Dir>ByPage` scroll up, scroll down, scroll left, scroll right. A custom action is its own name: CopyActionNames returns custom actions as `Name:<name>\nTarget:…\nSelector:…` (seen on TextEdit's colour buttons), and the word is the `Name:` part, lower-cased; one with no readable name is dropped. `AXShowAlternateUI` and `AXShowDefaultUI` (hover affordances on every Finder row) are always dropped. A word not in the table prints as its AX name without `AX`, split into lower-case words.
- **Role defaults** (`ROLE_DEFAULTS`, AXPress's word `press`), never listed: click (AXPress) for button, link, menu item, checkbox, switch, radio, tab, disclosure; click and show menu for pop up and menu button; typing, `set_value` and show menu for combo box; typing and `set_value` for input, search, password, text area, date (unless `read-only`); click (AXPress, else selecting it) for row and cell; increment and decrement for slider and stepper; the four page scrolls for scroll area; raise for window.
- `@x,y w×h`: the frame in the session's coordinate space, only with `geometry: true` and on every observation that carries a screenshot.

**Range lines** fold a run of unnamed siblings of one role that carry no state word: `<indent>[<first>]–[<last>] <n> × <role>` (TextEdit's 15 ruler markers above). Each folded element still has its index, consecutive and in order, and takes actions like any other; the AX reader sets the run length that folds (6 by default).

**Summary lines** carry no index: `<indent>… <n> more below`, `… <n> more above`, `… <n> more below, <m> above` under a scroll area or list whose rows fall outside the visible rect; `<indent>(<role> "<name>": items not exposed to accessibility; see the screenshot)` for a container whose rows are textless stubs (JetBrains with screen-reader support off); and the last line `(truncated: <n> elements left out; observe with element: <i> to see one part whole)` when the budget cut, `<i>` the container that lost the most. A stub line's name may be left out: `(list: items not exposed to accessibility; see the screenshot)`.

**What the parser holds** (`parseObservation` in `observation.ts`, which every fixture and every `apps/*/*/observation.txt` must pass, and `formatObservation(parseObservation(text)) === text`):

- Names, values and window titles are JSON strings written as `JSON.stringify` writes them: `"`, `\`, `\b \f \n \r \t` escaped, other controls and lone surrogates as lower-case `\u00xx`, nothing else (no `\/`, no escaped non-ASCII). Swift's JSONEncoder escapes `/` unless told `.withoutEscapingSlashes`, so the AX reader writes these strings itself.
- States print in `STATE_WORDS` order, each once (`sortStates`). A role is lower-case words and never holds a state word, `caret`, `selection` or `actions:`.
- An indent is a whole number of levels and grows one level at a time; the tree starts at depth 0 and may hold several roots (a window and, with `menus: true`, the menu bar). An index appears once, a range counting each of its indices. The `(truncated …)` line is last.
- A range line carries no state or geometry, and `<n>` is `<last> − <first> + 1`. ` (and <n> inside)` ends only a removed line, after any geometry.
- An `unchanged` observation is its header alone. Marker lines and `+` groups appear only in a diff, and a diff holds nothing else.

### 4.2 Element indices

- Positive integers, per session × app (one counter across that app's windows), assigned in reading order on the first full read, starting at 1.
- An element keeps its index while it exists. Identity is `CFEqual` on the AXUIElement; where an app recreates elements (Chromium, Electron) the AX reader may also match on AXIdentifier, AXDOMIdentifier, role, name and position under the same parent, and documents its rule.
- A new element takes the next unused number; a number is never reused in that session × app, so a stale index can only fail, never act on something else.
- Acting on a removed element answers `stale_element { element, reason: 'gone' }`; on one never assigned, `no_such_element`. A restarted service counts from 1 again, so an old index could name a new element: every call that names an element carries the `epoch` of the observation the model last got for that session × app (the host keeps it per session × app and fills it in), and a mismatch answers `stale_element { element, reason: 'service-restarted' }` before anything runs. The model reads the tree again.

### 4.3 What is kept

The AX reader walks the focus window's tree (plus open menus, sheets and popovers) in AX child order and keeps an element when it has a name, a value, a role-default or listed action, a state word, or is a window, sheet, dialog, menu, list, outline, table, scroll area or web area. It drops:

- unnamed `group`, `split`, unknown layout roles and scroll bars (unless focused): their children rise to the parent's depth;
- `text` whose string equals its parent's name or value (the appshot helper's dedupe);
- rows and descendants outside the visible rect of their scroll area, counted into a summary line;
- the menu bar, unless `menus: true`.

**The walk must cut before it descends.** Measured on the Mac (`.temp-code/computer-spec/ax-findings.md`, box only): reading one attribute per call costs about 0.67 ms a call, and Finder's list of 1,269 rows (25,297 pt tall) was still unfinished after 25 s; batched reads (`AXUIElementCopyMultipleAttributeValues`) ran about three times faster and still did not finish. So:

- read each node's attributes in one batched call;
- before descending into a list, outline, table or scroll area, take only its visible children (AXVisibleRows, AXVisibleChildren, AXVisibleColumns where exposed, else children whose frame meets the visible rect), and count the rest into a summary line without reading them;
- skip zero-size elements (Finder's scroll-bar arrows report 0×0);
- set `AXUIElementSetMessagingTimeout` to 2 s per app, so a hung app answers `timeout` instead of hanging the service;
- cap the walk at 5,000 nodes and 2,000 ms; past either the text is what it has and `stats.partial` is true.

Frames are global points and may be negative or past the main display (the probe's TextEdit window sat at (3700, −244) on a second display); nothing clamps them to the main screen. Chromium and Electron apps get `AXManualAccessibility` set on first read, retried as the appshot helper does when the tree comes back thin; native apps refuse it (-25205), which is harmless.

### 4.4 The diff rule

- `mode: 'auto'` (default) answers `full` on the first read of an app in a session, after an epoch change, when the target window is another window than the base's (the resolved window changed, or the old one closed), when an element that persists moved to another parent or its siblings changed order (a sort, a reordered list: the diff grammar has no move), and when the diff's text would pass 60% of the full text's bytes. A sheet, menu, popover or dialog that opens or closes on the same window is a diff. Otherwise it answers a `diff` against the last full, diff or unchanged observation **returned** to that session for that app (its `seq` is the new `base`), or `unchanged` when nothing differs.
- `mode: 'full'` always answers the whole tree. `element: <i>` answers that element's subtree whole, as `kind: 'subtree'`, under its own budget, with values uncut up to that budget (a document's full text); a subtree is never a base and leaves `seq` where it was.
- A diff's text is the header, then three groups, each in reading order. Illustrative, after the sample above got "!" typed and Command-S (the build records the real pair, `textedit/typed` → `textedit/save-sheet`):

```
app "TextEdit" · window "Untitled" · 1280×1072 · focused [42] · changes since your last read
- [20] group "Formatting" (and 16 inside)
~ [3] text area = "Hello from the probe\nSecond line!" caret 33 actions: show menu
+ in [1]:
  [41] sheet "Save As"
    [42] input "Save As:" = "Untitled" focused selection 0..8
    [43] button "Cancel"
    [44] button "Save"
```

- `- <line>` removed, with its role and name; a removed subtree is its root with ` (and <n> inside)`; a removed range is its range line.
- `~ <line>` changed: the element's new line under its own index. Name, value, states, caret or selection and actions count; geometry alone does not.
- `+ in [<parent>]:` then the added subtree in full-tree form, indented one level under the marker. `+ at top:` for a new top-level element (a menu).
- `unchanged`: the header line alone.

### 4.5 The size budget and thin trees

- Full text: at most 24,000 bytes (about 6,000 tokens) by default (`budget.bytes`, 2,000..96,000). Past it the reader keeps, in order, the focused element and its ancestors, interactive elements on screen, headings and text, then the rest; it folds the largest lists into summary lines first and ends with the `(truncated: …)` line.
- Diff text: at most 12,000 bytes, else the observation is `full`.
- `thin`: fewer than 3 elements with a role-default action and under 200 bytes of names and values, or a stub container covers most of the window. With `screenshot: 'auto'` (the default) a thin observation carries a screenshot and its header line ends ` · thin tree, see the screenshot`.
- `screenshot: 'always'` attaches one to every observation; `'never'` to none.

## 5. Actions and input tiers

### 5.1 The action shape

One flat object, the same on the wire, in `computer_act` and in each `computer_batch` entry: `action` plus that action's parameters. The first 17 are Anthropic's native member names with their parameter names and meanings unchanged; `element` and `start_element` are added beside `coordinate` and `start_coordinate`; the last four are ours.

| `action` | Parameters | Notes |
|---|---|---|
| `screenshot` | none | the focus window; sets the session's space (§6) |
| `zoom` | `region` | the region at full resolution, scaled to fit `maxEdge`; the space does not change |
| `left_click`, `right_click`, `middle_click`, `double_click`, `triple_click` | `element?` or `coordinate?`, `text?` (modifiers), `duration?` (seconds, 0 < d ≤ 10) | neither: at the agent cursor; `duration` keeps the button down that long before the release, which `ax` cannot express |
| `left_click_drag` | `start_element?` or `start_coordinate?`, `element?` or `coordinate?`, `text?` | press, drag, release |
| `mouse_move` | `element?` or `coordinate?` | hover |
| `left_mouse_down`, `left_mouse_up` | none | at the agent cursor |
| `cursor_position` | none | `X=<x>, Y=<y>` |
| `scroll` | `scroll_direction` (`up`, `down`, `left`, `right`), `scroll_amount` (wheel clicks, 1..50), `element?` or `coordinate?`, `text?` | |
| `type` | `text`, `element?` | the literal string; with `element`, into that element |
| `key` | `text` (a key or `+`-joined combo), `repeat?` (1..100) | |
| `hold_key` | `text`, `duration` (seconds, ≤ 300, as native) | holds the app's action slot for `duration` |
| `wait` | `duration` (seconds, ≤ 300, as native) | the smart wait capped at `duration` (§7): it returns once the window settles, which is what the native member is for ("pauses before the next action, for example while an application loads"), so no model ever sleeps blind |
| `set_value` | `element`, `value` (string) | AX only |
| `perform` | `element`, `name` (an action word the element lists, or a role default) | AX only |
| `select_text` | `element`, `text?` (its first occurrence) or `range?` `[a, b]` (UTF-16), `prefix?`, `suffix?`, `place?` (`select` \| `before` \| `after`) | AX only; the first match with `prefix` right before it and `suffix` right after it; `place` selects it (the default) or puts the caret before or after it; `prefix` and `suffix` never with `range`; no match is `text_not_found` |
| `paste` | `text` (1..200,000 UTF-16 units), `format?` (`text` \| `markdown` \| `html`, default `text`), `element?` | `process` or `session` (Command-V under the clipboard lock, §5.3); class `type`; `step.input = { via: 'paste', clipboard }` |

- `element` and `coordinate` exclude each other, and so do `start_element` and `start_coordinate`; `mouse_move` needs exactly one of `element`, `coordinate`; `left_click_drag` needs exactly one of `start_element`, `start_coordinate` and exactly one of `element`, `coordinate`; `zoom` needs `region`; `type`, `key`, `hold_key` and `paste` need a non-empty `text` (`paste` at most 200,000 UTF-16 units, no `coordinate`); `scroll` needs `scroll_direction` and `scroll_amount`; `hold_key` and `wait` need `duration`; the three AX actions need `element`; `perform` needs `name` and `set_value` needs `value`; `select_text` takes exactly one of `text`, `range` (`range` with a ≤ b). An action refuses any parameter it does not take (`ACTION_PARAMS` is the table; `refineAction` the rules). `ComputerActionSchema` (`protocol.ts`) refines these per action; its JSON Schema is one flat object with no `oneOf`, so Codex and Muse read it as written, and it generates one Swift struct `ComputerAction` with optional fields.
- **Held input**: `left_mouse_down` holds the button until `left_mouse_up` from the same session on the same app. While it is held that session owns the app's action slot (another session's action on the app waits, then `app_busy`), every pointer action of that session uses the tier the down used (a call whose `tiers` lacks that tier fails that step `needs_tier { needed: <the held tier> }` without acting, and the button stays down), and a `session`-tier down keeps the Mac-wide session lock. The service lets go (button up at the agent cursor, every held key up) on `interrupted`, `$/cancel`, `session.close`, `shutdown`, stdin EOF, and 30 s after the down with no up.
- **Modifiers** (`text` on clicks, drag and scroll): `shift`, `ctrl`, `alt`, `super`, `+`-joined. On the Mac `super` is Command and `alt` is Option; `cmd`, `command`, `opt` and `option` are accepted as aliases.
- **Keys** (`key`, `hold_key`): X11 keysym names as Anthropic's examples use them (`Return`, `Tab`, `Escape`, `BackSpace`, `Delete`, `space`, `Up`, `Down`, `Left`, `Right`, `Home`, `End`, `Page_Up`, `Page_Down`, `F1`..`F20`, single characters), case-insensitive, joined with modifiers by `+` (`ctrl+s`, `super+shift+t`, `alt+Tab`). `KEY_NAMES` and `parseKeyCombo` in `observation.ts` are the table; the Input tiers thread maps them to virtual key codes.
- **The agent cursor**: per session × app, the last point a pointer action used, in the session's space. `cursor_position` reads it; `left_mouse_down`/`up` and clicks without a target use it. Under the `session` tier it is the real pointer, mapped into the space.

### 5.2 Tiers

| Tier | What it does | Visible to the person |
|---|---|---|
| `ax` | AXUIElementPerformAction or AXUIElementSetAttributeValue on the element | nothing: no focus change, no pointer |
| `process` | CGEvents posted to the app's pid (`CGEventPostToPid`), at window-relative points converted to screen points | nothing on screen; the app may change its own key window |
| `session` | activates the app, raises the window, moves the real pointer, types at the focused field | everything: it takes the Mac |

- Every `action.run` and `action.batch` carries `tiers`: the tiers the host allows, in order. The service uses the first allowed tier that can express the action and reports it in `step.tier`. It never chooses a tier the host did not allow; an action no allowed tier can express answers `needs_tier { needed }` without acting.
- What each tier can express, **exactly**: `ax` takes, on an element and with no modifiers, `left_click` (AXPress; on a row or cell without AXPress, setting AXSelected), `double_click` where the element exposes AXOpen, `right_click` where it exposes AXShowMenu, `set_value`, `perform`, `select_text`, and `type` into an element whose AXSelectedText or AXValue is settable (§5.3); `process` takes every pointer, key, scroll and type action at a point or at an element's centre; `session` takes all of them. **Approximately**: `ax` can scroll a scroll area by whole pages (AXScroll<Dir>ByPage, one page per 5 wheel clicks, at least one). The service uses the first tier in `tiers` that expresses the action exactly, and an approximate one only when no allowed tier is exact; `step.tier` says which ran.
- **`perform raise` needs the session tier** (a correction to this section as first written, made before any service existed): raising can put the window over the person's, so `perform` with `raise` runs only when `tiers` includes `session` (the AX call is the same) and reports `tier: 'session'`; otherwise `needs_tier { needed: 'session' }`. Every other `perform` stays `ax`. `expand` and `collapse` set AXExpanded (a row's AXDisclosing) where it is settable; they are role defaults of `row` and `disclosure`, never listed in `actions:`.
- **Keys go only to a key window.** At the `process` tier a `key`, `hold_key`, `type` by keys or `paste` posts only when the app's AXFocusedWindow is the target window; anything else, no answer included, is `key_window_unavailable` with `keyWindow { id, title }` when another window is key, and nothing is posted. Mouse verbs are exempt (their window fields route them). The host retries that one step at the next tier (`ax` set value or insert for `type`, `session` for `key`) and records `needsKeyWindow` in the verdict.
- Seen on the Mac: Finder rows carry no AXPress (select by AXSelected or a click, open by AXOpen on the cell); TextEdit's text area exposes AXValue and AXSelectedTextRange as settable and only AXShowMenu as an action.
- **The verdict**: the host keeps, per bundle id and action class, the lowest tier that worked: `TierVerdictSchema` in `tools.ts`, `{ bundleId: string, classes: { [class]?: Tier }, misses: { [class]?: number } /* steps in a row with effect 'none' at the class's current tier */, needsKeyWindow?: boolean /* this app's background windows have been seen not key: a record, not a ban */, updatedAt: number /* epoch ms */ }`, stored by Computer sessions and tools as setting `computer.tiers.<bundleId>` and read by Tier scheduling. A class with no entry starts at `process`. Classes (`ACTION_CLASSES`, the wire's `ActionClassSchema`): `click` (clicks, mouse down and up), `drag`, `hover` (`mouse_move`), `scroll`, `key` (`key`, `hold_key`), `type`. The host learns from `effect`: a `process` step with `effect: 'none'` twice in a row in one class, where the same class then changed something at `session`, sets that class's verdict to `session`; a later `changed` at a lower tier lowers it. The host builds each call's `tiers` from the verdict; Tier scheduling decides when `session` may be in it.
- **The person's input during a `session` step**: the service watches for real keyboard and pointer events it did not post (a global event monitor; every event Input posts carries `eventSourceUserData = 0x74636370`, "tccp") and for Escape. Either stops the step at once with error `interrupted { by: 'person' }`, sends `session/interrupted`, and releases the Mac. A session step says what it changed (`step.session`, or the failed step's `error.session`); `input.restoreSession` puts it back (§14.5) when the host asks.

### 5.3 Typing and the clipboard lock

`type` tries, in order, within the allowed tiers: (1) `ax-insert`, setting AXSelectedText on the element (or the focused element), which inserts at the caret like typing; (2) `ax-value` when only AXValue is settable and the element is empty or the whole value is selected (after either write the evidence is read for up to 300 ms, and a write the app accepted that changed nothing (`none`; Chromium takes AXSelectedText on a contenteditable and drops it) goes on to (3), or answers `needs_tier` when no event tier is allowed); (3) `keys`, Unicode key events in chunks of at most 20 UTF-16 units never cut inside a grapheme cluster (`CGEventKeyboardSetUnicodeString`; a line break posts Return and a tab Tab, as real keys) at `process` or `session`, for text of 2,000 units or less with no cluster over 20 units; (4) `paste`, plain text, for the text (3) does not take, or when (3) showed no change at all (`none`; never after `changed` or `unknown`, so text never goes in twice). `step.input.via` says which ran. A `type` or `paste` naming an `element` first sets AXFocused on it and waits up to 200 ms for it to be the app's focused element; else `action_unsupported` ("[n] can't take keyboard focus") and nothing is posted.

The `paste` verb writes per `format`: `text` the plain string; `markdown` rendered HTML (`public.html`) and RTF (`public.rtf`) with the source as the plain string; `html` the HTML as given with its text (tags stripped, entities decoded) as the plain string. The renderers are Input's own (`MarkdownHTML.swift` walks `AttributedString`'s markdown intents; `RichTextRTF.swift` builds the attributed string), never WebKit's HTML import.

The paste runs under the **clipboard lock**, one per Mac (`flock` on `$TMPDIR/tc-computer/clipboard.lock`, §1):

1. take the lock (wait at most 2 s, else `clipboard_busy`);
2. check the destination and the key window (`process`) or the focused window (`session`); a failure leaves the clipboard untouched;
3. snapshot every pasteboard item with every type and its data, and the `changeCount`; a `changeCount` that moved while it read, or a type whose data cannot be read (a promise its owner did not keep), is `clipboard_busy` ("the clipboard holds data that can't be saved") with nothing written;
4. write the content, noting the `changeCount` after each of Input's own pasteboard calls, then check the destination and key window again;
5. post Command-V at the step's tier;
6. wait for the element's value to change, at most 500 ms;
7. on every exit, a throw or a cancel included, restore the snapshot only if `changeCount` is still ours (`clipboard: 'restored'`); if the person copied in between, leave their copy (`clipboard: 'kept-person-copy'`);
8. release the lock. It is never held over 2.5 s.

Reading a `password` value is never possible; typing into one is.

## 6. Coordinates and capture

- **The coordinate space** is the target window's screenshot: origin at the top-left of the window's frame (title bar included), x right, y down, integer pixels. `scale` is pixels per window point. Every `coordinate`, `start_coordinate`, `region`, `@x,y` and `cursor_position` uses it, as Anthropic's tools do with full-display screenshots. A session pixel maps to the screen at its centre, `window.frame.origin + (p + 0.5) / scale`, and a screen point back to `floor((s - origin) × scale)`, so the round trip lands on the same pixel (`CoordinateMapping` in ComputerCore; Input and the shell both call it).
- Each session × window keeps the space of its last full `screenshot` (or observation screenshot). Before any, the space is the one a screenshot at the default `maxEdge` would have. `zoom` never changes it. Every observation states it (`space`, and the header's `<width>×<height>`). A point outside it answers `out_of_bounds { coordinate, space }`.

The Capture module (`native/tc-computer/Sources/Capture/`, `ScreenCaptureKitCapture`) does everything below for one window, never the desktop. Every number is in `CaptureTuning.swift`; the ones the wire states come from the generated `ComputerDefaults`, and `src/shared/computer/captureParity.test.ts` refuses a literal in their place.

**Screen Recording.** `ScreenRecordingAccess.granted()` reads `CGPreflightScreenCaptureAccess()` and never prompts; `request()` raises the system's dialog. Every entry point checks the grant before any ScreenCaptureKit call (one without it raises the prompt) and throws `permission_missing { which: 'screenRecording' }`. Prompting is the host's decision: only when a computer tool needs the grant and it is off, at most once per install, never at boot. ScreenCaptureKit may keep a process's first answer, so the host respawns the service once when `permissions/changed` turns Screen Recording on. `CaptureRuntime.prepare()` touches `NSApplication.shared` and `CGMainDisplayID()` once (ScreenCaptureKit asserts without them); the shell calls it in `main` and every entry point calls it too.

**Screenshots** (`screenshot(windowID:maxEdge:regionPoints:format:to:)`):

- The window's live bounds come from the window server on every call (`LiveWindows`, `CGWindowListCreateDescriptionFromArray`, global points, top-left origin, never clamped; it answers for a minimized window too, which `CGWindowListCopyWindowInfo(.optionIncludingWindow)` drops). Its `SCWindow` comes from a cached `SCShareableContent` listed with `onScreenWindowsOnly: false`, so windows on other Spaces are there; the cache refreshes once when the id is missing or the size moved more than 0.5 pt, and `invalidate()` drops it on `window/changed`. The window is picked by CGWindowID, never by area.
- `SCContentFilter(desktopIndependentWindow:)` with no cursor, `ignoreShadowsSingleWindow` (the shadow's margin would shift every coordinate), `ignoreGlobalClipSingleWindow` (a window past a screen edge comes whole), best resolution, BGRA, sRGB. A covered window, one half off its display and a minimized one all capture their current pixels. Whether a minimized window answers `window_minimized` is the shell's call from AXMinimized.
- Size (`ShotGeometry`): `k = min(1, maxEdge / longEdge, sqrt(3,750,000 / pixels))` of the native size, never upscaled; one `scale` for both axes, width and height floored once. A zoom captures the whole window at the zoom's scale and crops the region (single-window capture ignores `sourceRect`), so the written image is the region at full resolution fitted to `maxEdge`. The capture races a 5 s deadline (`capture_failed` past it).
- `blank` is true when every channel, alpha included, spans at most 3 levels: a window the compositor has not drawn.
- **Format (A1).** A named `format` is used as named. With none, JPEG 0.85; when the image's flatness (on every 4th row, the share of pixels within 2 levels of their right neighbour) is at least 0.85, PNG too, kept when no larger. Text-dense UI comes out PNG (the proof's text window: 64.6 KB against 88.1 KB of JPEG), photographic content JPEG, and a mostly white window with little text JPEG too, since its PNG is the larger. `Shot.format` says which, and the host takes the image's mime type from it.
- **Files (A2).** The shell names the stem, `ShotNaming.stem` → `<dataDir>/shots/<session>/<nnnn>-<action>` (four digits, more past 9999; the action lower-cased with anything outside `[a-z0-9_]` made `_`), and Capture adds `.jpg` or `.png`. `ShotCounter` gives each session its next number, starting above the highest file already there, so a reopened session or a restarted service never reuses a name. The file is written beside its name and moved on with `renamex_np(RENAME_EXCL)`: the host never reads half a file and no shot is ever replaced. The host prunes them (Computer sessions and tools).

**The preview stream** (`capture.stream.*`, `startStream`): an SCStream on the window at `fps` (1..15, default 4), downscaled to `maxEdge` (256..2576, default 960), frames sent as `capture/frame` with the JPEG inline.

- **Only new pixels.** ScreenCaptureKit marks every sample of a covered window `complete` with a dirty rect over the whole frame, whether anything changed or not (macOS 27.2: 24 complete samples in 2.4 s of a still window, 2 distinct buffers). So a sample is sent only when its pixel fingerprint or size differs from the last one's (`PixelStats.fingerprint`, about 0.3 ms at 960 px; `PixelNovelty`).
- **Flow control** (`FrameGate`): at most 2 frames out without an ack; a newer sample replaces the held one, so nothing is encoded that will not be sent and the newest picture goes next. An ack covers every earlier frame (the pipe is ordered); one for a frame never sent is ignored. A frame left unacked for 5 s stops the stream's capture (a 1 s clock checks, so a still window that sent one frame pauses too) until the next ack, which resumes it; `StreamLifecycle` orders the pause, resume and stop calls, each waiting for the last to complete, `stop()` winning over all.
- **Frames.** Each frame is the sample cropped to its content rect (`contentRect × scaleFactor` is buffer pixels; `contentScale` must not be applied), so a window mid-resize is never letterboxed, then JPEG 0.85, re-encoded at 0.7 and 0.55 to stay under 380 KiB (the base64 line with its JSON fits the 512 KiB cap), dropped with a `log` line past that. `capture.stream.start` answers the window's size inside the buffer (`StreamHandle.startSize`, `ShotGeometry.fitted`), which every frame's crop matches. A content rect more than 1% off the configured window's aspect reconfigures the stream, at most every 250 ms.
- Frames carry the agent cursor, converted by the shell into the frame's own pixels; nothing is painted into the image. While any stream or watch runs on a window, macOS draws its window-sharing badge in the title bar, and frames show it; a screenshot with nothing streaming shows the traffic lights.
- **The end** (`StreamHandle.ended()`, `StreamEndReason`, A3): `stopped` (`capture.stream.stop`, or the person stopping capture from the menu bar), `windowClosed`, `permission`, or `error`; the shell sends `capture/streamEnded`. A closed window ends its stream through ScreenCaptureKit's `noCaptureSource` (−3815) 25–55 ms after it goes, the 1 s bounds check behind it; a window ordered out but kept alive keeps its bounds and its stream, and AX's `window/changed` is what says it is gone.
- **Frames stay inline** (measured, the busiest scene: colour noise shifting every 100 ms at 960 px and 4 fps): p95 225 KiB of JPEG and p95 6.7 ms to encode, under the 300 KiB and 25 ms bounds for staying inline; a flat window's frames were p95 32 KB in 3.0 ms.

## 7. The smart wait

`WaitOptions { minMs, quietMs, maxMs, busyMaxMs }`, all measured from the moment the action's last input was posted. The service waits `minMs`, then starts the **quiet clock**, which every change restarts, and returns when it reaches `quietMs`. Quiet means no AX notification from the app (an AXObserver on value changed, title changed, created, destroyed, layout changed, focused element changed, selected text changed, selected children changed, menu opened or closed, window created, moved or resized, element busy changed) and the same **shallow signature** (the focused element and a hash of its value and selection, the window's title, its sheets, and the child counts of the window and of the scroll areas the last observation showed). The signature is never a full walk: walks cost milliseconds per node (§4.3). It returns at `maxMs` if it never goes quiet and no busy indicator shows, and at `busyMaxMs` while one does. A **busy indicator** is a visible `busy` element, an indeterminate `progress` (no AXValue), or a `web area` whose AXElementBusy is true or whose AXLoaded is false. Neither app the probe walked exposed any of these, and Codex's service waits on the same signals (AXElementBusyChanged, AXProgressIndicator), so the quiet rule carries the wait and the busy rule only extends it.

`COMPUTER_WAIT` in `protocol.ts`, sent by the host with every call:

| Use | minMs | quietMs | maxMs | busyMaxMs |
|---|---|---|---|---|
| `action` (after the last action) | 300 | 450 | 1,500 | 5,000 |
| `step` (between batch steps) | 0 | 150 | 1,000 | 2,000 |
| `observe` (a plain `state.get`) | 0 | 300 | 1,000 | 5,000 |
| `wait` action | 0 | 450 | `duration × 1000` | `duration × 1000` |

So an action that changes nothing returns in about 0.75 s, a click that redraws in about a second, a page load when it has loaded or at 5 s with ` · still loading` in the header. The Task benchmark tunes these four rows and nothing else moves. No model ever needs to sleep; the tool descriptions say so.

**The pixel watch** (Capture's `PixelWatching`, A4). An AX notification says the app changed something; it does not say a page is still painting. So the quiet clock also listens to the window's own pixels (A5): `watch(windowID:)` starts, or keeps alive, one small SCStream per window a session acts on (256 px long edge, 10 fps, never encoded) and returns its `PixelChangeSignal` at once. The first complete frame is the baseline: it never counts, and it makes the signal `live` (37 ms cold on the Mac). Each later frame goes to `ChangeJudge`, on a grid of 8 px cells:

- A frame's dirty cells are those its dirty rects touch whose mean luma also moved more than 6 levels (a covered window's frames are all dirty, whole, whether anything changed or not); with no dirty rects, the cells whose luma moved. Idle frames never count.
- A dirty area under 0.05% of the frame never counts (a 2×18 pt caret is about 0.008%). Eight or more dirty cells always count: a page painting in, a list scrolling, a video playing, a sheet sliding down.
- Between the two, a cell dirty in three small frames within 2 s is ambient (a spinner, a ticking clock), and a small frame counts when at least two of its cells are not ambient: a spinner counts twice, then goes quiet; a progress bar moving into new cells keeps counting.

A counting frame stamps `lastChange` with its display time, the mach clock AX's `ChangeSignal.lastChange` uses. The shell calls `watch` at every `state.get` and before posting each action's input, awaits `waitLive` (at most 300 ms) when the signal is not live yet, and reads the signal or calls `watch` at least every 10 s while an action runs and through its wait; the stream stops 30 s after its last use, and at once when the window goes. While the signal is live, a `lastChange` later than the quiet clock's last restart restarts it, exactly as an AX notification does, never past `maxMs` (a busy indicator still extends to `busyMaxMs`). A watch that is not live (starting, stopped, or a window the compositor does not draw) adds nothing, and the wait runs on AX alone. Every number of the judge is `CaptureTuning.changeRule`, for the Task benchmark to tune.

## 8. Errors and notifications

**Errors.** A `ComputerError` rides in one of three places (§3 "Where a failure goes"): as the `data` of a JSON-RPC error object for a request that could not start (`code` -32000; the standard codes -32700, -32600, -32601, -32602 and -32603 carry no `data`), inside a `failed` StepResult, or as `observationError`:

```ts
type ComputerError = { kind: ComputerErrorKind; message: string } & Partial<{
  which: 'accessibility' | 'screenRecording'; candidates: string[]; element: number
  reason: 'gone' | 'service-restarted' | 'locked' | 'secure-input' | 'activation-refused' | 'in-use'

  keyWindow: { id: number; title: string }            // key_window_unavailable: the window that is key

}>

## 9. The tools the models see

Four tools on the app MCP server, the same on every harness: claude in-process (`mcp__app__computer_*` through the SDK's `mcpServers.app`), codex and Muse through `scripts/app-mcp-bridge.mjs` (codex's `mcp_servers.app`, Muse's `session/start` `config.mcpServers.app`). `tools.ts` holds their zod input shapes and result shapes; Computer sessions and tools registers them in `apptools.ts` and the bridge (with `app-bridge.test.ts` holding the two schemas equal, as it does for the other app tools), and Computer model instructions owns every description string.

| Tool | Input | Does |
|---|---|---|
| `computer_apps` | `{ launch?: string }` | lists running apps and their windows; `launch` first starts that app in the background |
| `computer_observe` | `{ app: string, window?: string, full?: boolean, element?: number, screenshot?: boolean, menus?: boolean }` | `state.get` with the `observe` wait |
| `computer_act` | `{ app: string, window?: string, screenshot?: boolean } & ComputerAction` | one action, the `action` wait, then the observation |
| `computer_batch` | `{ app: string, window?: string, screenshot?: boolean, actions: ComputerAction[] (1..20) }` | the actions in order, the `step` wait between, one `action` wait and one observation at the end |

- `app` is a name or bundle id; observe and act launch an installed app that is not running, in the background, and say so in the step line. `window` is a title or a part of one.
- Examples, verbatim shapes: `{"app":"TextEdit","action":"left_click","element":12}`, `{"app":"TextEdit","action":"left_click","coordinate":[500,300],"text":"shift"}`, `{"app":"Safari","action":"scroll","scroll_direction":"down","scroll_amount":3,"element":5}`, `{"app":"TextEdit","action":"key","text":"Tab","repeat":4}`, `{"app":"Preview","action":"zoom","region":[100,200,400,350]}`, `{"app":"Mail","actions":[{"action":"left_click","element":31},{"action":"type","text":"Lunch?"},{"action":"key","text":"super+Return"}]}`.

**The result** is MCP content: one text part, then one image part per picture, in order.

```
left_click [14] button "Save" · ax · changed
type "Lunch?" into [33] input "Subject" · ax-insert · changed
key super+Return · process · no change seen
screenshot 1 (observation): /srv/agents/work/x/.temp-code/attachments/<sid>/computer/0007.jpg (1280×800)

app "Mail" · window "New Message" · 1280×800 · focused [33] · changes since your last read
~ [33] input "Subject" = "Lunch?" focused caret 6
```

- One **step line** per action (`formatStepLine` in `tools.ts`): the verb and its target (`stepTarget`: an element as `[<i>] <role> "<name>"` from its `ElementBrief`, a point as `x,y`, neither as `at the cursor`, modifiers as ` with shift`, a drag as `<start> to <end>`, a scroll as `down 3 on <target>`, a key with its repeat as `Tab ×4`, typed text quoted and cut at 60 scalars), then the tier (or for `type` the `via`), then `changed`, `no change seen` or `can't tell` from `effect`. A step that sends no input has no tier: `cursor_position · X=512, Y=384`, `wait up to 2 s · settled after 0.8 s`, and `screenshot` or `zoom` alone (their picture has its own line). A failed step: `<verb> <target> · failed: <error message>`. Steps after it: `Not executed: an earlier action in this batch failed.`, Anthropic's own sentence with "batch" for "turn". Tier scheduling owns one more line, for a step held for the `session` tier.
- **Pictures**, in order: each `screenshot` or `zoom` step's shot, then the observation's. Each gets a line `screenshot <n> (step <i>|observation): <path> (<w>×<h>)` (`formatShotLine`) after the step lines, and an image part in the same order. At most 4 image parts ride in one result; past that the lines still name the files, marked ` (not attached)`.
- Then a blank line, then the observation's text; when the result carries `observationError` instead, the line `observation failed: <its message>` in that place (it rides in `text` across the bridge too). With `mode: 'none'` nothing follows the step lines.
- **An image** rides as `{ "type": "image", "data": <base64>, "mimeType": "image/jpeg" }`, the way `html_preview` returns its PNG today (`apptools.ts` `htmlPreviewContent`, the bridge's `toolContent`). The file is written on the **thread's own host** (`attachmentDir(session)/computer/<n>.jpg`), so the path in the text opens with the harness's own image tool if a harness drops the image part: Claude's Read, codex's `view_image`. The transcript keeps `[image]` in place of the bytes (`withoutImageBytes` in drivers/codex.ts) and the preview shows the file. Preview and image results proves, per harness and version, that the model receives the picture (claude in-process, codex ≥ 0.162.1 over the bridge, Muse over the bridge), and records the answer in docs.
- **The one-tool-per-verb variant**: `COMPUTER_ACTIONS` in `tools.ts` is a table of every action with its parameter shape, from which both `computer_act` and a per-verb set (`computer_left_click`, `computer_type`, … each with `app`, `window`, `screenshot` and that verb's parameters, its required ones required; `perVerbTools()`) are built. `computerToolJsonSchema` gives each input's JSON Schema for an MCP `tools/list`: one flat object, no `oneOf` or `anyOf` at the top. Computer model instructions may benchmark the per-verb set for Claude against `computer_act` and `computer_batch` and keep the faster; nothing below the tools changes. The Codex REPL shape stays out of scope until the typed tools prove slower.

**The peer payloads** (Bridge path): a box thread's tool call crosses the Mac bridge as `ComputerToolCallSchema`, a union discriminated on `tool` whose `args` is that tool's own input schema (`{ tool: 'computer_act', args: ComputerActInput, threadId, permission }` and so on), with `permission` the thread's `PermissionPolicy` (`'safe' | 'edits' | 'auto'`, src/shared/events.ts, as the bridge's other calls send it). It comes back as `ComputerToolResultSchema { text: string, images: { label: string /* "step 2" | "observation" */, data: string, mimeType: string, width: number, height: number }[] }` with `text` lacking the `screenshot` lines; the box writes each image under the thread's attachment dir and adds the lines. Policy, approvals and the load guard are the Bridge path's.

**The verdict** (§5.2) is `TierVerdictSchema`, stored under `tierVerdictSetting(bundleId)` (`computer.tiers.<bundleId>`); a class with none starts at `DEFAULT_TIER` (`process`), and `VERDICT_MISSES_TO_RAISE` (2) is the run of `none` that raises it.

  // format nil chooses by content (A1); stem is the path without its extension, Shot.path the file written (A2)
  func screenshot(windowID: UInt32, maxEdge: Int, regionPoints: Rect?, format: ShotFormat?, to stem: String) async throws -> Shot
  func startStream(windowID: UInt32, fps: Int, maxEdge: Int, onFrame: @escaping @Sendable (Frame) -> Void) async throws -> any StreamHandle
}
```

Every struct here has an explicit `public init` taking all its fields (Swift's memberwise initializer is internal, and the sibling targets build these values). `ResolvedElement`, `InputTarget`, `AppReading` and `InputPerforming` sit behind `#if canImport(ApplicationServices)`, so the package also builds on Linux, where the box's toolchain tests `ComputerProtocol`. `ComputerFailure { error: ComputerError }` is what any part throws. ApplicationServices brings Carbon's own `WindowRef`, `Rect` and `Point` (QuickDraw, MacTypes), so a file that imports it names the wire's types `ComputerProtocol.WindowRef`, `ComputerProtocol.Rect` and `ComputerProtocol.Point`; Seams.swift does, and only the Mac's SDK shows the clash. The shell maps the agent cursor into each frame's pixels before it sends `capture/frame`. The threads may add members; renaming one is a change to this document first.

## 12. The generator

`scripts/gen-swift-contract.ts` has a second target that leaves the iOS output alone (`check:swift-contract` holds it): `generate(subset, { methods, header, contract })` takes the method source (`CLIENT_METHODS`, the phone's `ClientRequestSchema` with the capability check, by default), the files' header and the body of `Contract.swift`, and `writeOrCheck` writes or diffs the files. `scripts/gen-swift-computer.ts` calls it with `COMPUTER_SUBSET` (every named type, the `StepResult`, `ComputerNotification` and `HostNotification` unions, then each method of `COMPUTER_METHODS`) and writes `native/tc-computer/Sources/ComputerProtocol/Generated/`; `emitInputTables()` writes `native/tc-computer/Sources/Input/Generated/InputTables.swift` from `observation.ts` (`KEY_NAMES`, `MODIFIERS` and `MODIFIER_NAMES`, `ACTION_WORDS`, `DROPPED_ACTIONS`, `ROLE_TAGS`, `ROLE_DEFAULTS`, `TYPING_ROLES`), so Input keeps no hand-written table of names. Its `Contract.swift` carries `computerProtocol` and `ComputerDefaults`: every constant group of `protocol.ts` (`SERVICE`, `AX_WALK`, `OBSERVATION_TEXT`, `OBSERVATION_BUDGET`, `SHOT`, `PREVIEW_STREAM`, `TYPING`, `LOCKS`, `ACTION_LIMITS`, `RPC_ERROR`) as `static let`s and the `COMPUTER_WAIT` rows as `WaitOptions`, so the service's defaults and the host's numbers have one home. A name the generator would turn into a Swift keyword or into `Type` gets a named type of its own (`RawAXValueType`) or another key (`internalError`).

- Scripts: `gen:swift-computer` and `check:swift-computer`, the latter inside `typecheck` beside `check:swift-contract`; `computer:test` (scripts/computer-test.sh, which picks an Xcode as scripts/ios-test.sh does) builds and tests the package.

## 14. Input as built

`native/tc-computer/Sources/Input/` performs the actions of §5 on one window and says which tier it used. It builds to `InputPerforming` (§11); the Service shell routes `input.probe` and `input.restoreSession` to it, implements `MacLock` twice over `flock`, keeps the crash ledger from `onHeld`, and counts the smart wait from `lastInputAt`. Public API only: no SkyLight or other private call.

### 14.1 Files

Most of Input is **pure**: Foundation and the wire, no AppKit, CoreGraphics or AX, each piece generic over the system it touches, so its suites run on the box's Linux toolchain as well as on the Mac. `InputTiming` (every delay and cap), `KeyCombo` (the same parse as `observation.ts`), `KeyCodes`, `KeyLayout` (`USANSILayout`), `TextMatch`, `TierPlan`, `Geometry`, `EventPlan` (`SyntheticEvent`, `EventPlans`), `Evidence` (the typing and paste evidence, `TypingRoute`), `PersonMark` (`TC_EVENT_MARK`, `isPersonEvent`), `InputClock`, `EventRoute` (`EventSink` and the poster), `Held` (held input across calls), `SessionLedger`, `SessionFlow` (`SessionHost`, `PersonWatching`, the session driver), `ProbeRun` (`ProbeAccess`, `ProbeJudge`), `PasteFlow` (`PasteboardStore`) and `InputCore` (the event-posting verbs at `process` and `session`, the trip between calls, restore, the stale release). `MarkdownHTML` is Foundation but Mac-only (`AttributedString`'s markdown intents). The **live** layer reads and writes the Mac: `AX`, `EventMaker`, `EventSink` (`LiveEventSink`), `CurrentKeyLayout`, `PersonWatch`, `AXTier`, `ProcessTier`, `SessionTier` (`LiveSessionHost`), `Pasteboard` (`SystemPasteboard`, `PasteContent.make`), `RichTextRTF`, `Typing`, `Probe` (`LiveProbeAccess`) and `InputEngine`. `Names.swift` aliases the wire's `Rect`, `Point` and `WindowRef` over Carbon's inside the module; `Generated/InputTables.swift` is the generator's (§12).

### 14.2 The engine

`InputEngine(clipboardLock:, sessionLock:, onPersonInput:, onHeld:, sink:, pasteboard:, layout:, watch:, clock:)`. `perform`, `probe` and `restoreSession` are synchronous and refuse the main thread; the person watch (NSEvent monitors) and the key layout (TIS) run on main and are reached through a hop bounded at 1 s. `perform` parses the action's strings, reads the element's facts, chooses the tier (§14.3) and answers `needs_tier` before touching anything; `screenshot`, `zoom` and `wait` are the shell's and answer `action_unsupported`; `cursor_position` answers the agent cursor (the real pointer while a session-tier button is held). Before any AX call `AXIsProcessTrusted()`, and before posting `CGPreflightPostEventAccess()`: either missing is `permission_missing`. `target.cancelled()` is checked before every posted event and inside every pause; a cancel lets go of what the step holds and answers `cancelled`. AX errors map: invalid element → `stale_element { reason: 'gone' }`, unsupported action, attribute or argument → `action_unsupported`, cannot complete → `timeout`, API disabled → `permission_missing`; every element Input calls has a 2 s messaging timeout. Every event comes from a private-state `CGEventSource` and carries `eventSourceUserData = 0x74636370` ("tccp").

Points: a session-space `[x, y]` maps to `frame.origin + point / scale` (frames in global points, never clamped; `out_of_bounds` outside the space); an element's point is the centre of its frame clipped to its scroll area and the window, after one `AXScrollToVisible` if nothing of it shows; a pointer verb with neither element nor coordinate uses the agent cursor, and with none answers `out_of_bounds` ("No pointer position yet"). At the session tier the frames are read again after activation.

### 14.3 Choosing the tier

The first tier in `tiers` that expresses the action exactly, else the first that approximates it, else `needs_tier` naming the lowest that could. A held button forces its tier on every action that posts events.

| Action | `ax` | `process` | `session` |
|---|---|---|---|
| `left_click` | on an element, no modifiers, no `duration`: AXPress; a row or cell without it: its table's AXSelectedRows, else AXSelected | yes | yes |
| `right_click` | AXShowMenu, no modifiers, no `duration` | yes | yes |
| `double_click` | AXOpen, no modifiers, no `duration` | yes | yes |
| `middle_click`, `triple_click`, `left_click_drag`, `mouse_move`, `left_mouse_down`, `left_mouse_up`, `key`, `hold_key`, `paste` | no | yes | yes |
| `scroll` | approximately: AXScroll<Dir>ByPage on the element or its nearest scroll area, no modifiers, max(1, round(amount / 5)) pages | yes | yes |
| `type` | the element (or the app's focused element) with AXSelectedText settable, or AXValue settable and empty or wholly selected | keys | keys |
| `set_value`, `select_text`, `perform` | yes (`perform raise`: no) | no | `perform raise` only |

### 14.4 The tiers

- **`ax`**: AX actions and values, nothing else. `perform` takes a word the element lists, a role default, or `expand`/`collapse` on an expandable element; anything else answers `action_unsupported { available }` with the words it does take. `select_text` reads AXValue, finds the match (UTF-16, `prefix`/`suffix`), and sets AXSelectedTextRange per `place`; an unsettable range is `action_unsupported`.
- **`process`**: `CGEventPostToPid` with the target window in fields 91 and 92, so a background window takes clicks, scrolls and drags without coming forward and the real pointer never moves. Modifiers go down as flagsChanged events before the action and up after, in reverse. The key-window rule (§5.2) holds for every key, `hold_key`, typing and paste. A minimized window takes no pointer verb (`window_minimized`). A drag goes to one pid, so it cannot drop onto another app.
- **`session`**, in order: refuse a locked screen (`CGSSessionScreenIsLocked` of the session dictionary; a missing key passes, the host's presence is the first guard) and, for keys, secure input (`IsSecureEventInputEnabled`); arm the person watch; take the session lock in 50 ms tries for at most 5 s (`session_unavailable { reason: 'in-use' }`); record the app in front and the pointer; activate over AX (un-minimize, AXFrontmost, AXRaise, AXMain; never `NSRunningApplication.activate`, which macOS refuses to a background caller), polling 20 ms for 400 ms until the pid is front and its AXFocusedWindow is the target (`activation-refused`), the person checked before every write and once more after; read the frames again; post at the HID tap, pointer verbs moving the pointer first. On every exit the ledger gets where the step left the Mac and the result (or the error) its `SessionChange`. A session-tier button held past the call keeps the lock and the watch until its release.
- **The person**: any watched event (key down, modifiers, moves, the three button downs, drags, the wheel) without the mark trips the watch. During a step it stops before the next event (within 10 ms in a pause), lets go of what the step holds and answers `interrupted`. Between calls, with session input held, it lets go of the held input and the lock, marks the ledger, calls `onPersonInput(pid)`, and that pid's next call answers `interrupted` once.

### 14.5 What the session tier took, and restore

The ledger keeps one record per service process: the app in front and the pointer before the first session step since the last restore, and where the last step left them. `input.restoreSession` first lets go of every held input (so it never waits on its own hold), takes the lock, and puts back each half:

- both halves give way (`person-moved`) when the person tripped the watch, used the keyboard or mouse between two session steps, or since the last one ended (the HID idle time against the step's end);
- the app half gives way when the app in front is not the one the step left there, or another app came forward meanwhile (NSWorkspace activations while no step ran); it is `app-gone` when the recorded app quit; `held` names the app it brought back;
- the pointer half gives way when the pointer is more than 2 pt from where the step left it; it goes back with `CGWarpMouseCursorPosition`, no event to any app;
- a half the steps never changed is `nothing`, and so is everything with no record. The record is cleared; a service restart loses it.

### 14.6 The probe

`input.probe` runs `process`-tier actions that change nothing lasting, judges each through AX and puts it back through AX; it never uses the session tier. A class is tried only where every value it will put back is readable and settable, else `untested` with the reason. `scroll`: one wheel click on a scroll area whose vertical bar is settable, judged by the bar's value. `key`: Right (Left at the end) on the focused text element, only when the window is key (`untested`, "the window is not key", otherwise, which the verdict's `needsKeyWindow` reads). `click`: a click at the left quarter of a character away from the caret, judged by the caret landing there; `drag`, when asked, a drag over two characters. `type` and `hover` are never probed. The candidate search reads at most 500 nodes; every element touched gets a messaging timeout of at most 0.25 s; no class starts past 1.5 s of the 2 s budget, and putting values back always runs to its end.

### 14.7 Timing

`InputTiming`, every number named; the Task benchmark may tune them: 8 ms between events, a 40 ms click, 60 ms between the pairs of a multi-click, 30 ms after a session move, a drag of 12 moves over 180 ms, 15 ms between wheel clicks, typing chunks of 20 units 10 ms apart, 300 ms for keys to show an effect, the paste's 500 ms wait inside its 2.5 s cap and 2 s lock wait, activation 400 ms polled at 20 ms, the session lock 5 s in 50 ms tries, the 30 s auto-release, the 10 s click `duration` cap, and the probe's 300 ms checks inside its 2 s.
