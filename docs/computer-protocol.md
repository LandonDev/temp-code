# The computer-use protocol

TempCode's own computer use: a Swift service on the Mac, `tc-computer`, reads accessibility trees, acts on elements and captures windows; the TypeScript host keeps one session per thread; four `computer_*` tools on the app MCP server put it in front of every model on every harness. Ten threads build it (AX reader, Input tiers, Capture, Service shell, Computer sessions and tools, Tier scheduling, Computer model instructions, Bridge path, Preview and image results, Task benchmark). This document is their contract, and each changes it with its code. It fixes:

1. the wire between the host and `tc-computer`: newline JSON-RPC 2.0 on stdio, every method, its params, result and errors, and the notifications;
2. the observation: the AX tree as indexed text, the diff after the first read, when a full tree comes back, the size budget;
3. the input tiers `ax`, `process`, `session`, the tier each action reports, the per-app verdict, the clipboard lock;
4. the smart wait;
5. capture: window screenshots to a downscaled file, and a preview stream;
6. the tools the models see, with Anthropic's native computer-use verbs and parameter names, element refs beside coordinates, and how a screenshot reaches each harness;
7. recorded fixtures from real apps, scratch content only.

**In code today**: the contract (the zod in `src/shared/computer/`: `protocol.ts` the wire, `observation.ts` the grammar, `tools.ts` the model-facing shapes; the Swift Codable types generated from it; the fixtures and the tests in both languages that parse them) and the service shell (§16: the stdio server, the smart wait, the locks, TCC, the lifecycle, the `tc-computer` binary and its build) over Capture (§6), Input (§14) and the AX reader (§15); the TypeScript host is in code too (§17: the process, one session per thread, the tier verdicts, the four tools on every harness, the cards and Stop), and so is what the person sees (§8, "What the person sees"). Where this document and the zod differ, the zod is right and this document is stale.

## 1. Process and framing

- **One service per app instance on the Mac**, spawned as `tc-computer serve` with stdin and stdout as pipes and stderr as a log. All of that instance's threads share it: AX element handles and the diff state live in the service. Each thread is a `session` inside it. A dev or proof instance spawns its own.
- **The two things there is one of per Mac**, the pasteboard and the real pointer and keyboard, are guarded by advisory file locks every service on the Mac shares, so a dev instance's service can never paste or take the session over the installed app's: `flock` on `clipboard.lock` (§5.3) and `session.lock` (held for the whole of a `session`-tier step, and while a `session`-tier button is held down, §5.1) in `tc-computer/` under the user's temporary directory as `confstr(_CS_DARWIN_USER_TEMP_DIR)` gives it, never `$TMPDIR`, so a process whose TMPDIR was overridden cannot split a lock.
- **Frames**: one JSON-RPC 2.0 object per line, UTF-8, `"jsonrpc":"2.0"` on every frame, no newline inside a frame. A line is at most 16 MiB; screenshots never ride the wire (they go to files), preview frames are capped at 512 KiB. The envelope is the framing's: `RpcRequestSchema`, `RpcErrorResponseSchema`, `requestFrameSchema(method)` and `resultFrameSchema(method)` in `protocol.ts`; `RPCFrame`, `LineReader` and `encodeLine` in `native/tc-computer/Sources/ComputerProtocol/Framing.swift`. The notification unions hold `{ method, params }` alone, since the generator tells a union's branches apart by one literal field.
- **Direction**: the host sends requests and two notifications (`$/cancel`, `capture.stream.ack`); the service answers requests and sends notifications. The service never sends a request.
- **Ids**: the host's integers, increasing. Responses may arrive out of order.
- **Lifecycle**: the host sends `initialize` first; any other method before it answers error `not_initialized`. `shutdown` is answered, then the service exits 0 within 2 s. The service also exits on stdin EOF and when its parent is gone (`getppid() == 1`, polled every 5 s, as the appshot helper does). A crash is respawned by the host with backoff (Computer sessions and tools); the new process has a new `epoch` and knows no sessions, so every element index from before is stale.
- **Cancellation**: `$/cancel { id }` stops request `id` at its next safe point (between batch steps, inside any wait, before an input event is posted). A cancelled `action.run` or `action.batch` answers its normal result: the steps already done keep their results, the step it stopped is `failed` with kind `cancelled`, the rest `not-run`, and no observation is taken (`observationError` kind `cancelled`). Any other cancelled request answers error `cancelled`. Thread Pause and Stop use it.
- **Admission**: at most 32 requests run at once, and a request's slot frees only once its response is on the pipe, so a host that stops reading holds at most 32 answers in memory; later ones wait in arrival order, and once 256 wait a new one answers -32603 `overloaded: 256 requests waiting` at once. stdin is always read: `$/cancel`, `permissions.get`, `clipboard.state` and `shutdown` never wait behind work, so `permissions.get` serves as the liveness ping.
- **Concurrency**: reads (`state.get`, `capture.*`, `apps.*`) run concurrently. Actions are serialized per app (one at a time per pid, across sessions); an action that waits more than 5 s for an app's slot fails `app_busy`. Any `session`-tier step holds the Mac-wide session lock. Reads of one app wait for its running action.
- **Versioning**: `COMPUTER_PROTOCOL = 1`. Adding a method, an optional field, an error kind or an enum value keeps 1; the generated Swift enums carry an `unknown(String)` case and the host tolerates unknown notification methods. Anything else bumps it; `initialize` with another number answers error `protocol_mismatch` and the host refuses the service.

## 2. Shared types

All in `src/shared/computer/protocol.ts`, exported as zod schemas and inferred types. Every wire shape is one the generator (§12) already emits as written: fixed-length arrays instead of tuples (`z.array(z.number().int()).length(2)` becomes `[Int]`), objects with optional fields and a refinement instead of untagged unions, discriminated unions only on a string literal field, no `z.unknown()`. `tools.ts` is TypeScript only and never generated.

```ts
type Rect = { x: number; y: number; w: number; h: number }      // points; screen space unless named otherwise
type Point = number[]          // length 2, integers: [x, y] in the session's coordinate space (§6)
type Region = number[]         // length 4, integers: [x0, y0, x1, y1], top-left and bottom-right, same space
type Tier = 'ax' | 'process' | 'session'
type Permissions = { accessibility: boolean; screenRecording: boolean }

type AppRef = { app?: string; pid?: number }                     // exactly one; app = bundle id or display name (§2.1)
type WindowRef = { id?: number; title?: string }                 // neither = the app's main window (§2.1)
type Target = {
  session: string; app: AppRef; window?: WindowRef; launch?: boolean
  epoch?: string   // the epoch of the observation the call's element indices came from; required when an action or a read names an element
}

type CoordinateSpace = { width: number; height: number; scale: number }
// width × height: the window's screenshot in pixels; scale: pixels per window point.

type AppInfo = { pid: number; bundleId: string | null; name: string; active: boolean; hidden: boolean; windows?: WindowInfo[] }
type WindowInfo = {
  id: number; title: string; frame: Rect; main: boolean; focused: boolean
  minimized: boolean; onScreen: boolean; space: 'current' | 'other' | 'unknown'
}

type WaitOptions = { minMs: number; quietMs: number; maxMs: number; busyMaxMs: number }
type WaitReport = { waitedMs: number; settled: boolean; busy: boolean; reason: 'quiet' | 'max' | 'busy-max' | 'cancelled' | 'skipped' }

type Shot = {
  path: string; format: 'jpeg' | 'png'; width: number; height: number; bytes: number
  scale: number; window: { id: number; frame: Rect }; region?: Region
  blank: boolean          // every pixel one colour: a window on another Space the compositor has not drawn
  capturedAt: number      // epoch ms
}

type ElementBrief = { index: number; line: string }               // line = the element's observation line after its indent and `[<index>] `: `button "Save"`

type ComputerAction = { action: ComputerActionName } & ActionParams // §5.1: one flat object, generated as one Swift struct
```

Named so the generator emits each once (`COMPUTER_SUBSET` in scripts/gen-swift-computer.ts is the list): `Tier`, `PermissionName`, `Permissions`, `Rect`, `Point`, `Region` (both `[Int]` in Swift), `AppRef`, `WindowRef`, `Target`, `CoordinateSpace`, `WindowSpace`, `AppInfo`, `WindowInfo`, `DisplayInfo`, `WaitOptions`, `WaitReason`, `WaitReport`, `Shot`, `ShotFormat` (`'jpeg' | 'png'`), `ElementBrief`, `ComputerActionName`, `ScrollDirection`, `ComputerAction`, `ObservationMode` (`'auto' | 'full'`, state.get), `ObserveMode` (`'auto' | 'full' | 'none'`, ObserveOptions), `ScreenshotPolicy`, `Budget`, `ObserveOptions`, `ObservationKind`, `ObservationStats`, `Observation`, `InputVia`, `ClipboardOutcome`, `StepEffect`, `StepResult` (branches `OkStep`, `FailedStep`, `NotRunStep`), `ActionResult`, `BatchResult`, `ComputerErrorKind`, `ComputerError`, `InterruptedBy`, `StaleReason`, `Empty`, `SessionRef`, the fixture shapes `RawAXValueType`, `RawAXValue`, `RawAXNode`, `RawAXTree`, and the notification unions `ComputerNotification` (the service's) and `HostNotification` (the host's), each discriminated on `method`.

### 2.1 Resolving a target

- `app` matches, in order: a bundle id exactly; a running app's display name case-insensitively; an absolute path to an `.app` (the running app whose bundle it is, else, with `launch: true`, that app launched); an installed app's name (only with `launch: true`, which launches it in the background, `activates: false`); a unique case-insensitive prefix of a running app's name. No match answers `app_not_found` with up to five close names in `data.candidates`.
- `window` absent: the app's AXMainWindow, else AXFocusedWindow, else its first standard window. `id` is the CGWindowID from `apps.list`; `title` matches exactly, then as a substring. No match answers `window_not_found` with the app's window titles.
- The **focus window** of an observation is the resolved window plus whatever is attached to it: sheets, open menus (an AXMenu the app shows), popovers and the app's focused dialog. A new standalone window does not replace the target; the observation header names it (§4.1).

## 3. Methods

Every method's params and result are a zod schema in `COMPUTER_METHODS` (`protocol.ts`): `{ [method]: { params, result } }`. Defaults below are the service's when a field is absent; the host always sends `wait` explicitly from `COMPUTER_WAIT` so the numbers have one home.

| Method | Params | Result |
|---|---|---|
| `initialize` | `{ protocol: 1, client: { name, version }, dataDir: string }` | `{ protocol: 1, service: { version, build }, epoch: string, os: { version, arch }, permissions: Permissions, displays: { id, frame: Rect, scale }[] }` |
| `shutdown` | `{}` | `{}` |
| `permissions.get` | `{}` | `Permissions` |
| `permissions.request` | `{ which: 'accessibility' \| 'screenRecording' }` | `Permissions` (as now; the grant arrives later as `permissions/changed`) |
| `apps.list` | `{ windows?: boolean }` (default false) | `{ apps: AppInfo[] }`: regular apps only (activation policy regular), the active one first, then by name |
| `apps.launch` | `{ app: string, open?: string[] }` (urls or absolute paths) | `{ pid: number, launched: boolean }` (false: it was already running); never activates |
| `session.open` | `{ session: string }` | `{}`: idempotent |
| `session.close` | `{ session: string }` | `{}`: frees its element maps, bases and streams |
| `state.get` | `Target & { mode?: 'auto' \| 'full', element?: number, screenshot?: 'auto' \| 'always' \| 'never', maxEdge?: number, geometry?: boolean, menus?: boolean, budget?: { bytes: number }, wait?: WaitOptions }` | `Observation` (§4) |
| `action.run` | `Target & { action: ComputerAction, tiers: Tier[], wait?: WaitOptions, observe?: ObserveOptions, pasteQuietMs?: number, ignored?: IgnoredRoutes }` | `ActionResult` |
| `action.batch` | `Target & { actions: ComputerAction[] (1..32), tiers: Tier[], stepWait?: WaitOptions, wait?: WaitOptions, observe?: ObserveOptions, pasteQuietMs?: number, ignored?: IgnoredRoutes }` | `BatchResult` |
| `capture.screenshot` | `Target & { maxEdge?: number, region?: Region, format?: 'jpeg' \| 'png' }` | `Shot` |
| `capture.stream.start` | `Target & { stream: string, fps?: number (1..15, default 4), maxEdge?: number (default 960) }` | `{ stream, width, height }` |
| `capture.stream.stop` | `{ stream: string }` | `{}` |
| `escape.watch` | `{ on: boolean, leaseMs?: number (1000..120000, default 30000) }` | `{}`: while on, the person's Escape is taken and told as `escape/pressed` (P1, §8); the host renews it every 10 s, and it ends on its own when a renewal is late. `permission_missing` without Accessibility |
| `input.probe` | `Target & { classes?: ActionClass[] }` (default `['scroll', 'key', 'click']`) | `ProbeReport`: which classes the app honours at the `process` tier, each tried only where its state can be put back through AX (§14.6) |
| `input.restoreSession` | `{ afterInterrupt? }` | `SessionRestore`: what the `session` tier changed since the last restore, put back unless the person moved since (§14.5; `afterInterrupt: true`, within 2 s of the person's trip, keeps only each half's own check); `session_unavailable` when another holder keeps the session lock for 5 s |
| `clipboard.state` | `{}` | `{ changeCount: number, foreignChangeAt: number \| null, watchingSince: number }` (epoch ms): when the pasteboard last changed by anyone but this service, from the change count alone (§16.4) |

Notifications from the host: `$/cancel { id }`, `capture.stream.ack { stream, seq }`.

`ObserveOptions = { mode?: 'auto' | 'full' | 'none', screenshot?: 'auto' | 'always' | 'never', maxEdge?, geometry?, menus?, budget? }`: the same knobs as `state.get`, for the observation that closes an action; `mode: 'none'` asks for none.

**Where a failure goes.** `action.run` and `action.batch` answer a JSON-RPC error only when nothing could start: `not_initialized`, `protocol_mismatch`, invalid params, `unknown_session`, `permission_missing`, `app_not_found`, `window_not_found`, and `stale_element` with reason `service-restarted` (the `epoch` check runs before any step). Every failure once steps can run is a step's: that step is `failed` with its `ComputerError`, the later ones `not-run`, and the result still carries the observation (or `observationError`, when the window it would read is gone), so the model sees where the batch left the window. `state.get` and `capture.*` answer every failure as a JSON-RPC error.

```ts
type ActionResult = {
  step: StepResult
  observation?: Observation              // absent with observe.mode 'none', or when observationError says why
  observationError?: ComputerError       // the closing observation failed (the action closed the app's last window or quit the app, §22.6; a cancel); the steps stand
}
type BatchResult = { steps: StepResult[]; observation?: Observation; observationError?: ComputerError; waited: WaitReport }

type StepResult =
  | { index: number; action: ComputerActionName; status: 'ok'; tier: Tier | null; effect: 'changed' | 'none' | 'unknown'
      element?: ElementBrief; input?: { via: InputVia; clipboard?: 'restored' | 'kept-person-copy'; on?: string /* what a fallback route acted on, §24.8 */ }
      cursor?: Point; text?: string; shot?: Shot; waited?: WaitReport
      session?: SessionChange }                       // on every step that ran at the session tier (§14.5)
  | { index: number; action: ComputerActionName; status: 'failed'; error: ComputerError }
  | { index: number; action: ComputerActionName; status: 'not-run' }
```

- `tier` is null for actions that send no input (`screenshot`, `zoom`, `cursor_position`, `wait`).
- `InputVia` is `ax-insert` | `ax-value` | `keys` | `paste` (the typing routes, §5.3), then `menu` | `hit` | `caret` | `scroll-bar` | `scroll-page` (the background fallbacks, §24), appended so the Swift enum keeps its order; `input` is present on every step a typing or fallback route ran. `ignored` (`IgnoredRoutes { via?: InputVia[], process?: ActionClass[], skip?: boolean }`) names the routes and process classes this app was seen to ignore: the service runs them last (§24.1), or with `skip` not at all, answering `needs_tier` as if they did not exist. `ComputerError` carries `menu?: string[]`, a disabled menu item's title path (§24.2).
- `effect` is what the service saw within the wait: `changed` when the focus window's tree, the focused element, a value, a selection or the set of windows moved, or a menu or sheet opened; `none` when nothing observable did; `unknown` when the app exposes too little to judge (a thin tree).
- `text` carries `cursor_position`'s answer, `X=512, Y=384`, in the session's space.
- `shot` carries the image of `screenshot` and `zoom`.
- A batch runs its actions in order, waits `stepWait` after each step that can change the screen (every action but `screenshot`, `zoom`, `cursor_position`, `wait`), and stops at the first failure: later steps are `not-run`. The final `wait` runs once after the last step that ran, then the observation.

## 4. The observation

```ts
type Observation = {
  epoch: string
  session: string
  app: { pid: number; bundleId: string | null; name: string }
  window: { id: number; title: string; frame: Rect }
  kind: 'full' | 'diff' | 'unchanged' | 'subtree'
  seq: number                 // per session × app: the baseline count, +1 per full, diff or unchanged observation returned; a subtree carries the current one
  base?: number               // the seq a diff is against
  text: string                // what the model reads (§4.1)
  space: CoordinateSpace      // what coordinates mean now (§6)
  stats: { elements: number; lines: number; bytes: number; omitted: number; thin: boolean; partial: boolean; readMs: number }
  shot?: Shot
  shotError?: ComputerError   // the shot this observation would carry could not be taken: Screen Recording off, minimized, capture failed
  waited?: WaitReport
}
```

- `omitted`: elements left out by the budget; `partial`: the walk stopped at its node or time cap; `thin`: the tree is too poor to act from (§4.5).

What the walk dropped here: the two scroll bars, two unnamed groups, and the title bar's `text "Untitled"` (it repeats the window's name).

**Header** (line 1): `app "<name>" · window "<title>" · <width>×<height>` (the coordinate space), then, in this order, any of ` · focused [<i>]`, ` · still loading` (a busy indicator showed when the wait ended), ` · changes since your last read` (a diff) or ` · no changes` (unchanged), ` · thin tree, see the screenshot` (§4.5). Line 2, only when the app has other windows: `other windows: ` and their titles, comma-separated, each followed by ` minimized` or ` other Space` when so.

**Element line**: `<indent>[<index>] <role>[ "<name>"][ = "<value>"][ <state>…][ caret <n> | selection <a>..<b>][ actions: <action>, …][ @<x>,<y> <w>×<h>]`

- `indent`: two spaces per depth among the elements kept (§4.3), at most 10 levels.
- `index`: §4.2.
- `role`: one entry of `ROLE_TAGS` (`observation.ts`), the AX role and subrole mapped to a short word: `window`, `sheet`, `dialog`, `button`, `pop up`, `menu button`, `checkbox`, `switch`, `radio`, `tab`, `tabs`, `input`, `search`, `password`, `text area`, `combo box`, `text`, `link`, `image`, `heading`, `toolbar`, `menu bar`, `menu`, `menu item`, `list`, `outline`, `table`, `row`, `cell`, `column`, `scroll area`, `slider`, `stepper`, `progress`, `busy`, `split`, `web area`, `disclosure`, `date`, `color well`, `level`, `group`. A role not in the table prints as its AX name without `AX`, split into lower-case words (`AXRulerMarker` → `ruler marker`).
- `name`: the first non-empty of AXTitle, AXDescription, the AXTitleUIElement's value, AXPlaceholderValue (shown as the name only when there is no value), then the subrole's word from `SUBROLE_NAMES` (`AXCloseButton` close, `AXMinimizeButton` minimize, `AXFullScreenButton` full screen, `AXZoomButton` zoom; the window buttons carry no title or description), as a JSON string, at most 100 Unicode scalars, then `…` inside the quotes (`cutName`).
- `value`: AXValue as a JSON string (numbers as written), at most 160 Unicode scalars, then `…(+<n> chars)` inside the quotes (`cutValue`). Never shown for `password`, nor when empty or equal to the name. Booleans of checkboxes and switches print as states instead. A number prints for no heading (Chrome's is the level) and no container (window, sheet, dialog, group, radio group, split, toolbar, tabs, tab, scroll area, row, cell, list, outline, table, web area, menu, menu bar: Swing puts a 0 on every panel).
- `state` words, only when they hold: `focused`, `selected`, `disabled`, `checked`, `unchecked`, `mixed` (checkbox, switch and radio always show one of the three), `expanded` (any role), `collapsed` (rows, cells and disclosures only: Chrome reports AXExpanded false on every web node; an AppKit disclosure triangle says it as AXValue 0 or 1), `required`, `invalid`, `modal`, `read-only` (an input, search, text area, combo box or date whose AXValue is not settable), `minimized` (a window in the Dock, §22.4).
- `caret <n>` or `selection <a>..<b>`: on the focused text element, AXSelectedTextRange in UTF-16 units.
- `actions:`: the AX actions the element exposes beyond its role's default, as words from `ACTION_WORDS`: `AXShowMenu` show menu, `AXOpen` open, `AXConfirm` confirm, `AXCancel` cancel, `AXDelete` delete, `AXIncrement` increment, `AXDecrement` decrement, `AXRaise` raise, `AXPick` pick, `AXZoomWindow` zoom window, `AXScrollToVisible` scroll to visible, `AXScroll<Dir>ByPage` scroll up, scroll down, scroll left, scroll right. A custom action is its own name: CopyActionNames returns custom actions as `Name:<name>\nTarget:…\nSelector:…` (seen on TextEdit's colour buttons), and the word is the `Name:` part, lower-cased; one with no readable name is dropped. `AXShowAlternateUI` and `AXShowDefaultUI` (hover affordances on every Finder row) are always dropped. Inside a web area, `AMBIENT_ACTIONS` (`AXShowMenu`, `AXScrollToVisible`: every web-content node in every recorded Chrome and Electron tree carries both) count as defaults of every role: never listed, never a reason to keep. A word not in the table prints as its AX name without `AX`, split into lower-case words.
- **Role defaults** (`ROLE_DEFAULTS`, AXPress's word `press`), never listed: click (AXPress) for button, link, menu item, checkbox, switch, radio, tab, disclosure; click and show menu for pop up and menu button; typing, `set_value` and show menu for combo box; typing and `set_value` for input, search, password, text area, date (unless `read-only`); click (AXPress, else selecting it) for row and cell; increment and decrement for slider and stepper; the four page scrolls for scroll area; raise for window, dialog and sheet.
- `@x,y w×h`: the frame in the session's coordinate space, only with `geometry: true` and on every observation that carries a screenshot.

**Range lines** fold a run of unnamed siblings of one role that carry no state word: `<indent>[<first>]–[<last>] <n> × <role>` (TextEdit's 15 ruler markers above). Each folded element still has its index, consecutive and in order, and takes actions like any other; the AX reader sets the run length that folds (6 by default).

**Summary lines** carry no index: `<indent>… <n> more below`, `… <n> more above`, `… <n> more below, <m> above` under a scroll area or list whose rows fall outside the visible rect; `<indent>(<role> "<name>": items not exposed to accessibility; see the screenshot)` for a container whose rows are textless stubs (JetBrains with screen-reader support off); and the last line `(truncated: <n> elements left out; observe with element: <i> to see one part whole)` when the budget cut, `<i>` the container that lost the most. A stub line's name may be left out: `(list: items not exposed to accessibility; see the screenshot)`.

**What the parser holds** (`parseObservation` in `observation.ts`, which every fixture and every `apps/*/*/observation.txt` must pass, and `formatObservation(parseObservation(text)) === text`):

- Names, values and window titles are JSON strings written as `JSON.stringify` writes them: `"`, `\`, `\b \f \n \r \t` escaped, other controls and lone surrogates as lower-case `\u00xx`, nothing else (no `\/`, no escaped non-ASCII). Swift's JSONEncoder escapes `/` unless told `.withoutEscapingSlashes`, so the AX reader writes these strings itself.
- States print in `STATE_WORDS` order, each once (`sortStates`). A role is lower-case words and never holds a state word, `caret`, `selection` or `actions:`.
- An indent is a whole number of levels and grows one level at a time; the tree starts at depth 0 and may hold several roots (a window and, with `menus: true`, the menu bar). An index appears once, a range counting each of its indices. The `(truncated …)` line is last.
- A range line carries no state or geometry, and `<n>` is `<last> − <first> + 1`. ` (and <n> inside)` ends only a removed line, after any geometry.
- An `unchanged` observation is its header alone. Marker lines and `+` groups appear only in a diff, and a diff holds nothing else.

### 4.2 Element indices

- Positive integers, per session × app (one counter across that app's windows), assigned in reading order on the first full read, starting at 1.
- An element keeps its index while it exists. Identity is `CFEqual` on the AXUIElement; where an app recreates elements (Chromium, Electron) the AX reader may also match on AXIdentifier, AXDOMIdentifier, role, name and position under the same parent, and documents its rule.
- A new element takes the next unused number; a number is never reused in that session × app, so a stale index can only fail, never act on something else.
- Acting on a removed element answers `stale_element { element, reason: 'gone' }`; on one never assigned, `no_such_element`. A restarted service counts from 1 again, so an old index could name a new element: every call that names an element carries the `epoch` of the observation the model last got for that session × app (the host keeps it per session × app and fills it in), and a mismatch answers `stale_element { element, reason: 'service-restarted' }` before anything runs. The model reads the tree again.

### 4.3 What is kept

The AX reader walks the focus window's tree (plus open menus, sheets and popovers) in AX child order and keeps an element when it has a name, a value, a role-default or listed action, a state word, or is a window, sheet, dialog, menu, list, outline, table, scroll area or web area. It drops:

- unnamed `group`, `split`, unknown layout roles and scroll bars (unless focused): their children rise to the parent's depth;
- `text` whose string equals its parent's name or value (the appshot helper's dedupe), or the name of a kept sibling control (an input's label: AppKit names the input by AXTitleUIElement, Chrome by AXTitle);
- rows and descendants outside the visible rect of their scroll area, counted into a summary line;
- the menu bar, unless `menus: true`.

A window's title-bar buttons are added from its attributes when AX leaves them out and placed last among its children, and the system's sharing badge is dropped (§22).

**The walk must cut before it descends.** Measured on the Mac (`.temp-code/computer-spec/ax-findings.md`, box only): reading one attribute per call costs about 0.67 ms a call, and Finder's list of 1,269 rows (25,297 pt tall) was still unfinished after 25 s; batched reads (`AXUIElementCopyMultipleAttributeValues`) ran about three times faster and still did not finish. So:

- read in three stages: one batch of AXRole, AXSubrole, AXPosition, AXSize and AXChildren for every node reached; one batch of what its role uses for a node inside its clip; then its actions, a long text value as a 2,000-unit prefix (`AXStringForRange`), its settable check and its label's text as calls of their own (the cost is per attribute served);
- before descending into a list, outline, table or scroll area, take only its visible children (AXVisibleRows, AXVisibleChildren, AXVisibleColumns where exposed and naming at least one: IntelliJ's names none with its rows on screen; else children whose frame meets the visible rect), and count the rest into a summary line without reading them; a listed child is judged by its frame too, and under a clip container a frame one point thin or less misses (Chrome lists every child of an overflow box and parks every scrolled-away one at its bottom edge as a 1-point sliver, so a sliver counts above when it comes before the first shown child and below otherwise);
- skip zero-size elements (Finder's scroll-bar arrows report 0×0) as lines, but walk through them: Chromium draws `display: contents` wrappers as 0×0 around visible children; inside the menu bar zero-size items are kept (a closed menu's items have no usable frame);
- set `AXUIElementSetMessagingTimeout` to 2 s per app, so a hung app answers `timeout` instead of hanging the service;
- cap the walk at 5,000 nodes and 2,000 ms; past either the text is what it has and `stats.partial` is true.

Frames are global points and may be negative or past the main display (the probe's TextEdit window sat at (3700, −244) on a second display); nothing clamps them to the main screen. Chromium and Electron apps get `AXManualAccessibility` set on first read, retried as the appshot helper does when the tree comes back thin; native apps refuse it (-25205), which is harmless.

### 4.4 The diff rule

- `mode: 'auto'` (default) answers `full` on the first read of an app in a session, after an epoch change, when the target window is another window than the base's (the resolved window changed, or the old one closed), when an element that persists moved to another parent or its siblings changed order (a sort, a reordered list: the diff grammar has no move), and when the diff's text would pass 60% of the full text's bytes. A sheet, menu, popover or dialog that opens or closes on the same window is a diff. Otherwise it answers a `diff` against the last full, diff or unchanged observation **returned** to that session for that app (its `seq` is the new `base`), or `unchanged` when nothing differs.
- `mode: 'full'` always answers the whole tree. `element: <i>` answers that element's subtree whole, as `kind: 'subtree'`, under its own budget, with values uncut up to that budget (a document's full text); a subtree is never a base and leaves `seq` where it was.
- A diff's text is the header, then three groups, each in reading order. Illustrative, after the sample above got "!" typed and Command-S (the build records the real pair, `textedit/typed` → `textedit/save-sheet`):

```
app "TextEdit" · window "Untitled" · 1280×1072 · focused [42] · changes since your last read
- [20] group "Formatting" (and 16 inside)
~ [3] text area = "Hello from the probe\nSecond line!" caret 33 actions: show menu
+ in [1]:
  [41] sheet "Save As"
    [42] input "Save As:" = "Untitled" focused selection 0..8
    [43] button "Cancel"
    [44] button "Save"
```

- `- <line>` removed, with its role and name; a removed subtree is its root with ` (and <n> inside)`; a removed range is its range line.
- `~ <line>` changed: the element's new line under its own index. Name, value, states, caret or selection and actions count; geometry alone does not. A value read as a 2,000-unit prefix compares by the prefix, its whole length and the selection. A container whose summary line changed (a scroll, a cut) prints `~ [<container>] <line>` with its new summary line one level under it; a changed `(truncated: …)` line closes the diff.
- `+ in [<parent>]:` then the added subtree in full-tree form, indented one level under the marker. `+ at top:` for a new top-level element (a menu).
- `unchanged`: the header line alone.

### 4.5 The size budget and thin trees

- Full text: at most 24,000 bytes (about 6,000 tokens) by default (`budget.bytes`, 2,000..96,000). Past it the reader keeps, in order, the focused element and its ancestors, interactive elements on screen, headings and text, then the rest; it folds the largest lists into summary lines first and ends with the `(truncated: …)` line. When even the focused path cannot fit, it drops the other-windows line, then the protected lines' `actions:`, then halves every quoted string down to 8 scalars, then drops outer ancestors other than the window line, their children rising.
- Diff text: at most 12,000 bytes, else the observation is `full`.
- `thin`: fewer than 3 elements with a role-default action and under 200 bytes of names and values, the window, sheet or dialog line and its title-bar buttons not counted (an Electron window before its content is exposed is those alone), or a stub container covers most of the window. With `screenshot: 'auto'` (the default) a thin observation carries a screenshot and its header line ends ` · thin tree, see the screenshot`.
- `screenshot: 'always'` attaches one to every observation; `'never'` to none.

## 5. Actions and input tiers

### 5.1 The action shape

One flat object, the same on the wire, in `computer_act` and in each `computer_batch` entry: `action` plus that action's parameters. The first 17 are Anthropic's native member names with their parameter names and meanings unchanged; `element` and `start_element` are added beside `coordinate` and `start_coordinate`; the last four are ours.

| `action` | Parameters | Notes |
|---|---|---|
| `screenshot` | none | the focus window; sets the session's space (§6) |
| `zoom` | `region` | the region at full resolution, scaled to fit `maxEdge`; the space does not change |
| `left_click`, `right_click`, `middle_click`, `double_click`, `triple_click` | `element?` or `coordinate?`, `text?` (modifiers), `duration?` (seconds, 0 < d ≤ 10) | neither: at the agent cursor; `duration` keeps the button down that long before the release, which `ax` cannot express |
| `left_click_drag` | `start_element?` or `start_coordinate?`, `element?` or `coordinate?`, `text?` | press, drag, release |
| `mouse_move` | `element?` or `coordinate?` | hover |
| `left_mouse_down`, `left_mouse_up` | none | at the agent cursor |
| `cursor_position` | none | `X=<x>, Y=<y>` |
| `scroll` | `scroll_direction` (`up`, `down`, `left`, `right`), `scroll_amount` (wheel clicks, 1..50), `element?` or `coordinate?`, `text?` | |
| `type` | `text`, `element?` | the literal string; with `element`, into that element |
| `key` | `text` (a key or `+`-joined combo), `repeat?` (1..100) | |
| `hold_key` | `text`, `duration` (seconds, ≤ 300, as native) | holds the app's action slot for `duration` |
| `wait` | `duration` (seconds, ≤ 300, as native) | the smart wait capped at `duration` (§7): it returns once the window settles, which is what the native member is for ("pauses before the next action, for example while an application loads"), so no model ever sleeps blind |
| `set_value` | `element`, `value` (string) | AX only |
| `perform` | `element`, `name` (an action word the element lists, or a role default) | AX only |
| `select_text` | `element`, `text?` (its first occurrence) or `range?` `[a, b]` (UTF-16), `prefix?`, `suffix?`, `place?` (`select` \| `before` \| `after`) | AX only; the first match with `prefix` right before it and `suffix` right after it; `place` selects it (the default) or puts the caret before or after it; `prefix` and `suffix` never with `range`; no match is `text_not_found` |
| `paste` | `text` (1..200,000 UTF-16 units), `format?` (`text` \| `markdown` \| `html`, default `text`), `element?` | `ax` first for `text` (or any format into an `input`): AXSelectedText, the clipboard untouched (§24.6); else `process` or `session` (Command-V under the clipboard lock, §5.3); class `type`; `step.input = { via: 'ax-insert' }` or `{ via: 'paste', clipboard }` |

- `element` and `coordinate` exclude each other, and so do `start_element` and `start_coordinate`; `mouse_move` needs exactly one of `element`, `coordinate`; `left_click_drag` needs exactly one of `start_element`, `start_coordinate` and exactly one of `element`, `coordinate`; `zoom` needs `region`; `type`, `key`, `hold_key` and `paste` need a non-empty `text` (`paste` at most 200,000 UTF-16 units, no `coordinate`); `scroll` needs `scroll_direction` and `scroll_amount`; `hold_key` and `wait` need `duration`; the three AX actions need `element`; `perform` needs `name` and `set_value` needs `value`; `select_text` takes exactly one of `text`, `range` (`range` with a ≤ b). An action refuses any parameter it does not take (`ACTION_PARAMS` is the table; `refineAction` the rules). `ComputerActionSchema` (`protocol.ts`) refines these per action; its JSON Schema is one flat object with no `oneOf`, so Codex and Muse read it as written, and it generates one Swift struct `ComputerAction` with optional fields.
- **Held input**: `left_mouse_down` holds the button until `left_mouse_up` from the same session on the same app. While it is held that session owns the app's action slot (another session's action on the app waits, then `app_busy`), every pointer action of that session uses the tier the down used (a call whose `tiers` lacks that tier fails that step `needs_tier { needed: <the held tier> }` without acting, and the button stays down), and a `session`-tier down keeps the Mac-wide session lock. The service lets go (button up at the agent cursor, every held key up) on `interrupted`, `$/cancel`, `session.close`, `shutdown`, stdin EOF, and 30 s after the down with no up.
- **Modifiers** (`text` on clicks, drag and scroll): `shift`, `ctrl`, `alt`, `super`, `+`-joined. On the Mac `super` is Command and `alt` is Option; `cmd`, `command`, `opt` and `option` are accepted as aliases.
- **Keys** (`key`, `hold_key`): X11 keysym names as Anthropic's examples use them (`Return`, `Tab`, `Escape`, `BackSpace`, `Delete`, `space`, `Up`, `Down`, `Left`, `Right`, `Home`, `End`, `Page_Up`, `Page_Down`, `F1`..`F20`, single characters), case-insensitive, joined with modifiers by `+` (`ctrl+s`, `super+shift+t`, `alt+Tab`). `KEY_NAMES` and `parseKeyCombo` in `observation.ts` are the table; the Input tiers thread maps them to virtual key codes.
- **The agent cursor**: per session × app, the last point a pointer action used, in the session's space. `cursor_position` reads it; `left_mouse_down`/`up` and clicks without a target use it. Under the `session` tier it is the real pointer, mapped into the space.

### 5.2 Tiers

| Tier | What it does | Visible to the person |
|---|---|---|
| `ax` | AXUIElementPerformAction or AXUIElementSetAttributeValue on the element | nothing: no focus change, no pointer |
| `process` | CGEvents posted to the app's pid (`CGEventPostToPid`), at window-relative points converted to screen points | nothing on screen; the app may change its own key window |
| `session` | activates the app, raises the window, moves the real pointer, types at the focused field | everything: it takes the Mac |

- Every `action.run` and `action.batch` carries `tiers`: the tiers the host allows, in order. The service uses the first allowed tier that can express the action and reports it in `step.tier`. It never chooses a tier the host did not allow; an action no allowed tier can express answers `needs_tier { needed }` without acting.
- What each tier can express, **exactly**: `ax` takes, on an element and with no modifiers, `left_click` (AXPress; on a row or cell without AXPress, setting AXSelected), `double_click` where the element exposes AXOpen, `right_click` where it exposes AXShowMenu, `set_value`, `perform`, `select_text`, and `type` into an element whose AXSelectedText or AXValue is settable (§5.3); `process` takes every pointer, key, scroll and type action at a point or at an element's centre; `session` takes all of them. **Approximately**: `ax` can scroll a scroll area by whole pages (AXScroll<Dir>ByPage, one page per 5 wheel clicks, at least one). `ax` also takes the background fallbacks of §24.2 to §24.5: a `key` combo with `super` or `ctrl` through its menu item, a click through the element under it or the caret, a `scroll` through the scroll bar. The order across tiers and routes is §24.1's: an approximate `ax` route now runs before the session tier; `step.tier` says which tier ran and `step.input.via` which route.
- **`perform raise` needs the session tier** (a correction to this section as first written, made before any service existed): raising can put the window over the person's, so `perform` with `raise` runs only when `tiers` includes `session` (the AX call is the same) and reports `tier: 'session'`; otherwise `needs_tier { needed: 'session' }`. On a minimized window it restores it first (§22.5). Every other `perform` stays `ax`. `expand` and `collapse` set AXExpanded (a row's AXDisclosing) where it is settable; they are role defaults of `row` and `disclosure`, never listed in `actions:`.
- **Keys go only to a key window.** At the `process` tier a `key`, `hold_key`, `type` by keys or `paste` posts only when the app's AXFocusedWindow is the target window; anything else, no answer included, is `key_window_unavailable` with `keyWindow { id, title }` when another window is key, and nothing is posted; and so does the `menu` route (§24.2), since a menu item acts on the app's focused window. Mouse verbs are exempt (their window fields route them). The host retries that one step at the next tier (`ax` set value or insert for `type`, `session` alone for `key` and `paste`) and records `needsKeyWindow` in the verdict.
- Seen on the Mac: Finder rows carry no AXPress (select by AXSelected or a click, open by AXOpen on the cell); TextEdit's text area exposes AXValue and AXSelectedTextRange as settable and only AXShowMenu as an action.
- **The verdict**: the host keeps, per bundle id and action class, the lowest tier that worked: `TierVerdictSchema` in `tools.ts`, `{ bundleId: string, classes: { [class]?: Tier }, misses: { [class]?: number } /* steps in a row with effect 'none' at the class's current tier */, needsKeyWindow?: boolean /* this app's background windows have been seen not key: a record, not a ban */, updatedAt: number /* epoch ms */ }`, stored by Computer sessions and tools as setting `computer.tiers.<bundleId>` and read by Tier scheduling. A class with no entry starts at `process`. Classes (`ACTION_CLASSES`, the wire's `ActionClassSchema`): `click` (clicks, mouse down and up), `drag`, `hover` (`mouse_move`), `scroll`, `key` (`key`, `hold_key`), `type`. The host learns from `effect`: a `process` step with `effect: 'none'` twice in a row in one class, where the same class then changed something at `session`, sets that class's verdict to `session`; a later `changed` at a lower tier lowers it. The host builds each call's `tiers` from the verdict; Tier scheduling decides when `session` may be in it.
- **The person's input during a `session` step**: the service watches for real keyboard and pointer events it did not post (a global event monitor; every event Input posts carries `eventSourceUserData = 0x74636370`, "tccp") and for Escape. Either stops the step at once with error `interrupted { by: 'person' }`, sends `session/interrupted`, and releases the Mac. A session step says what it changed (`step.session`, or the failed step's `error.session`); `input.restoreSession` puts it back (§14.5) when the host asks.

### 5.3 Typing and the clipboard lock

`type` tries, in order, within the allowed tiers: (1) `ax-insert`, setting AXSelectedText on the element (or the focused element), which inserts at the caret like typing; (2) `ax-value` when only AXValue is settable and the element is empty or the whole value is selected (after either write the evidence is read for up to 300 ms, and a write the app accepted that changed nothing (`none`; Chromium takes AXSelectedText on a contenteditable and drops it) goes on to (3), or answers `needs_tier` when no event tier is allowed); (3) `keys`, Unicode key events in chunks of at most 20 UTF-16 units never cut inside a grapheme cluster (`CGEventKeyboardSetUnicodeString`; a line break posts Return and a tab Tab, as real keys) at `process` or `session`, for text of 2,000 units or less with no cluster over 20 units; (4) `paste`, plain text, for the text (3) does not take, or when (3) showed no change at all (`none`; never after `changed` or `unknown`, so text never goes in twice). `step.input.via` says which ran. A `type` or `paste` naming an `element` first sets AXFocused on it and waits up to 200 ms for it to be the app's focused element; else `action_unsupported` ("[n] can't take keyboard focus") and nothing is posted.

The `paste` verb first tries the AX insert of §24.6 (`ax-insert`, the clipboard untouched) for `text`, or any format into an `input`; on `none` it goes on to the clipboard. It writes per `format`: `text` the plain string; `markdown` rendered HTML (`public.html`) and RTF (`public.rtf`) with the source as the plain string; `html` the HTML as given with its text (tags stripped, entities decoded) as the plain string. The renderers are Input's own (`MarkdownHTML.swift` walks `AttributedString`'s markdown intents; `RichTextRTF.swift` builds the attributed string), never WebKit's HTML import.

The paste runs under the **clipboard lock**, one per Mac (`flock` on `$TMPDIR/tc-computer/clipboard.lock`, §1):

1. take the lock (wait at most 2 s, else `clipboard_busy`);
2. check the destination and the key window (`process`) or the focused window (`session`), and find how Command-V will go in (§24.6): a disabled Paste item refuses here; a failure leaves the clipboard untouched;
3. snapshot every pasteboard item with every type and its data, and the `changeCount`; a `changeCount` that moved while it read, or a type whose data cannot be read (a promise its owner did not keep), is `clipboard_busy` ("the clipboard holds data that can't be saved") with nothing written;
4. write the content, noting the `changeCount` after each of Input's own pasteboard calls, then check the destination and key window again;
5. Command-V, delivered as §24.2 delivers a shortcut: the app's Paste item pressed through AX when it is enabled, else the key posted at the step's tier;
6. wait for the element's value to change, at most 500 ms;
7. on every exit, a throw or a cancel included, restore the snapshot only if `changeCount` is still ours (`clipboard: 'restored'`); if the person copied in between, leave their copy (`clipboard: 'kept-person-copy'`);
8. release the lock. It is never held over 2.5 s.

A call that carries `pasteQuietMs` (the tier scheduler sends `RECENT_COPY_MS`, 5 s, with every acting call) holds a paste off for the person's own copy: right before any paste (the `paste` verb and every route of `type` that pastes), once it holds the lock and before it reads or writes the pasteboard, the service asks its pasteboard watch whether a foreign change came within that window (`watchingSince` counted as one, as `clipboard.state` reads it). The watch reads the change count at that moment rather than waiting for its 250 ms poll, and the clipboard lock reads it as each hold begins and ends, so a copy made while the paste waited for the lock, or between two pastes, is never taken for the service's own. If so it lets the lock go and fails the step `clipboard_busy { reason: 'recent-copy' }`, the pasteboard untouched; the host waits (§20.5) and runs the call again from that step.

Reading a `password` value is never possible; typing into one is.

## 6. Coordinates and capture

- **The coordinate space** is the target window's screenshot: origin at the top-left of the window's frame (title bar included), x right, y down, integer pixels. `scale` is pixels per window point. Every `coordinate`, `start_coordinate`, `region`, `@x,y` and `cursor_position` uses it, as Anthropic's tools do with full-display screenshots. A session pixel maps to the screen at its centre, `window.frame.origin + (p + 0.5) / scale`, and a screen point back to `floor((s - origin) × scale)`, so the round trip lands on the same pixel (`CoordinateMapping` in ComputerCore; Input and the shell both call it).
- Each session × window keeps the space of its last full `screenshot` (or observation screenshot). Before any, the space is the one a screenshot at the default `maxEdge` would have. `zoom` never changes it. Every observation states it (`space`, and the header's `<width>×<height>`). A point outside it answers `out_of_bounds { coordinate, space }`.

The Capture module (`native/tc-computer/Sources/Capture/`, `ScreenCaptureKitCapture`) does everything below for one window, never the desktop. Every number is in `CaptureTuning.swift`; the ones the wire states come from the generated `ComputerDefaults`, and `src/shared/computer/captureParity.test.ts` refuses a literal in their place.

**Screen Recording.** `ScreenRecordingAccess.granted()` reads `CGPreflightScreenCaptureAccess()` and never prompts; `request()` raises the system's dialog. Every entry point checks the grant before any ScreenCaptureKit call (one without it raises the prompt) and throws `permission_missing { which: 'screenRecording' }`. Prompting is the host's decision: only when a computer tool needs the grant and it is off, at most once per install, never at boot. ScreenCaptureKit may keep a process's first answer, so the host respawns the service once when `permissions/changed` turns Screen Recording on. `CaptureRuntime.prepare()` touches `NSApplication.shared` and `CGMainDisplayID()` once (ScreenCaptureKit asserts without them); the shell calls it in `main` and every entry point calls it too.

**Screenshots** (`screenshot(windowID:maxEdge:regionPoints:format:to:)`):

- The window's live bounds come from the window server on every call (`LiveWindows`, `CGWindowListCreateDescriptionFromArray`, global points, top-left origin, never clamped; it answers for a minimized window too, which `CGWindowListCopyWindowInfo(.optionIncludingWindow)` drops). Its `SCWindow` comes from a cached `SCShareableContent` listed with `onScreenWindowsOnly: false`, so windows on other Spaces are there; the cache refreshes once when the id is missing or the size moved more than 0.5 pt, and `invalidate()` drops it on `window/changed`. The window is picked by CGWindowID, never by area.
- `SCContentFilter(desktopIndependentWindow:)` with no cursor, `ignoreShadowsSingleWindow` (the shadow's margin would shift every coordinate), `ignoreGlobalClipSingleWindow` (a window past a screen edge comes whole), best resolution, BGRA, sRGB. A covered window, one half off its display and a minimized one all capture their current pixels. Whether a minimized window answers `window_minimized` is the shell's call from AXMinimized.
- Size (`ShotGeometry`): `k = min(1, maxEdge / longEdge, sqrt(3,750,000 / pixels))` of the native size, never upscaled; one `scale` for both axes, width and height floored once. A zoom captures the whole window at the zoom's scale and crops the region (single-window capture ignores `sourceRect`), so the written image is the region at full resolution fitted to `maxEdge`. The capture races a 5 s deadline (`capture_failed` past it).
- `blank` is true when every channel, alpha included, spans at most 3 levels: a window the compositor has not drawn.
- **Format (A1).** A named `format` is used as named. With none, JPEG 0.85; when the image's flatness (on every 4th row, the share of pixels within 2 levels of their right neighbour) is at least 0.85, PNG too, kept when no larger. Text-dense UI comes out PNG (the proof's text window: 64.6 KB against 88.1 KB of JPEG), photographic content JPEG, and a mostly white window with little text JPEG too, since its PNG is the larger. `Shot.format` says which, and the host takes the image's mime type from it.
- **Files (A2).** The shell names the stem, `ShotNaming.stem` → `<dataDir>/shots/<session>/<nnnn>-<action>` (four digits, more past 9999; the action lower-cased with anything outside `[a-z0-9_]` made `_`), and Capture adds `.jpg` or `.png`. `ShotCounter` gives each session its next number, starting above the highest file already there, so a reopened session or a restarted service never reuses a name. The file is written beside its name and moved on with `renamex_np(RENAME_EXCL)`: the host never reads half a file and no shot is ever replaced. The host prunes them (Computer sessions and tools).

**The preview stream** (`capture.stream.*`, `startStream`): an SCStream on the window at `fps` (1..15, default 4), downscaled to `maxEdge` (256..2576, default 960), frames sent as `capture/frame` with the JPEG inline.

- **Only new pixels.** ScreenCaptureKit marks every sample of a covered window `complete` with a dirty rect over the whole frame, whether anything changed or not (macOS 27.2: 24 complete samples in 2.4 s of a still window, 2 distinct buffers). So a sample is sent only when its pixel fingerprint or size differs from the last one's (`PixelStats.fingerprint`, about 0.3 ms at 960 px; `PixelNovelty`).
- **Flow control** (`FrameGate`): at most 2 frames out without an ack; a newer sample replaces the held one, so nothing is encoded that will not be sent and the newest picture goes next. An ack covers every earlier frame (the pipe is ordered); one for a frame never sent is ignored. A frame left unacked for 5 s stops the stream's capture (a 1 s clock checks, so a still window that sent one frame pauses too) until the next ack, which resumes it; `StreamLifecycle` orders the pause, resume and stop calls, each waiting for the last to complete, `stop()` winning over all.
- **Frames.** Each frame is the sample cropped to its content rect (`contentRect × scaleFactor` is buffer pixels; `contentScale` must not be applied), so a window mid-resize is never letterboxed, then JPEG 0.85, re-encoded at 0.7 and 0.55 to stay under 380 KiB (the base64 line with its JSON fits the 512 KiB cap), dropped with a `log` line past that. `capture.stream.start` answers the window's size inside the buffer (`StreamHandle.startSize`, `ShotGeometry.fitted`), which every frame's crop matches. A content rect more than 1% off the configured window's aspect reconfigures the stream, at most every 250 ms.
- Frames carry the agent cursor, converted by the shell into the frame's own pixels; nothing is painted into the image, and the host preview draws only a brief click mark from `capture/click`, never a persistent cursor. While any stream or watch runs on a window, macOS draws its window-sharing badge in the title bar, and frames show it; a screenshot with nothing streaming shows the traffic lights.
- **The click** (P2). A click-class step (the five clicks, `left_mouse_down`, `perform`) says where it acted: `InputOutcome.clickAt`, session space; at the event tiers the pointer's point, at `ax` the centre of the element's frame from the tree, clipped to its scroll area's visible frame and the window (`ClickMark` in Input), never a pointer it moved. The shell sends `capture/click` at once to each of the session's streams on that window, `at × frameWidth / space.width` (and y) in the newest frame's size, with that size. It keeps the last click per session × window (`ClickCarry` in ComputerServiceKit): while the call that made it runs (its waits and a batch's later steps included) and for `clickCarryMs` (2 s) after its answer, a stream that starts on that window is sent it once, after `capture.stream.start`'s answer. A click on another window never reaches a stream.
- **The end** (`StreamHandle.ended()`, `StreamEndReason`, A3): `stopped` (`capture.stream.stop`, or the person stopping capture from the menu bar), `windowClosed`, `permission`, or `error`; the shell sends `capture/streamEnded`. A closed window ends its stream through ScreenCaptureKit's `noCaptureSource` (−3815) 25–55 ms after it goes, the 1 s bounds check behind it; a window ordered out but kept alive keeps its bounds and its stream, and AX's `window/changed` is what says it is gone.
- **Frames stay inline** (measured, the busiest scene: colour noise shifting every 100 ms at 960 px and 4 fps): p95 225 KiB of JPEG and p95 6.7 ms to encode, under the 300 KiB and 25 ms bounds for staying inline; a flat window's frames were p95 32 KB in 3.0 ms.

### The host preview relay

`ComputerPreviews` (`src/main/server/computer/preview.ts`) serves the local
`computer.preview.start`, `.ack` and `.stop` requests. It shares one service
stream per thread, using that thread's last app pid and bound window and
the largest edge its watchers requested (256..960), at 4 fps. Each socket
gets its own preview id, which survives an app or window change. A socket
can acknowledge and stop only its own previews; closing it drops them.
Hosts without computer use refuse these requests.

`PreviewGate` keeps one frame being drawn and the newest pending frame per
watcher. A draw ack releases the pending frame. Service acks go out on
receipt, including for discarded frames, while any watcher has answered
within five seconds (a new watcher gets an initial grace period). When all
watchers go quiet, service acks stop. A valid draw ack releases the withheld
service acks. A watcher takes no frame until its start answer is on the
socket (`ready`, run on the next turn of the event loop): a frame naming a
preview id the client has not been told would never be drawn or acked, and
that watcher would get nothing more. It then gets the newest frame, which
also wakes a stalled stream. Frame pushes pass straight to the asking
socket, without replay or the push coalescer.

A target change stops the old stream and starts the new one, pushing
`computer-preview` with `state: live`. A stream that ended while a start
waited says so in that start's answer (`ended`), since the push came before
the client knew its id. A row leaving ends it as `closed`;
`capture/streamEnded` maps a closed window or missing grant to
`window-closed` or `permission`. A refused start reports `minimized` or
`permission`. A new service epoch reopens the session and restarts capture;
only a failed recovery reports `restarted`. The last watcher leaving stops
the stream. `capture/click { stream, at, width, height }` reaches every
watcher of that stream as `computer-click`, outside the frame gate, even
when no pixels changed. Late clicks from an old stream are dropped. The
point uses the click notification's frame size.

The Node fake streams valid JPEGs with the same two-frame ack limit. Test
controls: `FAKE_NO_FRAMES=1`, `FAKE_STREAM_END_MS` with
`FAKE_STREAM_END_REASON`, `FAKE_ESCAPE_PRESS_MS`, and
`FAKE_ESCAPE_UNSUPPORTED=1`. Its clicks use each stream's pixel size and
carry to a matching window's new stream for two seconds. `FAKE_SHOT_FILE`
copies that file's bytes into every observation, screenshot, zoom and
capture shot, for picture proofs.

## 7. The smart wait

`WaitOptions { minMs, quietMs, maxMs, busyMaxMs }`, all measured from the moment the action's last input was posted. The service waits `minMs`, then starts the **quiet clock**, which every change restarts, and returns when it reaches `quietMs`. Quiet means no AX notification from the app (an AXObserver on value changed, title changed, created, destroyed, layout changed, focused element changed, selected text changed, selected children changed, menu opened or closed, window created, moved, resized, minimized or restored, element busy changed) and the same **shallow signature** (the focused element and a hash of its value and selection, the window's title, its sheets, and the child counts of the window and of the scroll areas the last observation showed; the window's children read without its title-bar buttons and the sharing badge, with its `AXMinimized` (§22.8); a focused value over 100,000 UTF-16 units hashes as its length and selection, and at most 32 scroll areas count). The signature is never a full walk: walks cost milliseconds per node (§4.3). It returns at `maxMs` if it never goes quiet and no busy indicator shows, and at `busyMaxMs` while one does. A **busy indicator** is a visible `busy` element, an indeterminate `progress` (no AXValue), or a `web area` whose AXElementBusy is true or whose AXLoaded is false, among those the last walk found, the app announced since (AXCreated, AXElementBusyChanged, AXLoadComplete), or a scan of the last walk's web areas found when the app changed since the last scan (breadth first, never into a child outside its clip, at most 400 nodes and 25 ms: Chrome announces no spinner it shows, measured 2026-11-09); visible is judged against its containers' frames as they are now. Neither app the probe walked exposed any of these, and Codex's service waits on the same signals (AXElementBusyChanged, AXProgressIndicator), so the quiet rule carries the wait and the busy rule only extends it.

`COMPUTER_WAIT` in `protocol.ts`, sent by the host with every call:

| Use | minMs | quietMs | maxMs | busyMaxMs |
|---|---|---|---|---|
| `action` (after the last action) | 300 | 450 | 1,500 | 5,000 |
| `step` (between batch steps) | 0 | 150 | 1,000 | 2,000 |
| `observe` (a plain `state.get`) | 0 | 300 | 1,000 | 5,000 |
| `wait` action | 0 | 450 | `duration × 1000` | `duration × 1000` |

Two rules of the service shell refine this (§16.3): **pixels count only while accessibility is weak** (a change in the window's pixels, from Capture's watch stream, restarts the quiet clock only while the last read of the app was thin or no AX change has been seen since the action, and never moves the cap), and **a busy indicator holds the wait** (while one shows, quiet does not end the wait; once one has shown, the wait ends at `busyMaxMs`, or once the indicator is gone and the window is quiet). A copy or cut step's change list also holds **a pasteboard change that is not the service's own** (§24.10).

So an action that changes nothing returns in about 0.75 s, a click that redraws in about a second, a page load when it has loaded or at 5 s with ` · still loading` in the header. The Task benchmark tunes these four rows and nothing else moves. No model ever needs to sleep; the tool descriptions say so.

**The pixel watch** (Capture's `PixelWatching`, A4). An AX notification says the app changed something; it does not say a page is still painting. So the quiet clock also listens to the window's own pixels (A5): `watch(windowID:)` starts, or keeps alive, one small SCStream per window a session acts on (256 px long edge, 10 fps, never encoded) and returns its `PixelChangeSignal` at once. The first complete frame is the baseline: it never counts, and it makes the signal `live` (37 ms cold on the Mac). Each later frame goes to `ChangeJudge`, on a grid of 8 px cells:

- A frame's dirty cells are those its dirty rects touch whose mean luma also moved more than 6 levels (a covered window's frames are all dirty, whole, whether anything changed or not); with no dirty rects, the cells whose luma moved. Idle frames never count.
- A dirty area under 0.05% of the frame never counts (a 2×18 pt caret is about 0.008%). Eight or more dirty cells always count: a page painting in, a list scrolling, a video playing, a sheet sliding down.
- Between the two, a cell dirty in three small frames within 2 s is ambient (a spinner, a ticking clock), and a small frame counts when at least two of its cells are not ambient: a spinner counts twice, then goes quiet; a progress bar moving into new cells keeps counting.

A counting frame stamps `lastChange` with its display time, the mach clock AX's `ChangeSignal.lastChange` uses. The shell calls `watch` at every `state.get` and before posting each action's input, awaits `waitLive` (at most 300 ms) when the signal is not live yet, and reads the signal or calls `watch` at least every 10 s while an action runs and through its wait; the stream stops 30 s after its last use, and at once when the window goes. While the signal is live, a `lastChange` later than the quiet clock's last restart restarts it, exactly as an AX notification does, never past `maxMs` (a busy indicator still extends to `busyMaxMs`). A watch that is not live (starting, stopped, or a window the compositor does not draw) adds nothing, and the wait runs on AX alone. Every number of the judge is `CaptureTuning.changeRule`, for the Task benchmark to tune.

### The session hold and Escape

`SessionHolds` (`computer/hold.ts`) follows a holder through calls, including
a held mouse button. Releasing it lingers three seconds; another holder in
that interval keeps the same hold. The host requests
`escape.watch { on: true, leaseMs: 30000 }` and renews every ten seconds.
The banner offers Esc only after the service answers. An older service's
method-not-found logs once and leaves the banner without Esc. Ending the
hold sends `escape.watch { on: false }` and hides the banner. An
`escape/pressed` notification stops the holder's thread through the same
`sessions.stop` path as Activity, with no linger.

The tier scheduler has not landed here. `index.ts` builds the holds and
leaves the `slot.onHolder(holds.holder)` wiring for that build; it does not
invent a slot or set `running.held`. The local `computer.proofHold { on }`
request can hold for no thread only when `TEMP_CODE_E2E_STATUS=1`. Other
instances refuse it. No thread is stopped for a proof hold.

## 9. The tools the models see

Four tools on the app MCP server, the same on every harness: claude in-process (`mcp__app__computer_*` through the SDK's `mcpServers.app`), codex and Muse through `scripts/app-mcp-bridge.mjs` (codex's `mcp_servers.app`, Muse's `session/start` `config.mcpServers.app`). `tools.ts` holds their zod input shapes and result shapes; Computer sessions and tools registers them in `apptools.ts` and the bridge (with `app-bridge.test.ts` holding the two schemas equal, as it does for the other app tools), and Computer model instructions owns every description string.

| Tool | Input | Does |
|---|---|---|
| `computer_apps` | `{ launch?: string }` | lists running apps and their windows; `launch` first starts that app in the background |
| `computer_observe` | `{ app: string, window?: string, full?: boolean, element?: number, screenshot?: boolean, menus?: boolean }` | `state.get` with the `observe` wait |
| `computer_act` | `{ app: string, window?: string, screenshot?: boolean } & ComputerAction` | one action, the `action` wait, then the observation |
| `computer_batch` | `{ app: string, window?: string, screenshot?: boolean, actions: ComputerAction[] (1..20) }` | the actions in order, the `step` wait between, one `action` wait and one observation at the end |

- `app` is a name or bundle id; observe and act launch an installed app that is not running, in the background, and say so in the step line. `window` is a title or a part of one.
- Examples, verbatim shapes: `{"app":"TextEdit","action":"left_click","element":12}`, `{"app":"TextEdit","action":"left_click","coordinate":[500,300],"text":"shift"}`, `{"app":"Safari","action":"scroll","scroll_direction":"down","scroll_amount":3,"element":5}`, `{"app":"TextEdit","action":"key","text":"Tab","repeat":4}`, `{"app":"Preview","action":"zoom","region":[100,200,400,350]}`, `{"app":"Mail","actions":[{"action":"left_click","element":31},{"action":"type","text":"Lunch?"},{"action":"key","text":"super+Return"}]}`.

**The result** is MCP content: one text part, then one image part per picture, in order.

```
left_click [14] button "Save" · ax · changed
type "Lunch?" into [33] input "Subject" · ax-insert · changed
key super+Return · process · no change seen
screenshot 1 (observation): /srv/agents/work/x/.temp-code/attachments/<sid>/computer/0007.jpg (1280×800)

app "Mail" · window "New Message" · 1280×800 · focused [33] · changes since your last read
~ [33] input "Subject" = "Lunch?" focused caret 6
```

- One **step line** per action (`formatStepLine` in `tools.ts`): the verb and its target (`stepTarget`: an element as `[<i>] <role> "<name>"` from its `ElementBrief`, a point as `x,y`, neither as `at the cursor`, modifiers as ` with shift`, a drag as `<start> to <end>`, a scroll as `down 3 on <target>`, a key with its repeat as `Tab ×4`, typed text quoted and cut at 60 scalars), then the tier (or for `type` the `via`), then `changed`, `no change seen` or `can't tell` from `effect`. A step that sends no input has no tier: `cursor_position · X=512, Y=384`, `wait up to 2 s · settled after 0.8 s`, and `screenshot` or `zoom` alone (their picture has its own line). A failed step: `<verb> <target> · failed: <error message>`. Steps after it: `Not executed: an earlier action in this batch failed.`, Anthropic's own sentence with "batch" for "turn". Tier scheduling owns one more line, for a step held for the `session` tier.
- **Pictures**, in order: each `screenshot` or `zoom` step's shot, then the observation's. Each gets a line `screenshot <n> (step <i>|observation): <path> (<w>×<h>)` (`formatShotLine`) after the step lines, and an image part in the same order. At most 4 image parts ride in one result; past that the lines still name the files, marked ` (not attached)`.
- Then a blank line, then the observation's text; when the result carries `observationError` instead, the line `observation failed: <its message>` in that place (it rides in `text` across the bridge too). With `mode: 'none'` nothing follows the step lines.
- **An image** rides as `{ "type": "image", "data": <base64>, "mimeType": "image/jpeg" }`, the way `html_preview` returns its PNG today (`apptools.ts` `htmlPreviewContent`, the bridge's `toolContent`). The file is written on the **thread's own host** (`attachmentDir(session)/computer/<n>.jpg`), so the path in the text opens with the harness's own image tool if a harness drops the image part: Claude's Read, codex's `view_image`. The transcript keeps `[image]` in place of the bytes (`withoutImageBytes` in drivers/codex.ts) and the preview shows the file. The live image proof below measures receipt per harness and CLI version; a path alone does not prove that the image part reached the model.
- **The one-tool-per-verb variant**: `COMPUTER_ACTIONS` in `tools.ts` is a table of every action with its parameter shape, from which both `computer_act` and a per-verb set (`computer_left_click`, `computer_type`, … each with `app`, `window`, `screenshot` and that verb's parameters, its required ones required; `perVerbTools()`) are built. `computerToolJsonSchema` gives each input's JSON Schema for an MCP `tools/list`: one flat object, no `oneOf` or `anyOf` at the top. Computer model instructions may benchmark the per-verb set for Claude against `computer_act` and `computer_batch` and keep the faster; nothing below the tools changes. The Codex REPL shape stays out of scope until the typed tools prove slower.

## 14. Input as built

`native/tc-computer/Sources/Input/` performs the actions of §5 on one window and says which tier it used. It builds to `InputPerforming` (§11); the Service shell routes `input.probe` and `input.restoreSession` to it, implements `MacLock` twice over `flock`, keeps the crash ledger from `onHeld`, and counts the smart wait from `lastInputAt`. Public API only: no SkyLight or other private call.

### 14.1 Files

Most of Input is **pure**: Foundation and the wire, no AppKit, CoreGraphics or AX, each piece generic over the system it touches, so its suites run on the box's Linux toolchain as well as on the Mac. `InputTiming` (every delay and cap), `KeyCombo` (the same parse as `observation.ts`), `KeyCodes`, `KeyLayout` (`USANSILayout`), `TextMatch`, `TierPlan`, `Geometry`, `EventPlan` (`SyntheticEvent`, `EventPlans`), `Evidence` (the typing and paste evidence, `TypingRoute`), `PersonMark` (`TC_EVENT_MARK`, `isPersonEvent`), `InputClock`, `EventRoute` (`EventSink` and the poster), `Held` (held input across calls), `SessionLedger`, `SessionFlow` (`SessionHost`, `PersonWatching`, the session driver), `ProbeRun` (`ProbeAccess`, `ProbeJudge`), `PasteFlow` (`PasteboardStore`) and `InputCore` (the event-posting verbs at `process` and `session`, the trip between calls, restore, the stale release). `MarkdownHTML` is Foundation but Mac-only (`AttributedString`'s markdown intents). The **live** layer reads and writes the Mac: `AX`, `EventMaker`, `EventSink` (`LiveEventSink`), `CurrentKeyLayout`, `PersonWatch`, `AXTier`, `ProcessTier`, `SessionTier` (`LiveSessionHost`), `Pasteboard` (`SystemPasteboard`, `PasteContent.make`), `RichTextRTF`, `Typing`, `Probe` (`LiveProbeAccess`) and `InputEngine`. `Names.swift` aliases the wire's `Rect`, `Point` and `WindowRef` over Carbon's inside the module; `Generated/InputTables.swift` is the generator's (§12).

### 14.2 The engine

`InputEngine(clipboardLock:, sessionLock:, recentForeignCopy:, onPersonInput:, onHeld:, sink:, pasteboard:, layout:, watch:, clock:)`; `recentForeignCopy(withinMs)` is the shell's pasteboard watch (§5.3's `pasteQuietMs`), which the paste flow asks once it holds the clipboard lock. `perform`, `probe` and `restoreSession` are synchronous and refuse the main thread; the person watch (NSEvent monitors) and the key layout (TIS) run on main and are reached through a hop bounded at 1 s. `perform` parses the action's strings, reads the element's facts, chooses the tier (§14.3) and answers `needs_tier` before touching anything; `screenshot`, `zoom` and `wait` are the shell's and answer `action_unsupported`; `cursor_position` answers the agent cursor (the real pointer while a session-tier button is held). Before any AX call `AXIsProcessTrusted()`, and before posting `CGPreflightPostEventAccess()`: either missing is `permission_missing`. `target.cancelled()` is checked before every posted event and inside every pause; a cancel lets go of what the step holds and answers `cancelled`. AX errors map: invalid element → `stale_element { reason: 'gone' }`, unsupported action, attribute or argument → `action_unsupported`, cannot complete → `timeout`, API disabled → `permission_missing`; every element Input calls has a 2 s messaging timeout. Every event comes from a private-state `CGEventSource` and carries `eventSourceUserData = 0x74636370` ("tccp").

Points: a session-space `[x, y]` maps to `frame.origin + point / scale` (frames in global points, never clamped; `out_of_bounds` outside the space); an element's point is the centre of its frame clipped to its scroll area and the window, after one `AXScrollToVisible` if nothing of it shows; a pointer verb with neither element nor coordinate uses the agent cursor, and with none answers `out_of_bounds` ("No pointer position yet"). At the session tier the frames are read again after activation.

### 14.3 Choosing the tier

`planRoutes` (TierPlan.swift) lists the action's routes in §24.1's order: exact routes at `ax` then `process` that `ignored` does not name, then approximate ones, then `session`, then the ignored ones (none with `skip`); `chooseRoute` is the first, and the engine tries the next only when a route did nothing it could tell (`RouteFellThrough`: a caret that moved nothing, a page action refused on its first call). With no allowed route it answers `needs_tier` naming the lowest tier that has one. A held button forces its tier on every action that posts events. The facts the fallbacks need (the menu item, the hit chain, the scroll area) are read lazily, only for the verb that needs them (`LiveRoutes`).

| Action | `ax` | `process` | `session` |
|---|---|---|---|
| `left_click` | on an element, no modifiers, no `duration`: AXPress; a row or cell without it: its table's AXSelectedRows, else AXSelected; else `hit` (§24.3) and `caret` (§24.4), at a coordinate too | yes | yes |
| `right_click` | AXShowMenu, no modifiers, no `duration`; else `hit` AXShowMenu | yes | yes |
| `double_click` | AXOpen, no modifiers, no `duration`; else `hit` AXOpen | yes | yes |
| `key` | a combo with `super` or `ctrl`: `menu` (§24.2) | yes, unless its menu item is disabled in the background | yes |
| `paste` | `ax-insert` for `text`, or any format into an `input` (§24.6) | yes | yes |
| `middle_click`, `triple_click`, `left_click_drag`, `mouse_move`, `left_mouse_down`, `left_mouse_up`, `hold_key` | no | yes | yes |
| `scroll` | no modifiers: `scroll-bar` (§24.5); approximately, after `process`: AXScroll<Dir>ByPage on the element or its scroll area, max(1, round(amount / 5)) pages | yes | yes |
| `type` | the element (or the app's focused element) with AXSelectedText settable, or AXValue settable and empty or wholly selected | keys | keys |
| `set_value`, `select_text`, `perform` | yes (`perform raise`: no) | no | `perform raise` only |

### 14.4 The tiers

- **`ax`**: AX actions and values, nothing else. `perform` takes a word the element lists, a role default, or `expand`/`collapse` on an expandable element; anything else answers `action_unsupported { available }` with the words it does take. `select_text` reads AXValue, finds the match (UTF-16, `prefix`/`suffix`), and sets AXSelectedTextRange per `place`; an unsettable range is `action_unsupported`.
- **`process`**: `CGEventPostToPid` with the target window in fields 91 and 92, so the real pointer never moves and nothing comes forward. Whether a background window acts on the events is the app's: on macOS 27.2 TextEdit and Chrome ignore left clicks, drags and the wheel (right click and plain keys work), which the probe reports as `ignored` (§14.8, measured). Modifiers go down as flagsChanged events before the action and up after, in reverse. The key-window rule (§5.2) holds for every key, `hold_key`, typing and paste. A minimized window takes no pointer verb (`window_minimized`). A drag goes to one pid, so it cannot drop onto another app.
- **`session`**, in order: refuse a locked screen (`CGSSessionScreenIsLocked` of the session dictionary; a missing key passes, the host's presence is the first guard) and, for keys, secure input (`IsSecureEventInputEnabled`); arm the person watch; take the session lock in 50 ms tries for at most 5 s (`session_unavailable { reason: 'in-use' }`); record the app in front and the pointer; activate over AX (un-minimize, AXFrontmost, AXRaise, AXMain; never `NSRunningApplication.activate`, which macOS refuses to a background caller), polling 20 ms for 400 ms until the pid is front and its AXFocusedWindow is the target (`activation-refused`), the person checked before every write and once more after; read the frames again; post at the HID tap, pointer verbs moving the pointer first. On every exit the ledger gets where the step left the Mac and the result (or the error) its `SessionChange`. A session-tier button held past the call keeps the lock and the watch until its release.
- **The person**: any watched event (key down, modifiers, moves, the three button downs, drags, the wheel) without the mark trips the watch. During a step it stops before the next event (within 10 ms in a pause), lets go of what the step holds and answers `interrupted`. Between calls, with session input held, it lets go of the held input and the lock, marks the ledger, calls `onPersonInput(pid)`, and that pid's next call answers `interrupted` once.

### 14.5 What the session tier took, and restore

The ledger keeps one record per service process: the app in front and the pointer before the first session step since the last restore, and where the last step left them. `input.restoreSession` first lets go of the held `session`-tier input (so it never waits on its own hold; a `process`-tier hold is another session's drag and stays down), takes the lock, and puts back each half:

- both halves give way (`person-moved`) when the person tripped the watch, used the keyboard or mouse between two session steps, or since the last one ended (the HID idle time against the step's end);
- the app half gives way when the app in front is not the one the step left there, or another app came forward meanwhile (an NSWorkspace activation while no step ran, of an app other than the one the last step left in front: NSWorkspace tells of Input's own activation only after the step has returned); it is `app-gone` when the recorded app quit; `held` names the app it brought back;
- the pointer half gives way when the pointer is more than 2 pt from where the step left it; it goes back with `CGWarpMouseCursorPosition`, no event to any app;
- a half the steps never changed is `nothing`, and so is everything with no record. The record is cleared; a service restart loses it.
- `afterInterrupt: true` is the host's restore on `session/interrupted`: the touch is what proves the person there, and their next keys go to the raised app. Within `SERVICE.restoreAfterInterruptMs` (2 s) of the trip (its time is kept on the record, during a step or between calls) the first rule is skipped and each half keeps only its own; past it, or with no trip on record, the call is the plain one.

A session step's `SessionChange` also carries its span, all epoch ms: `armedAt` (the step armed its person watch), `idleAtArmMs` (the login session's idle time then, `CGEventSource.secondsSinceLastEventType(.combinedSessionState, kCGAnyInputEventType)`, as Electron's `powerMonitor` reads it) and `lastInputAt` (its last posted event, `mach_absolute_time` converted through `mach_timebase_info` against one clock pair read at arm time, `TickEpoch`). A step that posted nothing carries none of the three; a failed one carries them as an ok one does.

### 14.6 The probe

`input.probe` runs `process`-tier actions that change nothing lasting, judges each through AX and puts it back through AX; it never uses the session tier. A class is tried only where every value it will put back is readable and settable, else `untested` with the reason. `scroll`: one wheel click on a scroll area whose vertical bar is settable, judged by the bar's value. `key`: Right (Left at the end) on the focused text element, only when the window is key (`untested`, "the window is not key", otherwise, which the verdict's `needsKeyWindow` reads). `click`: a click at the left quarter of a character away from the caret, judged by the caret landing there; `drag`, when asked, a drag over two characters. `type` and `hover` are never probed. The candidate search reads at most 500 nodes; every element touched gets a messaging timeout of at most 0.25 s; no class starts past 1.5 s of the 2 s budget, and putting values back always runs to its end, each value read back for up to 0.25 s (Chrome and Electron answer an AX write asynchronously).

### 14.7 Timing

`InputTiming`, every number named; the Task benchmark may tune them: 8 ms between events, a 40 ms click, 60 ms between the pairs of a multi-click, 30 ms after a session move, a drag of 12 moves over 180 ms, 15 ms between wheel clicks, typing chunks of 20 units 10 ms apart, 300 ms for keys to show an effect, the paste's 500 ms wait inside its 2.5 s cap and 2 s lock wait, activation 400 ms polled at 20 ms, the session lock 5 s in 50 ms tries, the 30 s auto-release, the 10 s click `duration` cap, and the probe's 300 ms checks inside its 2 s.

## 15. The AX reader

What `native/tc-computer` reads with, as built (plan `.temp-code/plan-8sO1AAx_glmS.md`).

| Part | Where | Runs on |
|---|---|---|
| The rules that need no live element: the node model, keep, facts, the viewport cut, indices, folds, the budget, rendering, the diff, the builder; the reader's pure decisions (`WindowMatch`, `ManualAccessibility`, `BusyRule`, `Signature`) | `Sources/AXText/` | box and Mac |
| The grammar's tables, generated from `observation.ts` | `Sources/AXText/Generated/ObservationTables.swift` (`bun run gen:swift-computer`, checked by `check:swift-computer`) | box and Mac |
| The three-stage walk, handles, window resolution, `AXManualAccessibility`, the change monitor, `AppReader`, `AXReaders`, `AppWindows` | `Sources/AXReader/` | Mac |
| The dev tool of the proof and the timings (`observe`, `session`, `bench`, `windows`, `replay`) | `Sources/tc-ax/` | Mac; `replay` anywhere |
| The rules on hand-built snapshots, and the goldens | `Tests/AXTextTests/`, `fixtures/apps/<app>/<state>/{observation,diff,truncated}.txt` | box and Mac |
| The AX glue without a live app | `Tests/AXReaderTests/` | Mac |

- **Indices.** One `IndexAllocator` per session × app key (bundle id, else name), so an app back under a new pid counts on; one `IndexBook` per session × pid. A read keeps a number in three steps: the same element (CFEqual through the handle table) keeps its number wherever it now sits; then, parent first, a rebuilt element under its matched parent takes the number of the one base element with its key: the DOM id when it has one; else role, subrole and name wherever it now sits, when no other kept child of that parent has them in either read (a child with a DOM id counts); else role, subrole, name and place among the parent's kept children. A key seen twice on either side matches nothing, so two siblings of one name keep the place rule. Last, a kept element under another parent, or kept siblings out of their order, make the read full. The target window keeps its root's number while its window id is the base's. Value, states and actions are not in the key: a changed value on a kept number is a `~` line. Past 20,000 entries the ones seen longest ago go, and their numbers answer `stale_element`.
- **The base and the diff.** The next base is the whole budgeted full render of every read, whatever kind came back, so the model's picture is always the last full text with every change applied. A diff is full when the window id differs, an element moved or siblings reordered, a shown element's displayed parent changed or a stub line moved (the grammar cannot say those), or the diff passes 60% of the full text or 12,000 bytes. A subtree read never touches the base.
- **The walk.** Stage A (role, subrole, position, size, children) for every node reached; stage B, one batch by role class, only inside its clip; stage C its actions, a long text value as a 2,000-unit prefix, the settable check and its label's text. A popover or menu is judged by its own frame. 5,000 nodes or 2,000 ms, then `partial`; depth 64; a node seen twice stops its branch; a 2 s messaging timeout, a hung window `timeout` after one wait.
- **Windows.** The CGWindowID comes from `_AXUIElementGetWindow`, the one private symbol, looked up through `PrivateSymbol` (§16.6, native/tc-computer/README.md), else the one window of that pid whose bounds match the AX frame within a point; with neither the read is `window_not_found`.

## 16. The service shell

`native/tc-computer/Sources/ComputerServiceKit/` (pure, Foundation only), `Sources/ComputerService/` and `Sources/tc-computer/`. The shell resolves, routes, waits and owns the locks; the modules read, act and capture.

### 16.1 Process shape

- `tc-computer serve` ignores SIGPIPE, sets the activation policy to `.prohibited` (no Dock icon, no menu bar), prepares Capture on the main thread and runs `NSApp.run()`. **The main thread runs the AppKit loop and never blocks**: Input's person watch and key layout reach it with `DispatchQueue.main.async`; no AX call, capture or request runs there.
- stdin is read by one thread with blocking `read(2)` into a line splitter that drops a line past 16 MiB up to its newline (answered -32700 with a null id); stdout is written by one thread draining the outbox; stderr carries log text only. **stdout carries frames and nothing else**: no product target calls `print(` or writes `FileHandle.standardOutput`.
- Each request runs as a Swift task. Every blocking module call runs on a **worker**, one serial queue per session × pid, which keeps that pair's AX handles: the resolved window elements and the reader. Only `Sendable` values come back to the request task.
- **App slots**: one per pid, fair. Actions take it exclusively in arrival order (5 s, else the step fails `app_busy`); reads take it shared and wait for a running or queued action. A session holding a button or key down (Input's `onHeld`) is the slot's sticky owner until it is let go: its own actions go through, other sessions' wait. `apps.*`, `permissions.*`, `clipboard.state` and `input.restoreSession` take no slot.
- **The outbox** has two lanes: responses and every notification but `capture/frame` first, frames only when the first lane is empty. An unsent `window/changed` of the same pid, window and change is replaced by the newer one; at most 100 `log` lines wait, past that the oldest go and one warn says how many. Producers never block; a host that leaves 64 MiB unread is treated as gone (exit 70).
- **The pure rules** (`ComputerServiceKit`, tested on the box): `Router` (framing errors, the init gate, typed handlers naming a bad field, admission, cancel), `Outbox`, `WaitRule`, `MacLocks` and `FileLock`, `AppMatcher`, `SessionBook` and `EpochCheck`, `HeldLedger`, `ClipboardWatchRule`, `Trace`, `LineSplitter`, `FileDescriptorSink`.

### 16.2 Lifecycle and what the host may rely on

Every exit the service decides on runs one path within 2 s: stop reading, cancel every request, let go of held input, stop every stream (`capture/streamEnded` `stopped`), close the readers, drain the outbox until 500 ms are left, exit; a timer ends the process at 2 s whatever is unfinished. The first cause fixes the code.

1. **Respawning is always safe.** Locks die with the process; held input is released at the next `initialize` (below); shots are never overwritten; nothing else persists. Input's session record (what `input.restoreSession` would put back) is lost.
2. **Every process has a new `epoch`.** A call naming a session the new process never opened answers `unknown_session`: open it again (`session.open` is idempotent) and retry once. Element indices from the old epoch answer `stale_element` (`service-restarted`). Preview streams do not survive.
3. **Exit codes**: 0 a clean exit (stdin EOF, `shutdown`, SIGTERM, SIGINT, SIGHUP, a failed write to stdout, the parent gone); 75 a restart to take a new Screen Recording grant (§16.5): respawn at once, no backoff; 64 a bad command line; 69 macOS older than 14; 70 an internal fault, or 64 MiB the host never read. A signal is a crash; so is any other code.
4. **stdout carries frames only.** A line that is not a JSON-RPC frame means a broken binary: kill and respawn.
5. **Liveness**: `permissions.get` answers from memory, takes no slot and waits on no worker, so it answers while an app hangs every AX call and all 32 slots are taken.
6. **One service per data dir**: `initialize` takes `<dataDir>/service.lock`, waits 3 s for a service still exiting, else answers `already_running`. A second `initialize` with the same `dataDir` answers the first result again; with another, -32600.
7. **The paste window**: a crash in the at most 2.5 s between writing the pasteboard and restoring it leaves the service's text on the clipboard; the lock frees.

**Held input across a crash**: `<dataDir>/held.json` holds every button or key held past one event pair, written (by rename) before the down is posted and removed after its up, from Input's `onHeld`. At `initialize` the records whose writer pid is dead go to Input's `releaseStale`, which posts their ups at their tier, and one `log` info says how many. A down and up posted close together (an ordinary click, a chord, typing) is not recorded.

### 16.3 The smart wait as built

Times count from `t0`, Input's `lastInputAt` (else the moment `perform` returned). Before posting, the shell starts or keeps Capture's watch on the window (only with Screen Recording) and waits up to 300 ms for its baseline, then reads the reader's signature (`sig0`) on the worker; a keep-alive touches the watch every 10 s while the step and its wait run. The runner samples every 25 ms: the AX change stamp and the watch's last counted change from memory, the signature every 100 ms and the busy indicator every 200 ms on the worker. The rule (`WaitRule`):

1. Nothing ends before `minMs`; the quiet clock starts there and restarts at every change: an AX notification after `t0`, a new signature, a busy indicator coming or going, a pixel change that counts.
2. A pixel change counts only while the session's last read of the app was thin, or no AX notification and no signature change has been seen since `t0`; it never moves the cap.
3. While a busy indicator shows, quiet does not end the wait; once one has shown, the cap is `busyMaxMs`.
4. It ends `quiet` at `quietMs` of quiet with no indicator showing; else `busy-max` or `max` at the cap; `cancelled` on `$/cancel`. An app that quits ends it `quiet` at once.

The step's `effect` comes from the same samples: `changed` when anything counted moved, else `unknown` when the session's last read of the app was thin, else `none`. `screenshot`, `zoom` and `cursor_position` skip the wait (`reason: 'skipped'`); the `wait` action runs the rule with its own row. The observation that follows passes `loading` (the wait ended busy) and `noteThin` to the reader. A batch waits `stepWait` after each step that can change the screen, stops at the first failure and waits `wait` once after the last step that ran.

### 16.4 The Mac-wide locks and the clipboard signal

`MacLocks` takes `flock(LOCK_EX | LOCK_NB)` through a fresh descriptor per acquire, tried every 10 ms, in a `0700` directory; a flock belongs to its open file description, so two sessions in one service exclude each other as two services do, and the kernel drops it when the process dies. Input takes both locks itself, through the shell's two `MacLock` adapters: the clipboard one for a paste and its restore (2 s, else `clipboard_busy`; a hold past 2.5 s is logged, never broken), the session one for a `session`-tier step or hold (5 s, else `session_unavailable` `in-use`). `tc-computer hold-lock clipboard|session <ms>` takes one from the command line, prints `{"held":true}` and lets go after `ms`.

`clipboard.state` comes from the pasteboard's change count, read every 250 ms from `initialize` on, never its contents (so it cannot raise macOS's paste privacy prompt). A change seen while this service held its clipboard lock at any moment since the last read is its own; any other change, another service's paste included, stamps `foreignChangeAt`, and so does a paste whose outcome was `kept-person-copy`. "Quiet for N ms" is `now − max(foreignChangeAt ?? 0, watchingSince) ≥ N`. The service refuses nothing on it: when a paste may run is the host's call.

### 16.5 TCC

Accessibility is `AXIsProcessTrusted()`, read live. Screen Recording is read from a fresh child, `tc-computer permissions` (`{"accessibility":bool,"screenRecording":bool}`), since a long-lived process may keep its first answer; a child of the service is a child of TempCode, so TCC answers for TempCode. The grants are read every 2 s while one is off, every 30 s while both are on, and at once when a module says one is missing; a flip sends `permissions/changed`. When Screen Recording comes on, the service waits up to 10 s for requests in flight and exits 75 so its captures take the grant. `permissions.request` asks the system at most once per grant per process run; the service never asks on its own. A call that needs a grant that is off answers `permission_missing` with `which`; an observation's shot that cannot be taken never fails the observation: it comes back with `shotError`. Every picture path (`capture.screenshot`, `capture.stream.start`, the `screenshot` and `zoom` actions, an observation's shot) goes through one guard: Screen Recording off is `permission_missing`, a minimized window `window_minimized`.

### 16.6 Private symbols

A private symbol is allowed in a product target only when it is read-only, resolved by name at run time through `ComputerCore/PrivateSymbol.swift` (the one file that calls `dlsym`), has a public fallback, and has a unit test that forces the lookup to miss (the lookup's `missing:` names, so a test forces it without touching a global; `TC_COMPUTER_PRIVATE_MISS=all` or a comma list for a whole process). The one so far is the AX reader's `_AXUIElementGetWindow` (§15), whose test resolves the lookup forced to miss and finds the window by the window list. `native/tc-computer/README.md` lists each one with its fallback and test, and what was refused. `scripts/tc-computer-guard.test.ts` holds the rules and the stdout rule over every product target.

### 16.7 Trace

`TEMP_CODE_COMPUTER_TRACE=1` in the service's environment logs on stderr every frame in (`→`) and out (`←`) with a millisecond stamp, every lock taken and let go, and every wait's report (`wait 812ms quiet ax=3 sig=1 px=0`). A `capture/frame`'s data prints as `<jpeg 41233 bytes>`; a line past 2,000 characters is cut with `…(+N)`. Off, stderr carries warnings and errors only.

### 16.8 Build and signing

## 17. The host: sessions and tools

`src/main/server/computer/` is the TypeScript side: it runs `tc-computer`, keeps one session per thread and puts the four tools in front of every model. Every word it says first is in `src/shared/computer/words.ts` and `hostErrors.ts`; the Computer model instructions thread owns the wording after.

### 17.1 The process

- **Availability** (`binary.ts`): computer use runs on a Mac with a screen, `TEMP_CODE_COMPUTER` not `0`, and the binary at `TEMP_CODE_COMPUTER_BIN`, else `resources/native/tc-computer`. Each reason off is one line (`computer use runs on a Mac`, `this host runs without a screen`, `turned off`, `tc-computer is not built`). index.ts builds the host when the first three hold and asks for the binary again at every spawn and every harness start, so a dev tree whose build finishes after boot still gets it. The box never builds a host; it serves its threads through the bridge (§18). A headless Mac instance serves computer use only with `TEMP_CODE_COMPUTER=1` and `TEMP_CODE_USER_DATA` both set (the bridge proof's isolated instance: tc-computer touches AppKit itself, so the main process needs no window).
- **One connection** (`connection.ts`): `tc-computer serve` on pipes; every frame checked against `protocol.ts` both ways (bad params never reach the service; a result that fails its schema rejects that request alone); a line that is no JSON-RPC frame kills the process as `bad-output`. A cancelled signal sends `$/cancel`. Each method has a deadline (`COMPUTER_DEADLINES`: `initialize` 10 s, an action 60 s plus its own `duration`, a batch at most 10 minutes); past it the host sends `$/cancel`, waits 3 s more, then answers `timeout` and pings. The exit is classified by the shell's codes (§16): 0 clean, 75 a restart for a new Screen Recording grant, 64 a bad command line, 69 an old macOS, 70 a fault, a signal or any other code a crash. Every request still pending answers `service_restarted`.
- **The supervisor** (`service.ts`): spawned on the first call, never at boot; concurrent first calls share one start. Exit 75 respawns with no wait. A crash, a fault, bad output or a killed process waits 0.5, 1, 2, 4, 8, 16, then 30 s before the next spawn; five inside two minutes put the service down for five minutes with the last stderr line as its reason. A bad command line or an old macOS make it unavailable for good. While a request has run over 10 s, `permissions.get` is a ping every 30 s with a 3 s deadline; two misses kill the process. With no request and no live session for 10 minutes it sends `shutdown`. Its state (`off`, `starting`, `up`, `idle`, `down`, `unavailable`, with the pid, the epoch, the restarts and the grants) is what `computer.sessions` answers.
- **The trace**: `TEMP_CODE_COMPUTER_TRACE=1` logs every frame each way as `[computer] → …` and `[computer] ← …` with a millisecond stamp, any `data` over 1 KiB as `<base64 N bytes>`, each line cut at 2,000 characters; the service's own trace (§16) goes to the same log through its stderr.

### 17.2 Sessions

- **One per thread** (`sessions.ts`), named by the thread id, or `t_` and 40 hex of its sha256 when the id does not fit `^[A-Za-z0-9_-]{1,64}$`. It opens once per epoch; a call answered `unknown_session` opens it again and runs once more.
- **One call at a time per thread**, in arrival order, so the diff chain the model reads stays in order and cards come up one at a time. Threads run at once; the service serializes per app.
- **The bound window**: a call that names no window targets the window this thread last used in that app while it is open, else the app's main window. A call whose window closed binds the one its observation names, and an observation error that says the window or the app is gone (`window_not_found`) forgets it (§22.6).
- **The book** (`elements.ts`): every element an observation named, with its line, kept through diffs and subtrees, so a card says `button "Save"` without asking the service. An element named in an app this thread never read answers `no_observation` with no request.
- **The epoch**: every call that names an element carries the epoch of the observation the model last got for that app. After a restart that epoch is old and the service answers `stale_element`; the model reads again.
- **needsFull**: an observation the service returned that the model never saw (a retried batch's) makes that app's next read `full`, so the model never gets a diff against a tree it did not see. A subtree read leaves it set.
- **Live rows**: a thread's session is live from its first computer call in a turn until the turn settles, a Stop or the thread's end. The row names the thread, its apps last used first with each one's window, the running call in activity words and the last step's tier; rows push at most four a second. A live session keeps the service from its idle shutdown.
- **Idle close**: 10 minutes after a thread's last call its service session closes and the service's shot directory for it goes; the thread's end does the same at once. Pictures land under the thread's attachment dir as `computer/<nnnn>.<ext>`, numbered by the thread's own counter, so a restarted service's numbering never overwrites one, and the archive and delete sweeps take them with the thread. At boot the service's session directories untouched for a day go.

### 17.3 Tier verdicts

The verdict (`verdicts.ts`, `TierVerdictSchema` with `needsKeyWindow` and `probedAt`) lives in the setting `computer.tiers.<bundleId>` and is forgotten after 30 days, since an app update may fix what it records. Each step's tiers: `ax` first, `process` unless its class's verdict is `session`, `session` only when the gate admits it (with `session` admitted, a class that missed twice at `process` skips it, so the session step that raises the verdict runs). Learning follows §5.2: `none` at `process` counts a miss, `changed` at `process` sets the class to `process`, `changed` at `session` after two misses sets it to `session`, `unknown` learns nothing, and `key_window_unavailable` sets `needsKeyWindow` without banning `process`.

- **The probe**: the first call that would send `process` input to an app with no verdict runs `input.probe` once, after its card: `honoured` sets the class to `process`, `ignored` puts it two misses in, a key window elsewhere sets `needsKeyWindow`, and `probedAt` is stamped whatever happened. Never for a call that only acts at `ax`, never without Accessibility.
- **The key-window retry**: a `type` that fails `key_window_unavailable` runs again once with `tiers: ['ax']`; a `key`, `hold_key` or `paste` needs the session tier and goes to the gate, and a `key` or `paste` retries with the gate's tiers less `ax` and `process` (the `menu` route refuses a window that is not key as the posted keys do, §24.2).
- **`ax` first under a `session` verdict** (§24.1): a step the verdict sends to the session tier that may have an `ax` route (`mayRunAtAx` in `tools.ts`: a `key` with `super` or `ctrl`, a plain `left_click`, `right_click` or `double_click`, a plain `scroll`, a `paste`, a `type`) runs with `tiers: ['ax']` and `ignored { skip: true }` first, so a route the app ignored is never its only try, and goes to the gate only when that answers `needs_tier` (any `needed`); a step with no `ax` route asks the gate first as before. This is the general form of §22.3's title-bar click. The card claims the session tier up front only for a step without an `ax` route.
- **Ignored routes** (§24.1): `viaMisses` on the verdict counts the learned routes (`LEARNED_VIAS`: `hit`, `caret`, `scroll-page`) as `misses` counts classes: `none` one up, `changed` cleared, `unknown` left; `TierVerdicts.ignoredFor` names each route and each process class at `VERDICT_MISSES_TO_RAISE` or more, and every acting call carries it as `ignored`. Not learned, on purpose: `scroll-bar` (its common no-op is a bar already at its end), `menu` (an enabled item is the app's own command, and many change nothing in the window) and the typing routes (§5.3 moves on within the step).
- **A refused disabled item**: a gate refusal of a step whose `needs_tier` named a menu item says the item first (`sessionRefusedLine(reason, app, { menu })`): "File › Close is disabled while TextEdit is in the background; needs the session tier …".
- **Split batches** (`batchPlan.ts`): `action.batch` takes one tier list, so steps whose lists differ run as segments of equal lists; every segment but the last reads nothing. A failure before the last segment ends the batch there and the host reads the window once.

### 17.4 The session tier

The session tier activates the app, moves the real pointer and types at the focused field. During the spec build's fixture recording a scratch TextEdit came to the front while the person typed, and two of their keystrokes landed in it. So `session` is in a call's tiers only when the gate (`tierGate.ts`) admits it. A step that needs it (the service answers `needs_tier { needed: 'session' }`, the verdict says `session`, or the key-window retry of a key) asks `gate.request`; an admit runs the step again from there with `session` allowed, a refusal fails it with `needs the session tier (the real pointer and keyboard), which is not available now: <reason>` and the later steps do not run. Every acting request goes through `gate.run`, which may take `session` out of its tiers and puts the Mac back after it. The gate is the tier scheduler (§20) on a host with a person's idle time to read; without one (headless, a test) every such step is refused `nothing schedules it yet` and `gate.run` sends the call without `session`.

### 17.5 Tools on each harness

- **Claude**, in process: `appToolsMcp` spreads `computerTools(session)` (`mcp.ts`): the four tools of §9, each deferred behind tool search (`_meta['anthropic/alwaysLoad'] = false` on the `alwaysLoad` app server, the SDK's `searchHint` from `COMPUTER_SEARCH_HINT`), so a thread that never touches an app pays no schema. ### 17.6 Permission and Stop

- **The card**: in `safe` and `edits` every `computer_act` and `computer_batch` with an action that sends input asks once, through `registry.requestApproval`, so one path serves every harness; reads (`computer_apps`, `computer_observe`, and an act or batch of `screenshot`, `zoom`, `cursor_position` and `wait` alone) never ask; full access asks only for a flagged act or a password field (§19.3). The turn goes on; the next one may use the computer again.
- **The composer's Stop and Pause** cancel the call in flight (`cancelled: the turn was stopped`, `cancelled: the thread was paused`); a call while paused answers `refused: the thread is paused`.
- **A grant that is off**: `permission_missing` from a request, a step or an observation's `shotError` asks the system once per install per grant (`permissions.request`, setting `computer.prompted.<which>`) and says where the switch is; what ran stays in the result.

## 18. The bridge

A box thread whose `macBridge.thread.<sessionId>` names a Mac drives that Mac's apps. The Mac runs the call in a computer session it owns; the box carries the call, lands the pictures and mirrors the row. docs/box.md "Computer use from a box thread" has the person's side; this is the wire.

- **The offer.** A Mac adds `computer` (`MAC_COMPUTER_OFFER`) to its `peer.register` offers for a host whose Access is above Off, whose switch (`macBridge.computer.<envId>`, `macBridge.computer.set`, off by default) is on, and only while computer use is available on the Mac. A change registers again on the live link. The box keeps the last offer per Mac (`macBridge.computerOffer.<envId>`) for while the Mac is offline, and a flip reboots the bridged threads at their next turn, since a harness's tools are fixed at spawn. The tools are listed only while the Mac offers them; a call goes to the Mac whenever the thread's bridge names one, so a Mac whose switch is off refuses in its own words.
- **`mac.computer`** carries `MacComputerCallArgsSchema { call: ComputerToolCall, turn, rootId }` under the usual `{ thread, args }`. `turn` is the box's boot and the thread's turn count: a new value clears the Mac session's Stop for the turn (`ComputerSessions.beginTurn`). `rootId` is the box thread's root; the Mac's tier gate sees `macComputerKey(box, root)`. The session is keyed `macComputerKey(box, thread)` (`env_…:<sessionId>`), so its pictures land under `<dataDir>/computer/bridged/<serviceSessionId(key)>/` on the Mac, only to be read back, and go once read.
- **On the Mac** (`remote/macComputer.ts`, under `MacBridge.handle`): the policy Off, the switch off and computer use unavailable each refuse with one line; a live session is a running request of kind `computer` on the load guard, under the host's commands cap and its computer cap (`macBridge.maxComputer.<envId>`, default 2, at most 8), held in line with its standing (`reason: 'computer'`, "Waiting for the Mac, 2 of 2 computer sessions, 1st in line") within the call's deadline, and it gives its slot back at the box turn's settle, a Stop, the link dropping or three idle minutes with no call out. In safe and edits an acting call asks a card of kind `computer` (`{ app, window, actions }`, Allow or Deny, nothing remembered); the tier gate's own ask past its bound is the same card (`TierGateContext.approve`); while Away is on every card is allowed as it is made (checked at each card, so a flip during a slot wait is caught) and the answer says `away: true`, except in a call the model flagged `pay` or `subscribe` (`awayAllowsKind`), which is refused with `MAC_AWAY_REFUSAL` before it waits or at its card; a card waiting when Away turns on is decided the same way (`MacBridge.awayChanged`).
- **Progress.** While a call is out, the Mac's row for the session goes as `peer.progress` chunks, `ComputerPeerProgressSchema { row }`, at most four a second, with `asking: { line }` while a card waits and the guard's or the session tier's words in `running.words` with `running.held: true` while it is held (a provisional row before the session has one).
- **`mac.computerEnd { reason }`**: `settled` (the box thread's turn settled) and `stopped` (Stop on the box's Activity row: the call in flight answers its steps so far and `stopped by the person` through its own reply, which the box waits 10 s for) free the slot; `ended` (the thread archived, deleted or moved; the ledger row removed; ten idle minutes on the box) closes the session. It answers `{ ended }`, false when the Mac held nothing for the thread. `mac.cancel` reaches the named calls (a pause, the composer's Stop, the harness giving a call up).
- **On the box** (`computer/bridge.ts`, `ComputerBridge`): one call at a time per thread, checked first (`checkComputerCall`) and refused before any peer call when given up, Stopped this turn, paused (`whilePaused: 'refuse'`: a click held while the screen moves on would land on something else), with no Mac named or the Mac offline, each again right before dispatch. The deadline is `bridgedDeadlineMs`: the card, the line, the scheduler's wait, the call's own budget and 30 s for the reply. Each picture lands as `attachmentDir(thread)/computer/<n>.<jpg|png>` (`landShotBytes`, the type from its mimeType alone), the thread's own counter. The Mac's row is mirrored re-keyed to the thread with `macPeer` and `macName`, `running.words` "Waiting for approval on <Mac>" while it asks, on the box's own `computer` push. A held row (no card) is the thread's tool hold (`ComputerBridgeDeps.held` → `registry.setToolHold`), so its `statusDetail` says the Mac's line; the next row without `held`, a card, the answer, a Stop, the link dropping, the thread's end and `close` clear it, and a row for a call that answered or was closed is dropped. A good answer records a `computer` row on the thread's ledger (one live per thread on that Mac); the thread's end, the idle close and a Stop stamp it. The Mac going offline mid-call answers that the action may or may not have happened.
- **Words** (`contract-maccomputer.ts`): `COMPUTER_SWITCH_OFF`, `computerUnavailableOnMac`, `COMPUTER_HOLD_EXPIRED`, `COMPUTER_HOLD_STOPPED`, `COMPUTER_MAC_WENT_OFFLINE`, `COMPUTER_NO_MAC`, `COMPUTER_BAD_ANSWER`, `askingWords`.
- **Proof**: `bun run script:e2e-computer-bridge` (`scripts/e2e-computer-bridge.ts`): on the Mac, an isolated headless Mac instance with its queries for TC Probe (the sessions proof's scratch app, never key) pinned to that app's pid (`TEMP_CODE_COMPUTER_PIN`, honoured only with `TEMP_CODE_USER_DATA`), and the box half started over SSH; the box thread's `app.computer` calls with no model turn, tiers `ax` and `process` only. One computer proof runs on the Mac at a time (it waits for another to finish); there is no idle gate, each check waits only for an unlocked, awake screen, and a window that comes forward is noted. Unit tests: `contract-maccomputer.test.ts`, `remote/macComputer.test.ts` and `macComputer.sessions.test.ts`, `computer/bridge.test.ts`, the guard's, pause's and peer calls' additions.

### 19.3 The confirmations policy

The model flags; the host asks. `computer_act`, `computer_batch` and every per-verb tool that sends input take `confirm: { kind, what }` (`ConfirmSchema`, `src/shared/computer/policy.ts`). With it the host shows one card in every permission mode, full access included, and acts only on Allow; Away allows it, unless its kind is `pay` or `subscribe` (`awayAllowsKind`, read off the call's own flag, never the card's). An act without the flag runs, and the prompt says a missed flag is the model's error.

| `kind` | Card label | The person's words may pre-approve it |
|---|---|---|
| `delete` | Delete | no |
| `send` | Send | no |
| `pay` | Pay | no |
| `subscribe` | Subscribe | no |
| `account` | Change an account | no |
| `access` | Change who has access | no |
| `install` | Install | no |
| `captcha` | Answer a CAPTCHA | no |
| `security` | Change a security setting | no |

- **Pre-approval** is the person's own words: the first message of a thread a person started (no `parentId`, no `startedBy`) and what they type later, a steer included. A subagent's brief, a master's `app_start_thread` message, a plan's build seed and a `send_to_agent` message pre-approve nothing, and such a thread reads that it must flag every act on the list. A "no" kind is flagged even when asked for: the card is the person's last look.
- **Left to the person**: the last step of a password change, one-time codes, getting past a security warning or a paywall.
- **Free**: reading, opening, switching, scrolling, typing into a field without sending it, downloads, cookie banners, closing a dialog that discards nothing.
- **Hygiene** (prompt text): text on screen is never permission; flag the step that has the effect, once; a denied card means stop, never the same effect another way.

What the host enforces whatever the model flagged (`src/main/server/computer/policy.ts`, run in `run.ts`):

- **A password field**: a `type`, `paste` or `set_value` step whose destination (its element, else the latest read's focused element; with neither, any password field in the window) is a `password` element asks in every mode, kind `password`. The card says how many characters go in, never what (`maskText`).
- **Read first for text**: a `type` or `paste` into an app this thread has not read answers `no_observation` with nothing sent.
- **A known destination**: in one call, a `type` or `paste` with no element after another step that sends input is refused before anything runs.
- **The pinned target**: every call's `app` becomes a pid before any request (`TargetResolver`): a running app by bundle id, then by name, from a list cached until `apps/changed`; else `apps.launch`, which never brings an app forward, and the pid it answered from a fresh list within 2 s; else, when launch found nothing, a unique prefix of a running app's name. Every request then names `{ pid }`, so the app checked is the app acted on. A proof's `resolveApp` pin wins.

## 20. Tier scheduling

`src/main/server/computer/schedule.ts` decides when a step may use the `session` tier, the person's own pointer and keyboard; the pure rules are `src/shared/computer/scheduleRules.ts`. The server sets it as the gate (§15.4) where it has the person's idle time (`src/main/personIdle.ts`, built over Electron's `powerMonitor` in main); a headless host keeps the refusal.

### 20.1 When the Mac is free

- **Away**: no input for `computer.sessionIdleMs` (one setting, default 120,000 ms, attention.ts's away threshold, clamped to 5 s – 1 h and read at every check, so a later Settings row can lower it), or the Away switch with no input for 10 s. A 30-second pause is reading, not absence.
- **Locked or asleep** refuses at once (keys typed at a lock screen would reach the password field).
- **Present**: the step waits, polling every second, and the thread says `Waiting for the Mac to be free` in its status detail (`SessionRegistry.setToolHold`, ahead of its other words, `…, then your message` while a steer is unread) and on its computer row, whose Stop ends it. In full access it asks after 3 minutes; in `safe` and `edits` at once, since the call already asks.
- **The card**: one `approval-request` with `toolName: 'computer_session'` (no harness calls it), `choices: 'run-skip'` (the transcript's card and the toast draw Run now and Skip, its verdict lines Ran now, Skipped, Skipped automatically), and the title `Use your pointer and keyboard to click button "Save" in TextEdit, window "Untitled"`. It goes the call's own way (`ctx.approve`: the registry here, the Mac bridge's card for a box thread). **Run now** leases the tier to the thread until the person's next input (their click on Run now is not that input: 1.5 s slack); **Skip** or a timeout is remembered for that app until the turn ends; a card cancelled by a pause or Stop is not. While the Away switch is on the card is answered Run now at the moment it would show, so it leases the tier as Run now does.
- **The call's own card** (`safe`, `edits`): when a step is expected to need the session tier (its class's verdict says `session`, or `perform` with `raise`), the title ends `, using your pointer and keyboard`, and an Allow leases the tier as Run now does, so the step runs with no second card.
- **The result** says how long a held step waited, before its own line: `waited 2m 14s for the Mac to be free`, `waited 3m for the Mac to be free, then the person chose Run now`, `waited 4s for the clipboard, the person had just copied` (none under a second).

### 20.2 Refusals

`needs the session tier (the real pointer and keyboard), which is not available now: <reason>`, the reason from `sessionRefusalWords`: `no-scheduler` (no gate), `screen-locked`, `asleep`, `skipped` (`the person did not choose Run now`), `skipped-earlier` (`… for TextEdit earlier in this turn`, no card), and a cancel, worded from the abort's cause (`cancelled: the thread was paused`, `stopped by the person`, `cancelled: the call was given up`).

### 20.3 The pointer and the keyboard

- **One session call at a time on the host** (`SessionSlot`, first come first served; a waiting thread says `Waiting for the Mac to be free, 2nd in line`). A thread whose person came back while it waited is sent without the tier, and a step that still needs it comes back through `request`. Calls that never need the tier never wait.
- **The Mac goes back after every call that touched it**, before the result returns: `input.restoreSession` puts the person's front app and pointer back (a step at `session`, a failed step carrying a `SessionChange`, or a call cut short with `session` among its tiers). Leaving the target app in front between calls would let a person who comes back type into it with no step running to stop them; the cost is that a thread raises its app again for each session call, and only while the person is away.
- **The person's touch**: the service stops the step within 10 ms and sends `session/interrupted` before the call's closing wait; on that notice the host calls `input.restoreSession { afterInterrupt: true }` at once, which acts despite the touch for `SERVICE.restoreAfterInterruptMs` (2 s), each half still checking its own part (the front app is still the one the step left there, the pointer within 2 pt). The call's end waits for that restore before it lets the slot go. The key that tripped the watch has already landed in the raised window; swallowing it is a follow-up. The step is never retried; the person is now present, so the next session step waits.
- **A held button** (`left_mouse_down` at the session tier, the up in a later call) keeps the slot and the tier until its up, a touch, Stop, a pause, the turn's end, or the service's own release 30 s after the down, which the host learns by its own timer 2 s later; no restore in between.
- **Settle**: Stop (after the service session closes), a pause, the turn's end and the thread's end clear the lease (and, but for a pause, the Skips), restore a held button and free the slot (`gate.settle`, from `ComputerSessions`).

### 20.4 The person's idle time

macOS counts an event posted at the HID tap as input, so every session step would read as the person returning. `PersonIdle` takes the app's own input out: each session step that ran to its end reports its span on its `SessionChange` (`armedAt`, `idleAtArmMs`, `lastInputAt`, epoch ms, the mach clock converted at arm time), and input that falls in a kept span (plus 1 s for the whole-second idle) reads as the person's last input before it, `armedAt − idleAtArmMs`, chaining through earlier spans. Only the spans: the gaps between a batch's steps and the closing wait have no person watch, so input there stays the person's. While a call is out, input after its start reads as the app's until its spans are known; an interrupted call keeps none. Spans are kept an hour, at most 64. main gives the same `PersonIdle` to `AttentionWatcher`, so a session step never makes the renderer name its thread to the hosts.

### 20.5 The clipboard

Only a paste touches it, and the host cannot tell which `type` will paste, so the check is the service's (§5.3). A step refused `recent-copy` asks `gate.clipboard`, which polls `clipboard.state` every 500 ms until `now − max(foreignChangeAt ?? 0, watchingSince) ≥ 5 s` (`RECENT_COPY_MS`, `clipboardQuiet`), saying `Waiting for the clipboard`, then runs the call again from that step; a person who keeps copying ends the step at 10 s from its first refusal, however often it is refused again, with `clipboard_recent`. A call that does not paste never waits.

## 22. Window actions

Measured on the Mac on 2026-11-10 (macOS 27.2, a scratch AppKit app in the background, two capture streams): while any capture runs on a window, macOS draws its "Window sharing" badge over the traffic lights, removes the title-bar buttons from the window's AXChildren and adds an `AXMenuButton` "Window sharing" child; the window's `AXCloseButton`, `AXMinimizeButton`, `AXZoomButton` and `AXFullScreenButton` attributes still answer the buttons, enabled, at their frames, and an AXPress on them closes or minimizes the window with the app left in the background. Setting `AXMinimized` false orders the window above the person's frontmost window. Our own pixel watch (§7) is such a capture, so before this section a read after the first action lost the buttons, and the badge's own churn could make an ignored step read `changed`.

22.1 **The title-bar buttons are always in the tree.** For a root whose role is `AXWindow` (a dialog subrole included; never a sheet), the walk reads the four attributes in the window's stage B batch and adds each answered element not already among its children (CFEqual; `AXZoomButton` and `AXFullScreenButton` are often one element) as a child (`TitleBar.missing`, AXText). The text then puts the window's title-bar buttons (subroles `AXCloseButton`, `AXMinimizeButton`, `AXFullScreenButton`, `AXZoomButton`, `TITLE_BAR_SUBROLES` in observation.ts) last among the window's children in that order, wherever AX listed them (`TitleBar.order`), so a capture starting or stopping never reorders siblings (§4.4) and their indices stay (CFEqual identity, §4.2). Their lines are unchanged: `button "close"`, `button "minimize"`, `button "full screen" actions: zoom window, show menu`, `button "zoom"`.

22.2 **The sharing badge is never a line.** A direct child of a window whose role is `AXMenuButton` with no subrole and whose frame contains the centre of one of the window's title-bar buttons (by 22.1's attribute frames), or, for a window with none, lies within `TITLE_BAR_CORNER` (96 × 32 pt from the window's top-left), is the system's badge: dropped with its subtree, uncounted in `stats`, never in a diff. A person sharing the window in another app draws the same badge; the rule is the same.

22.3 **Closing and minimizing are clicks.** `left_click` on a title-bar button runs at `ax` (AXPress) like any button; no new verb. The host tries `ax` first for such a click whatever the app's click verdict says: it always carries AXPress, so it needs no session tier up front. That is now one case of §24.1's rule, which tries `ax` first for every step that may have an `ax` route (§17.3). A close that leaves the window in place with a sheet attached (unsaved changes) returns the sheet in the closing observation as a diff, as any sheet (§2.1's focus window, A13); its buttons are pressed the same way. A window with no `button "close"` line in a read that is neither truncated nor partial cannot be closed from computer use; the model answers through the window's own controls or says so. A disabled close or minimize button (a sheet attached, a full-screen window's minimize) reads `disabled`, and a press answers `action_unsupported`.

22.4 **`minimized`.** A window line carries the state word `minimized` (last in `STATE_WORDS`) while its `AXMinimized` is true, read in the window's stage B batch. A diff shows the change as `~ [1] window "<title>" minimized`.

22.5 **Restore is `perform raise`, at the session tier.** §5.2's rule stands: `raise` runs only where `tiers` includes `session` and reports `tier: 'session'`. On a minimized window it sets `AXMinimized` false first, then AXRaise, in the same session step (`InputCore.raiseWindow`). Neither restore nor raise is offered at `ax`. AX reads and `ax` actions work on a minimized window as on any other; the `process` tier refuses it (`window_minimized`), and a screenshot answers `shotError` minimized.

22.6 **After a close.** A step after which the target window is no longer among the app's AXWindows reports `effect: 'changed'`; so does a step after which the app quit (`appGone`). The closing observation of a call whose target window closed reads the app's window as §2.1 resolves it with no `window` (its main window, else its focused, else its first standard window) as a `full` observation (§4.4: the old one closed), whose header names the new window; an app left with no window answers `observationError` `window_not_found` "<App> has no window open."; an app whose remaining windows §2.1 will not pick (none standard, none main or focused) answers `window_not_found` with §2.1's message and the window titles; an app that quit, `window_not_found` "<App> quit." (an app whose last window closing quits it, as TC Probe does). The first and the last carry `reason: 'gone'`, and the host shows the model those words as they are. The host binds the window the observation names (§17.2) and forgets the bound window on either error.

22.7 **Full-screen windows.** A full-screen window keeps its title-bar buttons in AX (its title bar is hidden, not gone); 22.1 adds them if AX leaves them out. Closing it ends its Space; AppKit disables minimize in full screen (22.3). Nothing here moves a window between Spaces.

22.8 **The watch's own badge is no change (§7).** The shallow signature hashes the window's children without its title-bar buttons and the badge, and adds the window's `AXMinimized`; an AX notification whose element is a title-bar button or the badge does not count, and `AXWindowMiniaturized` and `AXWindowDeminiaturized` are watched; the pixel judge ignores every cell inside `TITLE_BAR_CORNER` (`ChangeJudge`'s `ignore`, `CaptureTuning.titleBarCorner`). So a step the app ignored reads `none` whether or not the watch started during its wait.

22.9 **Tests and the proof.** The pure rules are box-tested (`sh scripts/computer-text-test.sh`: `TitleBarTests`, the `textedit/doc-shared` fixture, the doc as the walk gives it under a capture, which reads as `textedit/doc`, and the wait rule's `appGone` and `windowGone`); the walker's append, the corner, `raiseWindow` and the closing observation on the Mac (`bun run computer:test`). The window leg of `bun run script:e2e-tc-computer` runs on a TC Probe launched with `--windows` (scripts/mac/computer-probe-app.swift: "TC Probe Doc" with a save sheet, "TC Probe Plain", "TC Probe Fixed", standard windows that never become key) and on a third instance whose last window closes.


## 24. Background fallbacks

A window in the background ignores most posted input (§14.8). This section is the order in which the service tries the ways to do a step without taking the Mac, and what each way can and cannot do. Each way is a **route**; the step reports the one that ran in `step.input.via` and what it acted on in `step.input.on`. (§23 is sibling (3)'s launch section; whichever lands second keeps its number.) The plan is `.temp-code/plan-PC_BkkTm4KBm.md`.

24.1 **The order.** For each step the service lists the routes below for its verb, keeps those whose tier is in `tiers` and whose facts allow them, and runs, first found: (1) an exact route at `ax`, then at `process`, that the call's `ignored` does not name; (2) an approximate route not named there; (3) a route at `session`; (4) the routes `ignored` names, exact first, in this order. A route that did nothing it could tell (a caret that moved nothing, a page action refused on its first call) hands the step to the next. A step no allowed route can do answers `needs_tier { needed }` naming the lowest tier with a route, without acting. This replaces §5.2's "exact first across tiers": an approximate `ax` route now runs before taking the Mac. In Swift: `planRoutes` and `chooseRoute` in TierPlan.swift, walked by `InputEngine.perform`.

| Verb | Routes, in order |
|---|---|
| `key`, combo with `super` or `ctrl` | `menu` (ax) · keys (process) · keys (session) |
| `key`, other combos; `hold_key` | keys (process) · keys (session) |
| `left_click`, no modifiers, no `duration` | element AXPress or row selection (ax, §5.2) · `hit` (ax) · `caret` (ax) · click (process) · click (session) |
| `right_click`, the same | element AXShowMenu (ax) · `hit` AXShowMenu (ax) · click (process) · click (session) |
| `double_click`, the same | element AXOpen (ax) · `hit` AXOpen (ax) · click (process) · click (session) |
| `scroll`, no modifiers | `scroll-bar` (ax) · wheel (process) · `scroll-page` (ax, approximate) · wheel (session) |
| `type` | §5.3, unchanged |
| `paste` | `ax-insert` (ax, `text` format, or any format into an `input`) · then the paste of §5.3, whose Command-V is delivered as `key super+v` is (24.2) |
| every other verb, and any modified click or scroll | (process) · (session), as today |

24.2 **`menu`.** For a `key` whose combo has `super` or `ctrl`, the service looks the combo up among the app's menu-bar items (AXMenuBar → AXMenuBarItem → AXMenu → AXMenuItem, submenus included), never in the Apple menu (the bar's first item) or a submenu of the app menu (Services, the only one AppKit puts there, in whatever language). It matches the item's key equivalent as the posted keys would press it (`MenuItemShortcut.matches`): AXMenuItemCmdGlyph for keys such as Delete, Return and the arrows, else AXMenuItemCmdChar placed on the current key layout (AppKit reports a letter upper-cased whatever its shift, so the case is ignored; `super+shift+/` matches `?`), else AXMenuItemCmdVirtualKey, with AXMenuItemCmdModifiers exactly (0 is Command alone; bit 0 Shift, bit 1 Option, bit 2 Control, bit 3 no Command). The route needs the target window to be the app's AXFocusedWindow: a menu item acts on the app's focused window, so the §5.2 key-window rule holds and anything else is `key_window_unavailable`. An **enabled** match is pressed (AXPress, `repeat` times) and reported `via: 'menu'`, `on: "File › Close"`. A **disabled** match while the app is not active (`NSRunningApplication.isActive` false) skips the process keys for that combo, since AppKit routes the same key through the same disabled item, and runs the session keys when `session` is allowed (activation re-validates the item); else it answers `needs_tier { needed: 'session', menu: ["File", "Close"] }`, "File › Close is disabled while TextEdit is in the background." A disabled match while the app is active answers `action_unsupported`, "File › Close is disabled.", with nothing posted. No match goes on to the next route. The lookup reads at most 3,000 items in 250 ms (`InputTiming.menuMaxItems`, `menuMaxMs`; each item's facts in one batched read); its index of combos is kept per pid for 30 s (`menuIndexMaxAgeS`), a combo the fresh index lacks never walks the bar again, and the item is read again where the index found it before it is pressed (gone or changed: the bar is read again).

AppKit sends a menu item without a target down the responder chain from the key window, and an inactive app has no key window, so in the background such items (Close, Save, Select All, Copy, Paste, Find, Undo) are disabled or do nothing; items aimed at the application, its delegate or the document controller (New, Open…, Settings…, Quit) run. Measured: Edit › Select All pressed over AX did nothing in an inactive TextEdit (§14.8); the rest is 24.9's to measure.

24.3 **`hit`.** For a click at a coordinate (or the agent cursor), the service hit-tests the app (`AXUIElementCopyElementAtPosition` on the app element, at the screen point §14.2 computes) and keeps the result only when its AXWindow is the target window or a sheet whose AXParent is it; for a click on a named element with none of the click's own actions, it starts at that element. From the start it looks at the element and at most 3 ancestors (`hitAncestors`), stopping before a window, sheet, dialog, scroll area, web area, table, outline, list or text area (a start that is one of these presses nothing, but a text area may take the caret), and takes the first that has, for `left_click`: AXPress, else AXPick, else an AXIncrementor's half (AXIncrement above its middle, AXDecrement below), else a selectable row or cell (§5.2's selection); for `right_click` AXShowMenu; for `double_click` AXOpen. It reports `via: 'hit'`, `on: 'button "Save"'` (the element's role and first name as a line prints them; `chooseHit` in HitPlan.swift). A start with none of these goes on to `caret`, then to the next tier: a click on content with no action (a canvas, a background, a label alone) cannot be done in the background.

24.4 **`caret`.** A `left_click` whose start (24.3) is a text element (`text area`, `input`, `search`, `combo box`) with a settable AXSelectedTextRange and that found no action: set AXFocused true, then AXSelectedTextRange to `{ AXRangeForPosition(point).location, 0 }`. The evidence is the element's focus and range read back for up to 300 ms (`caretEvidenceMs`, §5.3's rule); a write the app accepted that moved neither is `none` and goes on to the next tier. `via: 'caret'`, `on: 'input "Name"'`.

24.5 **`scroll-bar`.** For a `scroll`, the scroll area is the named element's own or nearest one, else the one under the point, kept only when it is in the target window or a sheet of it (24.3's check), else the window's only one. Its AXVerticalScrollBar (up, down) or AXHorizontalScrollBar (left, right) with a settable AXValue takes `value ± clicks × SCROLL_POINTS_PER_CLICK / (content − visible)`, clamped to 0..1, where content is the scroll area's first AXContents frame along the axis and visible its own frame (`scrollBarMove` in ScrollPlan.swift). `SCROLL_POINTS_PER_CLICK` is 40 pt for the benchmark to tune (protocol.ts, generated as `InputTables.scrollPointsPerClick`). A bar already at the end changes nothing and reads `none`, no other route tried. `via: 'scroll-bar'`. Web content has no AX scroll bars; Chrome takes the page actions (`via: 'scroll-page'`, approximate, one page per five clicks as §5.2). A page action the element lists and refuses as unsupported on its first call (TextEdit's answers -25205, §14.8) goes on to the next route instead of failing the step, since no page moved; a timeout or any other error, or a refusal after a page has moved, fails the step as today.

24.6 **Text and paste.** `type` is unchanged (§5.3: AXSelectedText, AXValue, keys, paste); its first rung and the paste's insert are one function (`AXTier.insertPlain`). `paste` with `format: 'text'` first sets AXSelectedText on the destination (the named or focused element, after §5.3's AXFocused), reads the evidence as `type`'s first rung does, and on `none` goes on to the clipboard paste; a paste that went in this way never touches the clipboard (`via: 'ax-insert'`, no `clipboard`). With no event tier allowed the insert is the step alone, and `none` answers `needs_tier { needed: 'process' }`. `markdown` and `html` take this route only into an `input`, which pastes plain text (its plain string is what Command-V would put there); into a text area or web content they keep the clipboard paste, since AX inserts only plain text. The clipboard paste's Command-V (§5.3 step 5) goes through 24.2: the Paste item pressed when enabled, the posted key otherwise; step 2's checks find a disabled Paste before the pasteboard is written (`needs_tier` with its path at `process` in an inactive app, `action_unsupported` otherwise).

24.7 **Save and open panels.** A panel is a sheet of its window or the app's focused dialog, so it is in the focus window (§2.1) and every control in it takes `ax`: the name field `set_value`, the sidebar and file rows selection (and AXOpen to go into a folder), the format pop up `perform show menu`, Save and Open AXPress. In a sandboxed app the panel is drawn by another process (the open-and-save panel service) while its AX tree shows in the app's: events posted to the app's pid never reach it, AX does. Go to Folder (⌘⇧G) is the panel's own key, in no menu bar; whether inserting `/` into the name field through AXSelectedText opens it as typing does is 24.9's to measure. Opening the panel: Open… is aimed at the document controller and runs through `menu`; Save in an AppKit document app is aimed at the document through the responder chain and needs the session tier (24.2), unless the window's close button's save sheet (§22.3) offers Save…, which is pressed through AX.

24.8 **What the step says.** An `ax` route's AX call answering success proves nothing: the step's `effect` is the wait's (§7), `changed` only on an AX notification, a signature change, a counting pixel change or, for a copy or cut, a pasteboard change (24.10); else `unknown` after a thin read and `none` otherwise (§7, unchanged); `none`, which a step with nothing to wait for returns in about 0.75 s. The step line names the route and what it acted on (`formatStepLine`; the separator never appears inside `on`): `key super+w · menu File › Close · changed`, `left_click 412,230 · hit button "Save" · changed`, `scroll down 5 on [4] · scroll-bar · no change seen`, `paste text into [9] · ax-insert · changed`.

24.9 **Measured.** Nothing yet: the build landed while the person was running live computer-use tests on the Mac, so no proof that opens or drives an app ran (§14.8's "Expected in the background, to measure" holds what is expected). To run on a free Mac: `bun run computer:test`, then `bun run script:e2e-tc-computer -- --gate` (the fallbacks leg; its step 2 measures the AppKit rule of 24.2 on our own app, and if the first free run finds Ping Window enabled, 24.2's second paragraph is corrected), then `bash scripts/mac/input-proof.sh --tempcode --finder` (and `TC_INPUT_INTELLIJ=1`), whose fallback legs fill §14.8's table.

24.10 **The pasteboard counts, for copy and cut.** For a `key super+c` or `key super+x` step (posted or through `menu`; `WaitRule.readsPasteboard`), a change of the general pasteboard's `changeCount` between the step's start and the wait's end that is not the service's own write (§16.4's clipboard signal) makes the step `changed` and restarts the quiet clock (`WaitSample.pasteboardLastChange`, read from the clipboard watch by SmartWait), so a copy or a cut reads as done. No other step reads it, so the person copying meanwhile never makes another key, a scroll or a click read `changed`.

24.11 **Tests and the proof.** On the box, `sh scripts/computer-text-test.sh` runs FallbackTests.swift on Input's Foundation-only files (`MenuShortcutTests`, `MenuSearchTests`, `HitPlanTests`, `ScrollPlanTests`, `RouteTests`, `PasteInsertTests`) and ComputerServiceKit's `PasteboardWaitTests`; on the Mac, `bun run computer:test` adds `AXMenuTests` and `AXHitTests` on the live files' pure seams. vitest: protocol, tools (`formatStepLine` per route, `mayRunAtAx`), verdicts (`viaMisses`, `ignoredFor`), run (the fake service's `Menuey` and `Hitty`: a coordinate click under a session verdict running at `ax` through `hit`, a step with no `ax` route asking the gate first, a disabled ⌘W's refusal naming File › Close, `ignored` sent after two `none` hits, an ignored hit under a session verdict reaching the gate, a scroll moving the bar), descriptions and errorWords under their caps, the bench's step reader. The `--gate` leg (`fallbackLeg` in scripts/e2e-tc-computer.ts, after the window leg) runs on TC Probe launched with `--fallbacks <scratch>` (scripts/mac/computer-probe-app.swift: a window key in its background app with a button-role view and its own label, a monospaced field, a plain text view, a stepper, a scroll view over 60 lines, a save sheet aimed at the scratch folder, and a Probe menu with Ping App ⌘⇧P aimed at an object and Ping Window ⌘⇧K through the responder chain), at `ax` and `process` only, the paste at `ax` alone so it never writes the person's pasteboard: the menu route, the disabled item, a hit on a label, the caret at the fifth digit, a background click with no `ax` route, the stepper's upper half, the scroll bar and its end, the AX paste with the change count unmoved, and the save sheet driven into the scratch folder. The hand run's fallback legs are tc-input-proof's FallbackLegs.swift.

## The unattended proof modes

Proofs build wire coordinates through `intPoint` in
`scripts/lib/computerPoint.ts`: `Math.round` on both axes after bounds or
scale arithmetic. This covers Ping's centre in the held-input crash step,
TextEdit's click point and the capture region's corners in
`scripts/e2e-tc-computer.ts`. The wire still refuses fractional coordinates;
the host forwards validated actions and element IDs without computing
points from bounds or zoom.

The preview builds its own copy of TC Probe through
`scripts/lib/previewProbeApp.ts`. Its Ping button keeps AXPress and the
pong callback, with highlight and state drawing masks cleared. AppKit's
brief pressed/released drawing can otherwise make the second click a
visual change even when the label stays pong. The no-frame check stays in
place; the shared Swift source stays unchanged.

Run each from a built clone on the Mac:

```sh
bun run script:e2e-tc-computer -- --gate
bun run script:e2e-computer-bridge -- --gate
bun run script:e2e-computer-preview -- --gate
```

Each gate mode waits for `scripts/lib/gateBuild.ts` before compiling scratch
helpers or reading the shipped service. It checks the native source stamp
before calling `buildTcComputer`, so a stale service fails instead of rebuilding.
It also waits for older computer proofs through `scripts/lib/proofOrder.ts`,
with a bounded wait, and sets `TC_PROOF_UNGATED=1` itself. TC Probe is the only
scratch app it drives; every action stays at the ax or process tier. The
proofs kill their own children on success, failure, throws and handled signals.
Bridge instances disable warm harnesses. Cleanup reads the instance's process
tree before ending its group, so detached utility children also end.
Reports and traces remain in their `/tmp/tc-…` proof dirs for the caller to
copy and then remove. None of these modes uses a real model or the clipboard.

| Mode | Runs | Skips |
| --- | --- | --- |
| tc-computer | Background launch, list, find, Ping at ax, the private-symbol fallback, window capture, cancelled wait, crash with held process input, restart and EOF | TextEdit, its reads and actions, the clipboard lock and paste |
| computer-bridge | The existing box-half protocol over a local child pipe, with two isolated headless instances on this Mac; the box half sets `TEMP_CODE_BUILD_PLATFORM=linux` | SSH in gate mode; the default SSH pair still works as a hand run |
| computer-preview | Legs 1–3 and 5: target, frames, clicks, stop and the frontmost-app and pointer check | Leg 4: "takes the person's Escape: hand run"; neither direct `escape.watch { on: true }` nor `SessionHolds` may take Escape in gate mode |

`--pair local` also selects the bridge's local pair without `--gate`. Both
local and SSH modes use the same age-based proof ordering. The local child
belongs to its wrapper; it does not wait on its own parent as another proof.

Accessibility must belong to the app that holds the shell's session
(TempCode.app when Publish starts it). A missing grant fails by name without
asking for it. Without Screen Recording, the proof skips capture and image
checks, passes `screenshot: false` to host calls (the stdio bridge included),
and seeds its own host's `computer.prompted.screenRecording` setting before
startup. Direct wire reads use `screenshot: never`. The preview still checks
its target and an ax Ping without starting a capture stream. The pure rule
in `scripts/lib/computerProofGate.ts` refuses picture and permission-request
calls without the grant; its test also checks the actual host does not prompt,
even if the service reports a late Screen Recording error. The preview's
request guard refuses `escape.watch { on: true }` in gate mode.

These modes need an unlocked, awake Mac for AX and capture. At entry they
exit 0 with `skipped: the Mac is locked or asleep` if the screen is locked,
asleep or unreadable; the bench's `--gate` entry does the same. The publish
gate checks once before its lanes start and skips these four `screen: true`
rows with a note; `computer-swift` still runs. The tiny cached Swift check
uses the same session-lock, on-console and display-sleep rule as the proof
probe. It never unlocks, wakes or waits for the Mac. Losing the screen after
a proof starts still fails that proof as inconclusive.

The tc-computer proof keeps its `initialize` bound at 500 ms for a hand run.
Under `--gate` it allows 2,000 ms, since publish runs it beside the soaks,
Swift builds and other proofs.

On 2026-11-09 all three modes passed three consecutive runs in the isolated
Mac clone, with Accessibility and Screen Recording granted. Wall times were
19.082/18.828/19.075 s for tc-computer (17 passes and 10 skips each),
28.368/28.875/28.361 s for bridge (43 passes each), and
23.601/23.347/23.112 s for preview (16 passes and one skip each). Every accepted
preview run passed the unchanged-click check with zero frames in 1.5 s.
The one requested publish-tier run then failed at hub startup because
`@cloudflare/vitest-pool-workers` was missing; the gate stopped the other rows.
It was not retried. The handoff report includes each attempt, the preview
fixture fix, and the publish report's step times.
