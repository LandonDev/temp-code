## 0. The one finding that blocked everything else

In the BUILT renderer every lazy surface was dead: `chunk.surface()` (src/renderer/src/lib/lazyChunk.tsx) mounted an empty DOM element `<current>` (the DOM showed `<current scope="[object Object]">`, `<current path="/tmp/…">`) with no skeleton, no "Couldn't load", no console error. The bundle had `jsx(reactExports.Suspense, { fallback, children: jsx("current", { ...props }) })`: babel-plugin-react-compiler (electron.vite.config.ts) inlined S5b's alias `const Lazy = current` into the JSX tag and the lowercase identifier became the string tag "current". Dev (Vite's server) and jsdom tests never run the compiler, so thirty threads and their usability loops never saw it, and the gate's build lane only measured the bundle. Blank at a55789b5: Settings (every page, the column at zero height), the non-chat thread views and the master board, the dialogs chunk (New project, Add workspace, Preamble, Workspace settings), the editor body, the HTML frame, the lightbox, the terminal dock and the Dev servers pane, Accounts and Stats, the release notes, and the rail's thread list the moment the virtualizer chunk landed. Severity: broken, release-blocking. Owner: src/renderer/src/lib/lazyChunk.tsx; the guard in scripts/check-bundle-size.ts. Fixed by the planner started at once (ooYPgz0Et3Bv → build 8J6mwMHSDnhJ, landed d441068d: the binding renamed `Current`, `"use no memo"` on Surface, a `badJsxTags` scan of every built chunk in the build step). Waves 3 and 4 re-verified on d441068d: Settings, the thread views, the dialogs, the editor body and the panel render.
